## 四、设计取舍（需用户知情）

| 编号 | 决策 | 对使用方式的影响 |
|------|------|----------------|
| D-app-01 | 删除「应用管理」菜单，后端模块保留为运行时项目托管能力 | 侧栏不再有「应用管理」；旧地址 /app 自动跳到网站管理的 Python 项目分栏 |
| D-app-02 | Node 项目用 systemd 托管，不引入 PM2，不做 Node 版本隔离 | Node 项目与 Python 项目同一套启停、日志、开机自启、建站界面；全机一个 Node 版本（来自环境管理） |
| D-app-03 | 容器「应用」的主机端口只绑 127.0.0.1 | 应用建站后才能从外部访问；想直接用 IP:端口访问，需走「容器」页签的创建容器或手写 Compose |
| D-app-04 | 容器运行形态从应用管理下线，由容器管理「应用」页签承载 | v0.3.0 起就不可用的「容器运行」选项消失，改为在容器管理里新建应用 |
| D-app-05 | dougong.app 标签只由「应用」创建通道注入 | 「应用」页签只列面板创建的应用；手写 yml 的项目仍在 Compose 页签 |
| D-app-06 | 应用清单不落库 | 每次打开按目录与容器实况计算；不产生新表 |
| D-app-07 | Compose 列表并入落盘根目录扫描 | 停止后（零容器）的项目在列表里可见、可启动、可删除 |
| D-app-08 | 迁移 018 仅加 runtime 列 | 升级零风险；已有的 Python 应用自动归入 Python 项目分栏 |
