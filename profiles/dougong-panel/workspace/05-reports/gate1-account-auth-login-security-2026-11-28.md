## 2. 设计一致性（G1-01~07）

- **G1-01 落点归位** ✅：登录双形态与恢复码登录归 C-02 登录认证（C-02-05/06）；passkey/恢复码管理归 S-02 账户自助（S-02-03/04）；会话签发扩新设备识别（C-02-04）。无新聚合根、无新状态机（登录锁定沿用 R-01 既有状态机；恢复码「未用/已用」为属性非状态机）。
- **G1-02 自助边界自洽** ✅：自助凭证操作不受只读变更禁令限制的行业惯例（FL 附录既有）延伸至 passkey/恢复码——readonly 负空间不变，PRD/FL/AA/readonly PageSpec 四处口径一致。
- **G1-03 规则零削弱** ✅：断言失败计入 R-01 锁定计数（FR-22/23、AA C-02-05/06、api §4.6 一致）；恢复码哈希存储、明文只展示一次（FR-25 与 I-P06 同口径）；passkey 私钥不出本机认证器（FR-24）。
- **G1-04 安全上下文约束登记** ✅：RP ID 不能为 IP、需域名+HTTPS（AUTH_018）在 api §4.6 校验规则、FR-22/24、BA 2.3.1.5、FL 备注四处一致。
- **G1-05 flags 存储语义** ✅：api v1.4 明确「注册即持久化认证器 flags 原始字节、断言后回写、旧行 flags=0 自愈一次、已存 flags 不一致仍拒」与实现一致（见 gate2 报告代码取证）。
- **G1-06 审计清单同步** ✅：prd FR-18 补 passkey 注册/删除、恢复码生成与恢复码登录；api §4.6 审计动作一致（webauthn_registered/webauthn_deleted + 登录流既有审计）。
- **G1-07 迁移编号** ✅：019/020 编号接力无冲突；020 为 ADD COLUMN 非表重建（无 sqlite_sequence 问题）。

### INFO（无需修复）

- **I1** BA 不使用 C-02-05/S-02-03 记号而以 L3 编号承载新业务活动——BA 文档既有文体（L1-L4 业务层级），AA 承担 C/S 编号映射，无歧义。
- **I2** prd 新增 FR-22~25 采用「编号接尾、按落点分节」（4.2 取 22/23、4.5 取 24/25）——FR 编号区间未占用无冲突，更新记录已注明分节口径。
