## 2. 读码复核结论（面板侧验证链路无缺陷）

逐环核验（详见 D0 §2 表，file:line 实证）：前端密码原样透传（无 trim）→ 后端无截断
（≤128）→ connArgs `-h localhost -P 3306 --protocol=TCP` → query 字面量参数数组
`-u tonyxyz --batch -N -e "SELECT 1"` + MYSQL_PWD env 真实注入（os.Environ() 追加，
无 shell，'@' 无特殊语义）→ classifyRun "Access denied"→ErrAuthRejected →
translatePingErr→DBM_005+data.reason（与实拍逐字一致）。建用户 quoteString 转义正确；
env-mgmt 不写任何 my.cnf 覆盖。**DBM_005 是服务器真实拒绝的如实呈现，验证逻辑不动。**

已确认 UX 缺口（本轮修复面）：凭据弹窗 DBM_005/006 内联固定文案丢弃 data.reason、
DBM_005 断言「用户名或密码错误」过窄（1045 含账户不存在/host 落空）、无操作指引。
建用户 host 默认='localhost'（CreateUserModal.vue:39/43）——与 tcp localhost 验证在
名字解析开启时兼容；错误形态显示 host='localhost' 证明名字解析开启，host 默认值缺陷
假设被削弱，待取证终裁。
