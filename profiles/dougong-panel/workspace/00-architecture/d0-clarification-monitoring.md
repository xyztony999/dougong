# D0 需求澄清报告：monitoring（系统监控）

> 引擎 design 阶段 D0 产物（2026-11-12，批量澄清）。作为 D1 架构设计的直接输入。
> 需求来源：idea.md §4.1 M2（监控部分）+ knowledge/business-concepts（metric、ADR-014、A4）。

## 1. 业务概念解析

| 维度 | 内容 |
|------|------|
| 业务术语 | 实时监控、历史趋势、环形缓冲、TOP 进程、系统信息概览 |
| 业务流程 | gopsutil 周期采集（CPU/内存/磁盘/网络/负载/进程）→ 进程内环形缓冲 → 前端图表展示（echarts，1h/24h 切换） |
| 业务角色 | admin/readonly 均可查看（只读场景核心价值，ADR-018） |
| 业务规则 | ADR-014/A4 已拍板：**环形缓冲不落库，重启后历史清零**；总内存目标 <60MB 约束缓冲容量 |
| 业务数据 | metric（采样条目：时间戳 + CPU 总/核 + 内存 + 磁盘容量/IO + 网络上下行 + 负载）、system_info（发行版/内核/运行时长/主机名） |

## 5. D1 输入摘要（结构化需求）

**模块边界**：
- IN：实时采集（CPU 总/核、内存、磁盘容量与 IO、网络上下行、负载、TOP 进程）、历史趋势（最近 1h/24h）、系统信息概览（发行版/内核/运行时长/主机名）、仪表盘 API（REST 拉取与 WS 推送的取舍 D3 定）
- OUT：systemd 服务列表与操作（service-mgmt）、告警阈值与通知渠道（非目标，材料未列）、进程 kill/优先级管理（材料未列，不做）

**核心实体**：metric（环形缓冲条目，内存态不落库）、system_info（只读投影，实时获取不持久化）

**状态机**：无（纯展示数据流）

**待 D1 细化（次要，不阻断）**：
- ⚠️ 采样频率与缓冲容量（建议：实时采样 2~3s 推送；历史 1min 粒度 × 1440 条覆盖 24h；TOP 进程取前 10）
- 多磁盘/多网卡聚合口径（总量 + 分设备明细的取舍）
