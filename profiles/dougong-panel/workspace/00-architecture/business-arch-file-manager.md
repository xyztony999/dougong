## 第一部分：文档概述

### 1.1 背景与目标

文件管理器（file-manager）是斗拱面板里程碑 M2 的入口模块：服务器上的文件本就在那里，面板不导入、不镜像、不重建，直接在受管根范围内提供浏览与操作能力——这是「接管存量环境」哲学在文件维度的落点。本模块同时是 files 适配器（安全路径层）的唯一业务消费模块，也是安全设计（R-04）的重灾区：所有路径类操作必须先解析真实路径再做白名单前缀校验，路径逃逸测试为里程碑验收硬项。业务输入来源：idea.md §4.1 M3（浏览/上传/下载/在线编辑/新建/重命名/移动/删除/权限属主/压缩解压）+ §5.4（安全路径层：R-04 路径白名单、R-05 上传安全）、D0 需求澄清报告（d0-clarification-file-manager.md，2026-11-12）及其拍板（Q1 删除策略=回收站 → ADR-021、R-17 更新）、知识库对象 file_entry 与 trash_entry（trash_entry 为 ADR-021 新增登记对象）。

本业务架构设计目标：

1. 以 L1-L4 层级刻画文件管理器「受管访问 → 内容操作 → 回收站治理」的业务主线；
2. 将已拍板的业务规则（R-04 路径白名单防逃逸、R-05 上传临时文件+rename/分块、R-17 删除进回收站（ADR-021）、R-03 全变更审计、ADR-018 只读边界禁上传下载）落到确定的业务活动节点上，并落定 D0 留给本阶段的四个细化口径（回收站位置方案、还原冲突策略、自动清理策略、分块与断点续传口径）；
3. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

> ⚠️假设A12（本设计新增，推导自 R-04「可配置排除」语义）：D0 输入清单（IN）未显式列出「受管根与排除目录配置」入口，但 R-04「默认 `/`，可配置排除 `/proc`、`/sys` 等」的语义必须有一个管理落点，否则排除清单无法调整、白名单退化为硬编码。本架构按规则语义将其纳入业务范围（L4 2.1.1.2），如后续裁剪需同步 BA/AA/FL 三文档。

边界声明（OUT，沿 D0 结论）：

- 磁盘配额管理：D0 明确非目标；
- 在线编辑的版本历史与协同编辑：D0 明确非目标（编辑保存为全量覆盖写）；
- 目录打包下载：D0 输入清单未列，MVP 不做（下载仅单文件），留二期；
- 大文件断点续传：二期（D0 拍板口径，本阶段仅分块上传，见 2.2.1.2）；
- 回收站保留天数自动清理：二期（本阶段默认仅手动清空，D0 落定，见 2.3.1.4）；
- 跨文件系统回收站的复杂语义：D1 已落定单一回收站方案 + 跨设备降级策略（见 2.3.1.1），无更多语义；
- files 适配器（安全路径层）的实现：零业务语义的技术实现（R-04 技术规约），归后端工程，不构成业务活动；
- 受管根与排除目录配置的存储载体：归 PRD/API 设计细化（本域只定配置业务本身）。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

文件管理器遵循「进得来（受管访问）→ 动得了（内容操作）→ 删得回（回收站治理）」的业务主线，划分为三个业务阶段：

- **受管访问阶段**：一切文件操作的安全通道——请求路径先经 EvalSymlinks 解析真实路径再做白名单前缀校验（R-04），越界访问（`../` 相对路径逃逸、符号链接外指）一律拒绝；受管根内提供目录浏览（列表/图标视图）与面包屑导航；
- **内容操作阶段**：受管根内的文件内容与元数据动作——上传（含大文件分块）、下载、在线编辑、新建/重命名/移动/删除、权限与属主修改、压缩/解压；全部变更类动作记审计（R-03），仅管理员可执行（ADR-018）；
- **回收站治理阶段**：删除动作的缓冲与可逆闭环（R-17，ADR-021）——删除不使文件直接消失而是入站回收站（trash_entry 元数据落库），支持还原与清空；trash_entry 状态机「在站 → 已还原 / 已清空」。

三阶段为「通道 → 主链 → 缓冲」结构而非严格时间序：受管访问贯穿始终（每次路径请求都经 R-04 校验），内容操作循环往复，删除类内容操作经回收站治理获得可逆性。下载虽不改变文件系统，但属「数据取出」（ADR-018 对只读角色禁下载），故归入内容操作阶段按数据取出口径管理。查看类操作（浏览、导航、回收站列表查看）按 ADR-018「全模块可查看」对两类角色同等开放。

### 2.1 受管访问阶段

**业务说明**：全部文件业务的安全前置与视野入口。受管访问阶段解决两个问题：一是「哪些路径可被触碰」——受管根与排除目录划定业务边界，路径白名单校验（R-04）逐请求执行，是全模块所有 L3 的强制前置；二是「边界内看得清」——目录浏览与导航把文件系统实况投影为面板视野。file_entry 为实时投影、元数据不落库（kb 拍板）：面板不建文件台账，每次呈现均为读取时刻的文件系统实况。

##### 2.1.1 安全路径管控

**业务说明**：R-04 的业务落点，本模块安全主线的载体。所有文件操作的路径参数在执行前必须经过「真实路径解析 → 白名单前缀校验」两步，任何一步不通过即拒绝并明确提示越界原因。路径逃逸测试为本模块里程碑验收硬项（D0 拍板）。所属 L2：受管访问阶段。

###### 2.1.1.1 路径白名单校验

**业务说明**：对每个携带路径的文件操作请求执行强制前置校验（R-04）：第一步将请求路径经 EvalSymlinks 解析为真实物理路径（消除 `../` 相对路径与符号链接的间接指向）；第二步校验真实路径是否落在受管根白名单内且未命中排除目录清单。两步全过才放行执行，否则拒绝本次操作并明确提示越界原因。校验覆盖全部 L3 的全部路径操作（含上传落盘目标、移动目标、解压条目目标、还原目标）。所属 L3：安全路径管控。

###### 2.1.1.2 受管根与排除目录配置

**业务说明**：白名单业务边界的自身治理（R-04「可配置」语义的落点，⚠️假设A12）：受管根默认 `/`（整机文件均受管），可配置为其他目录；排除目录清单默认建议排除 `/proc`、`/sys`、`/dev` 等伪文件系统，可增删。配置修改为变更类操作、记审计（R-03）；修改后对后续文件操作即予生效（生效细节归 D2/D3）。所属 L3：安全路径管控。

##### 2.1.2 目录浏览与导航

**业务说明**：受管根内的查看能力，是全部内容操作的入口与操作对象来源。查看类操作按 ADR-018「全模块可查看」对管理员与只读用户同等开放，是只读角色在本域的核心价值。所属 L2：受管访问阶段。

###### 2.1.2.1 目录内容浏览

**业务说明**：以列表或图标两种视图呈现当前目录的条目清单：名称、类型（文件/目录/符号链接）、大小、权限、属主（用户/组）、修改时间等元数据（file_entry 实时投影，不落库）；支持按名称/大小/修改时间排序；条目含点开头的隐藏文件（运维场景需直视 `.env`、`.htaccess` 等配置，解释性决策：默认全量呈现，不设隐藏开关）。所属 L3：目录浏览与导航。

###### 2.1.2.2 目录导航与面包屑

**业务说明**：在目录层级间移动的导航能力：面包屑路径条逐级点击回跳、上级目录导航；浏览位置与内容操作的目标目录绑定（上传落盘、新建位置等均为当前浏览目录）。目录跳转经 R-04 校验后方可呈现。所属 L3：目录浏览与导航。

### 2.2 内容操作阶段

**业务说明**：受管根内的内容与元数据动作，是本域业务主链。约束：仅管理员可执行全部变更类操作（ADR-018 禁变更、禁上传下载）；全部变更类动作记审计（R-03）；下载属数据取出、同样仅管理员可执行（ADR-018 禁下载）。所有写类操作的目标路径均经 2.1.1.1 强制前置校验。

##### 2.2.1 文件上传与下载

**业务说明**：文件内容进出受管根的传输业务。上传执行 R-05 安全落盘规则（临时文件 + rename 原子生效；大文件分块传输）；下载为单文件数据取出。所属 L2：内容操作阶段。

###### 2.2.1.1 文件上传

**业务说明**：向当前浏览目录上传文件：支持多文件选择与拖拽上传；落盘走「临时文件写入 + rename 原子生效」，避免半写文件（R-05）；目标目录经 R-04 校验；同名冲突时不静默覆盖——提示操作者显式选择覆盖或跳过（解释性决策，多文件时逐个决策或统一决策的交互口径归 D4）。上传完成记审计（R-03）。所属 L3：文件上传与下载。

###### 2.2.1.2 大文件分块上传

**业务说明**：超过单请求阈值的文件按分块传输（R-05）：分块依次上传、服务端校验分块序号与总大小、全部到齐后合并并原子落盘；分块大小等参数归 D2/D3 细化（D0 建议 5MB 仅为建议值）；断点续传二期（D0 拍板，本阶段中断即整任务重传）。所属 L3：文件上传与下载。

###### 2.2.1.3 文件下载

**业务说明**：单文件数据取出：按流式传输下载文件内容；目录打包下载不做（OUT）；只读角色禁下载（ADR-018）；下载动作记审计（解释性决策：下载为数据取出，从紧把握——与账户与安全基座「审计导出记审计」同口径）。所属 L3：文件上传与下载。

##### 2.2.2 在线编辑

**业务说明**：受管根内文本文件的在线内容编辑。编辑保存为全量覆盖写，无版本历史、无协同（OUT）。

###### 2.2.2.1 文件内容编辑

**业务说明**：在线打开并编辑文本文件：编辑器提供语法高亮；保存时全量覆盖写回（写回目标经 R-04 校验）；二进制文件与超过大小上限的文件拒绝在线编辑并提示改用下载后本地处理（上限数值归 D2/D3）；保存成功记审计（R-03）。所属 L3：在线编辑。

##### 2.2.3 文件与目录整理

**业务说明**：文件系统结构的变更业务：新建、重命名、移动、删除。删除不直接销毁内容而是入站回收站（R-17，ADR-021）——真实销毁仅发生在回收站清空环节（2.3.1.4）。

###### 2.2.3.1 新建与重命名

**业务说明**：在当前目录新建空文件或空目录；对既有文件/目录在原目录内重命名。新建与重命名目标名经合法性校验（不含路径分隔符等），操作记审计（R-03）。所属 L3：文件与目录整理。

###### 2.2.3.2 移动

**业务说明**：将文件/目录（含整棵子树）移动到目标目录（跨目录移动）；源路径与目标目录均经 R-04 校验；目标同名冲突时提示操作者显式选择覆盖或放弃，不静默合并；移动完成记审计（R-03）。所属 L3：文件与目录整理。

###### 2.2.3.3 删除入站

**业务说明**：删除文件/目录（目录递归整体）的受控删除：条目移入回收站而非直接销毁（R-17，ADR-021 拍板），回收站侧的入站登记规则见 2.3.1.1；删除动作记审计（R-03）。本 L4 承载删除的用户发起动作与确认，入站后的还原/清空治理归回收站治理阶段。所属 L3：文件与目录整理。

##### 2.2.4 权限与属主管理

**业务说明**：文件系统元数据（权限位与属主）的修改业务，服务「接管存量环境」下对既有文件权限的运维调整。修改对象经 R-04 校验，操作记审计（R-03）。

###### 2.2.4.1 权限修改

**业务说明**：修改文件/目录的访问权限位（chmod 语义）：以所有者/组/其他三组读-写-执行九位呈现与修改（交互表示法归 D4）；递归修改目录权限的口径归 D2/D3。所属 L3：权限与属主管理。

###### 2.2.4.2 属主修改

**业务说明**：修改文件/目录的属主用户与属主组（chown 语义）：候选为操作系统的用户与组清单（system_user/system_group，读系统实况的实时投影、不落库）；修改完成记审计（R-03）。所属 L3：权限与属主管理。

##### 2.2.5 压缩与解压

**业务说明**：受管根内的归档打包与拆包业务，支持 tar / tar.gz / zip 三种格式（D0 指定）。解压是路径逃逸的高危入口（压缩包内条目路径可含 `../` 或绝对路径——zip slip 类攻击），条目级路径校验为强制规则。

###### 2.2.5.1 压缩

**业务说明**：将浏览中选中的多个文件/目录压缩为一个归档文件（tar / tar.gz / zip 三选一），归档产物落在当前浏览目录；压缩对象与产物路径经 R-04 校验；压缩完成记审计（R-03）。所属 L3：压缩与解压。

###### 2.2.5.2 解压

**业务说明**：将 tar / tar.gz / zip 归档解压到指定目标目录：逐条目校验解压目标真实路径仍在白名单内（防 zip slip 类条目路径逃逸，R-04 在归档场景的强制延伸），越界条目拒绝并整体失败回滚；目标同名冲突时提示操作者显式选择覆盖或跳过；解压完成记审计（R-03）。所属 L3：压缩与解压。

### 2.3 回收站治理阶段

**业务说明**：删除动作的缓冲与可逆闭环（R-17，ADR-021）。回收站为受管根下单一目录（`.dougong-trash/`）+ trash 内唯一标识子目录的方案（D0 待细化项，本阶段落定，见 2.3.1.1）；trash_entry 元数据落 SQLite（原路径、删除时间、操作者、类型、大小、trash 内标识）；trash_entry 状态机「在站 → 已还原 / 已清空」（kb 拍板）。回收站列表查看属查看类操作，按 ADR-018 对两类角色开放；还原与清空属变更类操作，仅管理员可执行（ADR-018），记审计（R-03）。

##### 2.3.1 回收站治理

**业务说明**：回收站的入站登记、列表查看、还原与清空四项业务能力。所属 L2：回收站治理阶段。

###### 2.3.1.1 回收站入站登记

**业务说明**：删除入站（2.2.3.3）的回收站接收规则（D0 待细化项，本阶段落定）：回收站为受管根下单一目录 `.dougong-trash/`，每个被删条目在 trash 内以唯一标识子目录存放（标识含时间与随机成分，避免重名覆盖）；同时写 trash_entry 元数据记录（原路径、删除时间、操作者、类型、大小、trash 内标识）落 SQLite。跨设备降级规则：被删条目与回收站不在同一文件系统时（受管根含挂载点场景），rename 失败（EXDEV）则降级为「复制入站 + 原条目删除」，降级事实记审计。选择单一回收站方案的理由：所有入站路径集中在受管根内，避免多回收站目录与跨挂载点 rename 失败的复杂处理。所属 L3：回收站治理。

###### 2.3.1.2 回收站列表查看

**业务说明**：呈现全部在站条目的 trash_entry 清单：原路径、删除时间、操作者、类型（文件/目录）、大小；在站条目才出现在列表（已还原/已清空为终态，见 2.3.1.3/2.3.1.4）；列表查看对管理员与只读用户同等开放（ADR-018 全可看）。所属 L3：回收站治理。

###### 2.3.1.3 回收站还原

**业务说明**：将在站条目移回其原路径（trash_entry 记录的原路径），还原目标经 R-04 校验；原路径已被占用的还原冲突策略（D0 待细化项，本阶段落定）：提示操作者显式选择覆盖或放弃，不做自动改名——被覆盖是不可逆动作，必须操作者知情确认；还原成功后条目转「已还原」终态、从回收站列表消失，trash_entry 记录保留（低频操作量小，供追溯）；还原动作记审计（R-03）。所属 L3：回收站治理。

###### 2.3.1.4 回收站清空

**业务说明**：销毁在站条目的终局动作：删除 trash 内对应内容并将 trash_entry 记录物理删除（条目转「已清空」，记录不保留——销毁即不可追溯，销毁事实由审计留痕）；支持清空全部在站条目；自动清理策略（D0 待细化项，本阶段落定）：默认仅手动清空，不设自动清理；可选的保留天数自动清理留二期；清空动作记审计（R-03）。所属 L3：回收站治理。

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 文件条目（file_entry） | 受管根内文件/目录/符号链接在面板中的投影对象：路径、类型、大小、权限、属主、修改时间 | 实时投影，元数据不落库（kb 拍板） |
| 回收站条目（trash_entry） | 一次删除入站在回收站中的记录：原路径、删除时间、操作者、类型、大小、trash 内标识 | 落 SQLite，ADR-021 新增对象 |
| 受管根 | 文件操作业务边界：白名单前缀，默认 `/`，可配置 | R-04；配置入口 ⚠️A12 |
| 排除目录清单 | 受管根内被禁操作的目录清单（如 `/proc`、`/sys`、`/dev`） | R-04「可配置排除」 |
| 安全路径层 | 「EvalSymlinks 解析真实路径 → 白名单前缀校验」的两步校验机制 | R-04；files 适配器实现归后端工程 |
| 路径逃逸 | 经 `../` 相对路径、符号链接外指、压缩包条目路径等手段绕过受管根边界 | 防逃逸测试为里程碑验收硬项（M2） |
| zip slip | 压缩包内条目声明越界路径（`../`/绝对路径）使解压写出白名单外的攻击手法 | 解压逐条目校验（2.2.5.2） |
| 原子落盘 | 上传写盘「临时文件 + rename」两段式，避免半写文件可见 | R-05 |
| 分块上传 | 超阈值大文件按分块传输、服务端合并的传输方式 | R-05；断点续传二期 |
| 回收站（.dougong-trash/） | 受管根下单一回收站目录，被删条目以唯一标识子目录存放于此 | R-17 / ADR-021，D1 落定方案 |
| 入站登记 | 删除动作的回收站接收：条目移入 trash + trash_entry 落库 | 2.3.1.1；跨设备降级 copy+delete |
| 还原冲突 | 还原时原路径已被占用的情形 | 决策权在操作者：覆盖或放弃，不自动改名 |
| 在站 | trash_entry 活动态：条目仍在回收站中、出现在列表 | 状态机：在站 → 已还原 / 已清空（kb） |
| 在线编辑 | 面板内编辑器对文本文件的加载-编辑-全量覆盖写回 | 语法高亮；无版本历史/协同（OUT） |
| 属主 | 文件的属主用户与属主组（操作系统语义） | 候选为 system_user/system_group 实时投影 |
