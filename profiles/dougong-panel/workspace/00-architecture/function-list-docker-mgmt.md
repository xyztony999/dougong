## 第一部分：文档概述

### 1.1 背景与目标

依据《斗拱面板 容器管理（docker-mgmt）应用架构》（application-arch-docker-mgmt.md v1.0），按用户类型分章列出容器管理可操作的菜单项与功能点描述，作为功能开发、页面设计（D4）与权限配置的依据。功能点遵循的业务规则：R-12 只接管已有 daemon、不做应用商店/一键部署，R-13 Compose 经容器 label 自动识别 + `docker compose` CLI 参数数组调用，R-03 全变更审计（经 account-auth 审计契约），R-08 命令参数数组纪律，ADR-013 Compose 走 CLI 不走 SDK 编排，ADR-018 只读边界，ADR-025 容器状态枚举含 paused，以及 D1 落定的口径（容器状态映射与动作矩阵、Compose 定位失败兜底、日志尾部行数与跟踪，见附录C 与 BA 附录B）。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|

## 第二部分：功能清单

> 本章按用户类型分章，每章按应用域→功能模块→功能子模块逐层描述菜单和功能点。

### 本清单概览

容器管理面向两类操作者：

- **管理员（admin）**：本域全部功能的执行者——容器观测（清单/日志/资源占用）、容器生命周期操作（启停/重启/暂停恢复/删除）、镜像列表/拉取/删除、卷与网络的列表/删除、Compose 项目清单/up/down/restart/日志；全部变更动作自动记入审计（R-03）；
- **只读用户（readonly）**：按 ADR-018「全模块可查看 + 禁一切变更」——可查看容器/镜像/卷/网络/Compose 项目全部清单、容器与 Compose 项目日志（日志属查看类）、容器资源占用与未装引导呈现；无任何变更入口（无启停/删除/拉取/Compose 操作）。

全局行为说明（无独立菜单，作用于全部章节）：daemon 探测与连接（S-45-01）为进入容器业务时自动执行的机制，接管结论（可用 + daemon 版本信息 / 不可用）呈现于容器视图页头；全部清单为 daemon 实况投影（面板外变更如实呈现）；动作可用性按 BA 附录B 矩阵随容器当前态约束（服务端同样校验）。本域无访客触达点（全部功能位于登录会话之后）。

## 2.1 管理员（admin）

**用户类型概述**：容器运维主链的唯一执行角色：接管结论与全部清单查看，容器生命周期六类动作（按状态矩阵约束），镜像/卷/网络治理，Compose 项目级操作；所有变更动作自动记入审计（R-03）。

#### 2.1.1 核心业务域

**应用域概述**：管理员对容器状态迁移主链的操作能力（动作可用性受状态矩阵约束）。

##### 2.1.1.1 容器生命周期管理（C-12）

**功能说明**：容器启动/停止/重启、暂停/恢复、删除六类状态迁移动作；动作与当前态不匹配时入口禁用并提示原因（服务端同样校验）。

###### 容器启停与重启（C-12-01）

**功能说明**：容器的启动、停止与重启动作。

| 菜单名称 | 功能点描述 | 所属功能子模块 | 备注 |
|---------|-----------|---------------|------|
| 容器启停与重启 | 对指定容器执行启动（仅 stopped 态开放）、停止（running/paused 态开放，对 paused 等效先恢复后停止）、重启（running/paused 态开放）；入口按状态矩阵（BA 附录B.2）随当前态开放/禁用并提示原因；操作即时生效并记审计 | 容器启停与重启（C-12-01） | 记审计（R-03）；对象来源为容器列表（S-46-01） |

###### 容器暂停与恢复（C-12-02）

**功能说明**：容器的暂停与恢复动作。

| 菜单名称 | 功能点描述 | 所属功能子模块 | 备注 |
|---------|-----------|---------------|------|
| 容器暂停与恢复 | 对指定容器执行暂停（仅 running 态开放——进程冻结、容器与资源保留）与恢复（仅 paused 态开放）；排障冻结现场场景（ADR-025 拍板动作集）；操作即时生效并记审计 | 容器暂停与恢复（C-12-02） | 记审计（R-03）；区别于多数面板只做启停 |

###### 容器删除（C-12-03）

**功能说明**：容器的删除动作（确认制，仅 stopped 态开放）。

| 菜单名称 | 功能点描述 | 所属功能子模块 | 备注 |
|---------|-----------|---------------|------|
| 容器删除 | 删除指定容器：确认文案含容器名与镜像信息，确认后执行；删除入口仅对 stopped 态开放，running/paused/过渡态禁用并提示先停止（MVP 无强制删除语义）；删除解除该容器对镜像/卷/网络的引用 | 容器删除（C-12-03） | 记审计（R-03）；引用解除是资源线删除可达性前提（AA 附录B） |
| 容器创建 | 经表单创建并启动容器（docker run 语义）：镜像（本地缺失时自动先拉取，复用镜像拉取通道；失败如实报错不创建）/容器名/端口映射（多组）/环境变量（多组）/挂载（卷名或主机路径，多组）/重启策略（不重启/总是/除非手动停止/失败时）/网络选择（下拉默认 bridge，数据源为网络清单实况）；服务端逐项格式校验；创建后容器进入实况清单（动作矩阵按新状态天然覆盖） | 容器创建（C-12-04，v1.1） | 变更类操作，记审计（detail 不含环境变量值）；readonly 不渲染（ADR-018 负空间） |

## 2.2 只读用户（readonly）

**用户类型概述**：按 ADR-018「全模块可查看 + 禁一切变更」：查看容器/镜像/卷/网络/Compose 项目全部清单、容器与 Compose 项目日志、容器资源占用；界面不提供任何生命周期操作、删除、拉取与 Compose 项目操作入口；未装 Docker 时同样见安装引导。越界操作被拒绝并明确提示边界原因。
