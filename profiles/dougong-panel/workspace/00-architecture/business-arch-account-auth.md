## 第一部分：文档概述

### 1.1 背景与目标

斗拱面板是面向个人自托管场景的单机运维面板，账户与安全基座（account-auth）是其里程碑 M1 的地基模块，也是横切全系统的安全基座：审计日志被所有业务模块调用（规则 R-03），会话鉴权被 Web 终端等 WebSocket 场景复用（规则 R-18），RBAC 权限矩阵是全部页面与接口的权限基线。业务输入来源：idea.md §4.1 M1（初始化引导、登录+TOTP+锁定、会话管理+CSRF、多用户+RBAC、审计日志）、D0 需求澄清报告（d0-clarification-account-auth.md，2026-11-12）及其沉淀的决策 ADR-017~020。

本业务架构设计目标：

1. 以 L1-L4 层级刻画账户与安全基座「准入准备 → 账户管理 → 身份认证 → 会话存续 → 审计追溯」的业务全生命周期；
2. 将已拍板的业务规则（R-01 登录锁定、R-02 会话与 CSRF、R-03 全变更审计、ADR-017 初始化双入口互斥、ADR-018 只读边界、ADR-019 会话过期策略、ADR-020 审计保留策略）落到确定的业务活动节点上；
3. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

> ⚠️假设A11（本设计新增，推导自材料 idea.md §4.1 M1「多用户 + RBAC」与 ADR-018 两角色边界）：D0 澄清未显式列出「账户管理面」（管理员创建/删除用户、密码重置、全员自助改密与 TOTP 绑定），但多用户 + 两角色必须经账户管理面才能生效，panel_user 的 TOTP 开关字段也需要管理入口。本架构按行业惯例将其纳入业务范围并单列 L3，如后续裁剪需同步三文档。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

账户与安全基座遵循「先有管理员，再有账户，再能登录，登录后持续受控，全程留痕」的业务主线，按时间序划分五个业务阶段：

- **准入准备阶段**：面板安装后处于未初始化态，通过 Web 向导或 CLI 双入口（互斥，先到先得）创建首个管理员；未初始化前一切业务不可用；
- **账户管理阶段**：管理员维护面板用户及其角色指派（管理员/只读），各用户自助维护自己的凭证（密码、TOTP）；
- **身份认证阶段**：凭密码（及可选 TOTP）登录，失败受锁定规则约束，登录成功建立受 CSRF 保护的会话；
- **会话存续阶段**：会话按绝对过期与空闲滑动续期策略存续，可主动登出或被强制下线；会话存续期间每个请求都经过鉴权与角色边界管控；
- **审计追溯阶段**：全部变更类操作与安全事件写入只追加的审计日志，支持查询、导出，并按保留策略自动清理。

五阶段为严格时间序依赖：准入准备产出首个账户 → 账户管理维护账户集合 → 身份认证消费账户凭证 → 会话存续承载认证后的操作 → 审计追溯贯穿并记录以上全部阶段的关键业务事件。

### 2.1 准入准备阶段

**业务说明**：面板生命周期的业务起点。安装完成后系统处于「未初始化」态，必须先创建首个管理员账户方可使用任何业务能力。本阶段提供 Web 向导与 CLI 子命令两个互斥入口（ADR-017），并以「先到先得」的仲裁规则保证全系统有且仅有一个初始化结果。

##### 2.1.1 管理员初始化

**业务说明**：创建面板第一个管理员账户的业务能力。所属 L2：准入准备阶段。双入口互斥生效：任一入口完成初始化后，另一入口永久拒绝；并发初始化以先落库者胜出（单行初始化标记仲裁）。

###### 2.1.1.1 Web 首次访问向导初始化

**业务说明**：浏览器首次访问面板时的强制初始化向导：设置管理员用户名与登录密码（密码策略按 A10 假设从宽：最小长度 8，无强制字符类），可选开启 TOTP 两步验证。初始化完成后向导永久关闭，后续访问一律进入登录页。所属 L3：管理员初始化。

###### 2.1.1.2 CLI 子命令创建管理员

**业务说明**：通过服务器上的面板 CLI 子命令（`dougong` set-admin 类）创建管理员，覆盖无浏览器、自动化脚本等场景；参数与向导一致（用户名/密码/可选 TOTP）。所属 L3：管理员初始化。

###### 2.1.1.3 初始化互斥仲裁

**业务说明**：双入口并发时的唯一性保证：以单行初始化标记的先落库者胜出仲裁，后到者收到「已初始化」拒绝并引导转向登录；确保系统任意时刻至多一个初始化结果（ADR-017 建议的初始化锁单行写入）。所属 L3：管理员初始化。

###### 2.1.1.4 未初始化全站拦截

**业务说明**：未初始化状态下，面板拦截一切业务路由并将访问者引导至初始化向导；初始化完成后拦截自动失效（ADR-017：未初始化前拦截一切路由）。所属 L3：管理员初始化。

### 2.2 账户管理阶段

**业务说明**：面板用户（panel_user，区别于操作系统用户）全生命周期管理：管理员侧的用户维护与角色指派，以及每个登录用户对自己凭证的自助管理。角色为管理员（admin）/只读（readonly）固定两类（MVP 不做角色 CRUD，ADR-018）。⚠️假设A11：本阶段业务活动为「多用户 + RBAC」生效前提（见 1.1）。

##### 2.2.1 用户管理

**业务说明**：管理员对其他面板用户的创建、删除与密码重置。业务约束：删除用户不得使系统失去最后一个管理员（唯一管理员保护）；被删用户的全部在线会话立即失效。所属 L2：账户管理阶段。

###### 2.2.1.1 用户创建与角色指派

**业务说明**：管理员创建面板用户并指派角色（管理员/只读二选一）；密码满足最小 8 位策略（A10）。所属 L3：用户管理。

###### 2.2.1.2 用户删除

**业务说明**：管理员删除面板用户，其全部在线会话同步吊销；受唯一管理员保护约束——不允许删除系统中最后一个管理员账户。所属 L3：用户管理。

###### 2.2.1.3 密码重置

**业务说明**：管理员为指定用户重置登录密码（新密码满足最小 8 位策略）；重置后该用户既有会话吊销，需以新密码重新登录。所属 L3：用户管理。

##### 2.2.2 账户自助管理

**业务说明**：每个登录用户维护自身凭证的业务能力：修改自己的登录密码、绑定/解绑自己的 TOTP。自助凭证操作不属于只读角色「禁一切变更」的受限范围（行业惯例：凭证自助始终可用）。

###### 2.2.2.1 修改登录密码

**业务说明**：登录用户验证旧密码后设置新密码（满足最小 8 位策略，A10）；修改成功后本人其他会话吊销，仅保留当前会话。所属 L3：账户自助管理。

###### 2.2.2.2 TOTP 绑定与解绑

**业务说明**：登录用户按 RFC 6238 标准（30 秒时间窗，允许 ±1 窗口偏差）绑定 TOTP（扫码录入密钥并验证一个动态码后生效）；解绑需验证密码确认。绑定状态决定下次登录是否要求动态码。所属 L3：账户自助管理。

### 2.3 身份认证阶段

**业务说明**：面板访问者以已注册账户凭证换取受保护会话的业务过程。密码为必选要素，TOTP 为可选第二要素；失败尝试受锁定规则约束（R-01）；登录成功即建立 HttpOnly Cookie 会话并发放 CSRF 令牌（R-02）。

##### 2.3.1 登录认证

**业务说明**：核对用户名/密码（及启用 TOTP 时的动态码）并签发会话的准入业务。认证成功、失败、锁定均作为安全事件进入审计追溯。所属 L2：身份认证阶段。

###### 2.3.1.1 密码登录

**业务说明**：以用户名 + 密码认证；密码校验使用抗暴力破解的慢哈希存储比对（存储态细节归应用设计）。服务端对全部输入做校验，不信任前端（R-14）。所属 L3：登录认证。

###### 2.3.1.2 TOTP 两步验证

**业务说明**：对已开启 TOTP 的账户，密码通过后继续校验 6 位动态码（RFC 6238，30 秒窗口 ±1）；动态码错误按一次登录失败计。所属 L3：登录认证。

###### 2.3.1.3 登录失败锁定

**业务说明**：连续 5 次登录失败锁定账户 15 分钟，锁定期满自动解除（R-01）；锁定期间一切登录尝试被拒绝并提示剩余时间。锁定、解除均记入审计。所属 L3：登录认证。

###### 2.3.1.4 会话签发与 CSRF 发放

**业务说明**：认证通过后建立会话：会话令牌经 HttpOnly Cookie 承载（不入 localStorage），同时发放全站 CSRF 令牌，后续变更类请求须同源校验 + CSRF 令牌双重校验（R-02）。所属 L3：登录认证。

### 2.4 会话存续阶段

**业务说明**：会话自建立至终结期间的存续治理与逐请求访问控制。过期策略默认绝对过期 12 小时 + 空闲超时 2 小时滑动续期，两项均可配置（ADR-019）；强制下线为管理员立即吊销。存续期间每个请求经角色判定执行只读边界（ADR-018），Web 终端等 WebSocket 场景复用同一会话鉴权（R-18）。

##### 2.4.1 会话治理

**业务说明**：会话生命周期治理：按可配置的有效期策略自动存续或过期，支持用户主动登出与管理员强制下线；提供在线会话可观测能力。所属 L2：会话存续阶段。

###### 2.4.1.1 会话有效期管理

**业务说明**：会话双轨过期策略——绝对过期（默认 12 小时，自建立起算）与空闲超时（默认 2 小时，每次活跃滑动顺延），两项均可配置（ADR-019）；任一到期会话即失效，访问被引导重新登录。所属 L3：会话治理。

###### 2.4.1.2 登出

**业务说明**：用户主动终结当前会话：立即吊销服务端会话并清除浏览器侧 Cookie，登出动作记入审计。所属 L3：会话治理。

###### 2.4.1.3 在线会话查看与强制下线

**业务说明**：查看当前在线会话清单（账户、建立时间、最后活跃时间、来源）；管理员可对任意会话执行强制下线（立即吊销，ADR-019），强制下线属变更类操作、记入审计。所属 L3：会话治理。

##### 2.4.2 访问控制

**业务说明**：基于角色的逐请求访问控制（RBAC）。角色为管理员/只读固定两类；只读边界为「全模块可查看（含审计日志）+ 禁一切变更 + 禁 Web 终端 + 禁上传下载」（ADR-018）。

###### 2.4.2.1 请求鉴权

**业务说明**：对每个业务请求判定会话有效性与操作者身份：无有效会话的请求被拒绝并引导登录；变更类请求额外校验同源 + CSRF 令牌（R-02）。所属 L3：访问控制。

###### 2.4.2.2 只读边界管控

**业务说明**：对只读角色执行边界管控：全部查看类操作放行（含审计日志查看），一切变更类操作、Web 终端、上传下载一律拒绝（ADR-018）；拒绝结果向操作者明确提示边界原因。所属 L3：访问控制。

###### 2.4.2.3 WS 鉴权复用

**业务说明**：WebSocket 类业务（Web 终端等）握手时复用同一会话鉴权与角色判定（R-18）；会话失效或角色不符时拒绝连接，会话中途失效时已建立的终端连接断开。终端侧连接限流属 Web 终端业务（OUT）。所属 L3：访问控制。

### 2.5 审计追溯阶段

**业务说明**：全系统变更行为的只追加留痕与治理。所有变更类操作记录「谁、何时、改了什么、结果」（R-03）；认证与会话安全事件一并留痕；审计日志保留 90 天，由后台每日任务自动清理过期记录，清理动作本身记审计，到期前可手动导出（ADR-020）。各业务模块的埋点经统一接口约定接入（本域只定接口约定，埋点实现归各模块）。

##### 2.5.1 审计记录

**业务说明**：审计日志的只追加写入能力，是横切全模块的业务契约。所属 L2：审计追溯阶段。

###### 2.5.1.1 变更操作审计

**业务说明**：记录全部变更类操作的四要素——操作者、时间、变更对象与变更内容、执行结果（R-03）；只追加、不可修改删除。所属 L3：审计记录。

###### 2.5.1.2 安全事件审计

**业务说明**：记录账户与安全域自身的安全事件：登录成功/失败、账户锁定/解锁、强制下线、密码重置、TOTP 绑定/解绑、审计清理与导出等。所属 L3：审计记录。

###### 2.5.1.3 跨模块审计接口约定

**业务说明**：向全部业务模块开放的审计写入接口约定（事件主体、动作、对象、变更内容、结果的标准语义）；本域只维护该约定本身，各业务模块的埋点实现归各模块（D0 边界 OUT）。所属 L3：审计记录。

##### 2.5.2 审计查询与治理

**业务说明**：审计日志的消费与体积治理：按条件查询、手动导出、按保留策略自动清理。审计日志对只读角色可见（ADR-018「全可看含审计」）。

###### 2.5.2.1 审计日志查询

**业务说明**：按时间范围、操作者、动作类型、对象等条件分页检索审计日志；管理员与只读角色均可使用（ADR-018）。所属 L3：审计查询与治理。

###### 2.5.2.2 审计日志导出

**业务说明**：管理员将审计日志手动导出留存（尤其用于 90 天清理前的留档，ADR-020）；导出动作本身记入审计。只读角色可查询但不可导出（导出视为数据取出，从紧把握——解释性决策）。所属 L3：审计查询与治理。

###### 2.5.2.3 审计过期清理

**业务说明**：后台每日任务自动清理超过 90 天的审计记录（ADR-020）；每次清理动作（清理批次与条数）本身记入审计，保证清理行为可追溯。所属 L3：审计查询与治理。

```
    │   └── 跨模块审计接口约定
    └── 审计查询与治理
        ├── 审计日志查询
        ├── 审计日志导出
        └── 审计过期清理
```

> 描述 L3 关键业务之间的上下游依赖关系，为后续应用架构中模块调用分析提供依据。

| 上游 L3 | 依赖方向 | 下游 L3 | 依赖说明 |

| 管理员初始化 | → | 用户管理 | 初始化产出的首个管理员账户是用户管理的数据源头 |
| 用户管理 | → | 登录认证 | 角色指派与账户存在性决定可登录性与登录后的权限基线 |
| 账户自助管理 | → | 登录认证 | 密码修改与 TOTP 绑定状态改变后续登录的认证要素 |
| 登录认证 | → | 会话治理 | 登录成功签发会话，进入会话存续治理 |
| 会话治理 | → | 访问控制 | 访问控制以会话有效性与操作者身份为判定输入 |
| 访问控制 | → | 用户管理 | 权限判定读取账户的角色指派 |
| 登录认证 | → | 审计记录 | 登录成功/失败、锁定/解锁作为安全事件写入审计 |

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 面板用户（panel_user） | 登录面板的人员账户，区别于操作系统用户（system_user） | 英文命名经 ADR-015 确认 |
| 角色（role） | 面板用户权限类别，固定为管理员（admin）/只读（readonly）两类 | MVP 不做角色 CRUD |
| 初始化引导 | 面板安装后创建首个管理员的过程，Web 向导与 CLI 双入口互斥 | ADR-017 |
| 初始化互斥仲裁 | 双入口并发初始化时「先落库者胜出」的唯一性保证 | 单行初始化标记 |
| 登录锁定（lockout） | 连续 5 次登录失败后账户 15 分钟内拒绝登录 | R-01，期满自动解除 |
| 会话（session） | 登录成功后建立的受保护访问态，HttpOnly Cookie 承载 | R-02，含 CSRF 令牌 |
| 绝对过期 | 自建立起算的会话最长存活时间，默认 12 小时 | ADR-019，可配置 |
| 空闲滑动续期 | 会话每次活跃顺延的空闲超时，默认 2 小时 | ADR-019，可配置 |
| 强制下线 | 管理员立即吊销指定在线会话 | ADR-019 |
| 只读边界 | 只读角色「全可看（含审计）+ 禁变更 + 禁终端 + 禁上传下载」 | ADR-018 |
| TOTP 两步验证 | 基于 RFC 6238 的时间型一次性密码（30 秒窗口 ±1） | 可选开启 |
| 审计日志（audit_log） | 全部变更类操作与安全事件的只追加记录 | R-03 |
| 审计保留策略 | 审计日志保留 90 天，每日后台任务清理，清理本身记审计 | ADR-020 |
| 访客（未认证操作者） | 初始化前的安装者与登录前的账户持有人等未认证操作者 | 仅触达初始化向导与登录页 |
