## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 文件管理器（file-manager）业务架构》（business-arch-file-manager.md v1.0）的 8 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。files 适配器（安全路径层）为材料给定事实（R-04 技术规约），具体实现归 D2/D3 与后端工程，本架构不涉及。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **核心业务域**：回收站治理（trash_entry 有明确状态机「在站 → 已还原 / 已清空」，kb 拍板；对应聚合根 trash_entry（落 SQLite）；删除→还原→清空为本模块「删得回」闭环主链环节，R-17/ADR-021 拍板方向）——满足原则一全部特征（状态机 + 聚合根 + 闭环主链 + 单据型记录）；
- **支撑业务域**：安全路径管控（含 R-04 防逃逸业务规则，被全部功能模块调用编排）、目录浏览与导航（含视图/隐藏条目呈现口径领域规则）、文件上传与下载（含 R-05 原子落盘/分块业务规则）、在线编辑（含二进制/大小上限领域规则）、文件与目录整理（含同名冲突显式决策领域规则）、权限与属主管理（含属主候选实时投影规则）、压缩与解压（含 zip slip 条目级校验业务规则）——七者均含文件运维领域特有业务规则、被主链调用或构成主链操作集合，但无独立状态机（file_entry 为实时投影，无面板侧状态机）；
- **基础数据域**：本模块无基础数据 L3——system_user/system_group 为操作系统实况的实时投影（读系统用户/组清单，非面板维护的引用数据，写入走操作系统自身），仅作为属主修改（S-24-02）的选择数据源；file_entry 为本模块业务对象本身的实时投影（不落库，kb 拍板）；
- **平台支撑域**：本模块无零业务语义的纯技术 L3——压缩/解压算法库调用、分块传输机制为实现细节，其业务规则（格式三选一、条目级防逃逸校验）承载在压缩与解压（S-25）中；files 适配器（安全路径层）实现与 account-auth 对密码哈希的处理口径一致，归后端工程，不构成功能模块。

> ⚠️假设A12（与 BA 文档同源）：受管根与排除目录配置入口（S-19-02）为 R-04「可配置排除」语义的必要落点，D0 输入清单未显式列出，经推导纳入范围；如裁剪需同步 BA/AA/FL 三文档。

> 模块编码衔接说明（编码规则的跨模块执行口径）：功能模块编码全局唯一，承接 account-auth 已占用的 C-01~C-03、S-01~S-05，panel-core 已占用的 S-06~S-12，monitoring 已占用的 S-13~S-16，service-mgmt 已占用的 C-04~C-05、S-17~S-18；本模块核心业务域模块自 C-06 起编，支撑业务域模块自 S-19 起编至 S-25（依据「新模块在域内最大序号后递增」）。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层聚为两个应用域：

- **核心业务域**承载「删得回」闭环：回收站治理以 trash_entry（落 SQLite）为聚合根，承载删除入站登记、列表查看、还原、清空，使删除类操作从不可逆变为可逆缓冲；
- **支撑业务域**承载「进得来 + 动得了」：安全路径管控为全模块强制前置（R-04），目录浏览与导航提供操作入口与对象选择，文件上传与下载、在线编辑、文件与目录整理、权限与属主管理、压缩与解压构成内容操作集合。

调用关系总脉络：全部功能模块的路径参数先经安全路径管控（S-19-01）校验（R-04 强制前置）；浏览与导航是内容操作的入口与对象来源；文件与目录整理的删除动作经回收站入站登记（C-06-01）进入核心域闭环；还原目标路径回流安全校验；全部变更类操作经 account-auth 审计契约留痕（R-03），下载按数据取出口径记审计；全部接口位于登录会话之后并受只读边界管控（account-auth S-03，全局中间件层面生效，不在本模块内单列调用）。跨模块契约与模块边界见附录B。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 L3→DDD 四层归类原则归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | 回收站治理（C-06） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 安全路径管控（S-19）、目录浏览与导航（S-20）、文件上传与下载（S-21）、在线编辑（S-22）、文件与目录整理（S-23）、权限与属主管理（S-24）、压缩与解压（S-25） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | —（本模块无；system_user/system_group 为操作系统实况实时投影，仅作 S-24-02 选择数据源；file_entry 为本模块业务对象本身的实时投影，不落库） |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | —（本模块无；压缩算法库/分块传输机制为实现细节；files 适配器实现归后端工程，R-04） |

### 2.1 核心业务域

**应用域概述**：承载文件删除的可逆缓冲闭环（R-17，ADR-021）：删除入站登记使删除可逆，列表查看使缓冲可见，还原使删除可撤销，清空使销毁可终局。服务的用户群体：管理员（admin）执行还原/清空；只读用户（readonly）可查看回收站列表（ADR-018 全可看），无还原/清空入口。

#### 2.1.1 回收站治理（C-06）

**功能说明**：以 trash_entry（落 SQLite：原路径、删除时间、操作者、类型、大小、trash 内标识）为聚合根的删除缓冲治理：入站登记、列表查看、还原、清空；trash_entry 状态机「在站 → 已还原 / 已清空」（kb 拍板）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（还原/清空仅管理员，列表查看两角色开放）

##### 2.1.1.1 回收站入站登记（C-06-01）

**功能说明**：删除入站的回收站接收机制：被删条目移入受管根下单一回收站目录 `.dougong-trash/` 的唯一标识子目录，同时写 trash_entry 元数据落 SQLite；跨设备（条目与回收站不同文件系统）降级为「复制入站 + 原条目删除」并记审计（BA 2.3.1.1 落定）。系统内部机制，被删除动作（S-23-03）调用，无直接用户交互。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，被 S-23-03 编排）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 路径白名单校验（S-19-01） | 入站来源路径经白名单校验后方可移入 |
| 审计记录（account-auth S-04） | 跨设备降级事实写入审计（R-03） |

##### 2.1.1.2 回收站列表查看（C-06-02）

**功能说明**：呈现全部在站 trash_entry 清单：原路径、删除时间、操作者、类型（文件/目录）、大小；已还原/已清空终态记录不出现在列表。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

*（无调用，只读消费 trash_entry 数据）*

##### 2.1.1.3 回收站还原（C-06-03）

**功能说明**：将在站条目移回原路径：还原目标经白名单校验；原路径被占用时提示操作者显式选择覆盖或放弃，不做自动改名（BA 2.3.1.3 落定）；成功后条目转「已还原」终态、记录保留供追溯。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 路径白名单校验（S-19-01） | 还原目标路径经白名单校验 |
| 审计记录（account-auth S-04） | 还原为变更类操作，写审计（R-03） |

##### 2.1.1.4 回收站清空（C-06-04）

**功能说明**：删除 trash 内条目内容并将 trash_entry 记录物理删除（转「已清空」，销毁事实由审计留痕）；默认仅手动清空，自动清理留二期（BA 2.3.1.4 落定）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 清空为变更类操作（销毁终局），写审计（R-03） |

### 2.2 支撑业务域

**应用域概述**：承载「进得来 + 动得了」：安全路径管控是全模块的强制安全前置（R-04），目录浏览与导航提供视野与操作入口，五个内容操作模块（传输/编辑/整理/权限属主/压缩解压）构成受管根内的变更动作集合。服务的用户群体：管理员（admin）执行全部内容操作；只读用户（readonly）同等使用浏览与导航（ADR-018），在内容操作模块无任何入口。

#### 2.2.1 安全路径管控（S-19）

**功能说明**：R-04 的功能组织落点：路径白名单校验为全模块强制前置机制，受管根与排除目录配置为白名单边界的自身治理（⚠️A12）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）（校验机制作用于全部请求者；配置入口仅管理员）

##### 2.2.1.1 路径白名单校验（S-19-01）

**功能说明**：对全部携带路径的文件操作请求执行「EvalSymlinks 解析真实路径 → 受管根白名单前缀校验 → 排除目录清单校验」（R-04），任一步不通过即拒绝并明确提示越界原因；防 `../` 逃逸、符号链接外指与解压条目越界（zip slip）。被动前置机制，被全部功能模块调用，无直接用户交互。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统前置机制，作用于全部请求）

**调用关系**：

*（无调用，作为全模块路径操作的强制前置被各模块依赖）*

##### 2.2.1.2 受管根与排除目录配置（S-19-02）

**功能说明**：白名单业务边界的治理入口（⚠️A12）：查看与修改受管根（默认 `/`）与排除目录清单（默认建议 `/proc`、`/sys`、`/dev`）；修改为变更类操作记审计，对后续文件操作即予生效（生效细节归 D2/D3）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 白名单配置修改为变更类操作，写审计（R-03） |

### 附录B：跨模块契约与模块边界

**跨模块契约**：

| 契约 | 方向 | 内容 |
|------|------|------|
| 审计写入（account-auth S-04） | 本模块消费 | 全部变更类操作（上传/编辑保存/新建/重命名/移动/删除/权限/属主/压缩/解压/还原/清空/白名单配置修改）按 R-03 写入审计；下载按数据取出口径写审计（解释性决策） |
| 会话鉴权与只读边界（account-auth S-03） | 本模块消费 | 全部接口位于登录会话之后；只读角色按 ADR-018「全可看 + 禁变更 + 禁上传下载」：同等查看目录内容/导航/回收站列表，全部变更与下载被全局边界管控拒绝 |
| files 适配器（安全路径层） | 本模块消费 | 本模块为 files 适配器的唯一业务消费模块（D0 拍板）；「EvalSymlinks → 白名单前缀校验」语义由 R-04 定义，实现归后端工程 |

本模块为服务消费终模块：不向其他业务模块输出契约（cron-backup 等后续模块对文件能力的消费如出现，另行在对应模块设计中定义）。

| 事项 | 归属 |

| 编辑器版本历史 / 协同编辑 | 非目标（D0） |
| 目录打包下载 | MVP 不做，留二期 |
| 大文件断点续传 | 二期（本阶段仅分块上传） |
