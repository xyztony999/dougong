## 第一部分：文档概述

### 1.1 背景与目标

防火墙（firewall）是斗拱面板里程碑 M7 的安全防线模块，也是「接管存量环境」哲学在主机网络入口侧的落点：服务器上既有的 ufw 或 firewalld 后端不重装、不替换，自动识别并接管（规则 R-15），端口规则以后端实况为唯一事实源。本模块误操作风险为全面板最高——一次错误删除可将面板自身的访问入口一并封锁（失联风险），因此面板端口保护为设计硬项（M7 明示）。业务输入来源：idea.md §4.1 M7（自动识别 ufw/firewalld、端口规则列表/添加/删除、面板自身端口保护提示、端口开放状态展示）、D0 需求澄清报告（d0-clarification-firewall.md，2026-11-12）、知识库对象 firewall_rule（端口、协议、方向、来源限制、后端类型；后端实态投影不落库）、规则 R-03（全变更审计，经账户与安全基座审计契约）、R-08（命令一律参数数组、禁 shell 拼接）、R-15（存量自动识别）、ADR-018（只读边界，经账户与安全基座生效）。

本业务架构设计目标：

1. 以 L1-L4 层级刻画防火墙「识别既有后端 → 看清规则与端口 → 安全增删规则」的业务主线；
2. 将已拍板的业务规则与边界（R-15 双后端自动识别、R-08 命令纪律、面板端口保护硬项、D0 确认的 OUT 边界）落到确定的业务活动节点上；
3. 落定 D0 移交本阶段的三个次要细化口径（firewalld 端口级映射口径、ufw 动作表达口径、监听端口信息来源口径，均已按 D0 建议方向落定，见 2.2.1.2 / 2.3.1.1 与附录B）；
4. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

边界声明（OUT，沿 D0 结论）：

- firewalld zone 与富规则（rich rule）完整管理：MVP 仅做端口级规则映射，zone 使用后端默认（D0 确认口径）；
- IP 黑白名单独立管理：二期；
- 出站方向规则：材料仅涉及入站端口开放治理，出站规则不在本域；
- 端口扫描、入侵检测：非目标；
- 防火墙后端自身的安装、启用/停用开关（如 ufw enable、firewalld 服务启停）：材料 M7 未列，本域不做——识别阶段仅呈现后端运行状态；firewalld 作为 systemd 服务的启停可经 systemd 服务管理（service-mgmt）业务域达成，不在本域单列业务活动；
- ufw/firewalld 命令通道封装（firewallx 适配器，R-08 参数数组纪律）为零业务语义的技术实现，归后端工程实现，不构成业务活动。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

防火墙遵循「识别既有后端 → 看清规则与端口 → 安全增删规则」的业务主线，划分为三个业务阶段：

- **后端识别阶段**：自动探测服务器上既有的 ufw / firewalld（ufw 优先），识别结果决定规则业务的后端通道；两者均无时以引导提示呈现，不将「无后端」误呈现为「无规则」；
- **规则观测阶段**：对当前后端的端口级规则投影的只读呈现（规则列表），以及系统监听端口与规则投影的开放状态对照；
- **规则治理阶段**：端口规则的添加与删除（经后端命令即时生效并审计），以及对涉及面板自身端口的高危操作执行警示与二次确认保护。

三阶段为支撑依赖序而非严格时间序：后端识别为观测与治理提供通道判定；观测为治理提供对象来源与结果反馈视图；治理结果经后端实况投影回到观测视图，循环往复。全部规则对象为后端实况投影、面板不落库（kb 拍板口径：后端实态投影不落库）；全部变更类操作按 R-03 记入审计（经账户与安全基座审计契约，跨域约定见应用架构附录B），变更操作仅管理员可执行（ADR-018）。

### 2.1 后端识别阶段

**业务说明**：「识别即接管」在本域的落点。面板不安装、不切换、不配置任何防火墙后端，仅以探测结论作为规则业务的后端通道依据；识别为进入防火墙业务时的被动自动行为，无需用户发起。识别结论包含后端类型（ufw / firewalld）与其运行状态（呈现用，无开关动作——启停边界见 1.4）。

##### 2.1.1 防火墙后端识别

**业务说明**：对服务器既有防火墙后端的自动探测与结论产出，是本域全部规则业务的前提。所属 L2：后端识别阶段。

###### 2.1.1.1 双后端自动识别

**业务说明**：按「ufw 优先、firewalld 次之」的优先级探测既有后端（R-15 接管哲学：识别既有后端、不引入新防火墙）：探测维度为后端存在且可用；识别结论为唯一后端类型 + 后端运行状态（如 ufw 的启用/未启用、firewalld 的运行态），后续规则观测与治理均经该唯一后端通道执行；探测为只读行为，不改变后端任何状态。所属 L3：防火墙后端识别。

###### 2.1.1.2 无后端引导提示

**业务说明**：ufw 与 firewalld 均未检测到时的降级呈现：防火墙业务以引导提示页呈现，说明未检测到受支持的后端并指引安装其一后再使用；提示页不提供代为安装动作（MVP）。业务约束：均无后端时规则相关功能整体不可用，不得将「无后端」呈现为「无规则」的空列表（避免误判防火墙无规则而放松警惕）。所属 L3：防火墙后端识别。

### 2.2 规则观测阶段

**业务说明**：对当前后端端口级规则与系统监听端口的只读呈现能力，是治理动作的对象来源与状态依据。查看能力按 ADR-018「全模块可查看」对管理员与只读用户同等开放，是只读角色在本域的核心价值。

##### 2.2.1 端口规则观测

**业务说明**：端口规则列表与监听端口对照两类查看业务。所属 L2：规则观测阶段。

###### 2.2.1.1 端口规则列表查看

**业务说明**：只读呈现当前后端的端口级规则投影：端口/端口段、协议（tcp/udp）、方向（入站）、来源限制（任意来源或 CIDR 网段）、动作、后端原始语义标识（用于与后端自身工具的输出互认）；规则为后端实况投影、面板不落库，每次呈现均为后端当前实态（面板外变更的后端规则同样如实呈现）。列表对与面板自身端口相关的规则作出标注（标注依据为面板基座的监听配置，涉险判定语义见 2.3.1.3）。所属 L3：端口规则观测。

###### 2.2.1.2 监听端口对照查看

**业务说明**：读取系统当前监听端口清单（监听地址、端口、监听进程），与端口规则投影逐项对照，呈现每个监听端口的开放状态（已被规则放行 / 无放行规则）：其中对外监听且无放行规则的端口（在默认拒绝策略下不可达、在默认放行策略下为风险敞口）为对照视图的重点提示对象。业务口径：对照仅针对入站方向（出站为 OUT）；监听端口取数为系统网络栈只读读取，具体取数通道为技术实现（D0 待细化口径落定：建议与系统监控采集统一取数来源，避免双通道口径漂移）。所属 L3：端口规则观测。

### 2.3 规则治理阶段

**业务说明**：端口规则的变更类管控，是本域业务主链的核心环节。约束：仅管理员可执行（ADR-018 禁变更）；全部操作经当前后端命令通道即时生效并记审计（R-03 / R-08）；涉及面板自身端口的高危操作受面板端口保护约束（见 2.3.1.3）；无后端时本阶段全部业务不可用（见 2.1.1.2）。规则无生命周期状态机（D0 拍板：规则有无即状态），操作即生效、无草稿/审批环节。

##### 2.3.1 端口规则治理

**业务说明**：端口规则的添加、删除与面板端口保护三类治理业务。所属 L2：规则治理阶段。

###### 2.3.1.1 端口规则添加

**业务说明**：管理员录入端口/端口段、协议（tcp/udp）、来源限制（任意来源或 CIDR 网段）、动作并提交，经当前后端命令通道即时生效（命令一律参数数组方式，R-08）。动作支持面随后端能力而定（D0 待细化口径落定）：ufw 提供 allow/deny/reject/limit 全动作（deny 丢弃无回应、reject 明确拒绝、limit 为限速放行的防暴力破解语义）；firewalld 在 MVP 端口级映射口径下仅支持 allow（deny/reject/limit 依赖富规则能力，为 OUT）。firewalld 后端下的写入口径（D0 待细化口径落定）：以永久配置写入并同步生效运行态（永久 + 运行态双写），保证规则在系统重启后仍然有效。变更记审计（R-03）。所属 L3：端口规则治理。

###### 2.3.1.2 端口规则删除

**业务说明**：管理员对指定规则执行删除（删除前经确认），经当前后端命令通道即时生效（R-08）；firewalld 后端下同样按永久 + 运行态双写删除。删除面板端口相关规则时受面板端口保护约束（见 2.3.1.3）。变更记审计（R-03）。所属 L3：端口规则治理。

###### 2.3.1.3 面板端口规则保护

**业务说明**：对涉及面板自身端口的高危规则治理动作执行保护（M7 明示项，D0 定为设计硬项）：删除面板端口的放行规则、或在面板端口上添加阻断类规则（deny/reject）时，先行警示「此操作可能导致面板失去访问」并要求二次确认，确认后方可执行；保护为警示与确认语义，不阻止操作本身（最终执行权在管理员，救援通道为服务器本地/SSH 操作）。涉险判定依据为面板基座的监听配置（面板端口与协议）；判定口径以「规则对象是否直接命中面板端口」为准（端口/端口段直接覆盖面板端口），不做跨规则重叠语义推导（如宽端口段规则的删除影响推导留二期）。所属 L3：端口规则治理。

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 防火墙后端（backend） | 服务器上既有的 ufw 或 firewalld，端口规则的真实承载者 | 自动识别、接管不替换（R-15） |
| ufw | Ubuntu 系默认的防火墙前端，规则为端口级 allow/deny/reject/limit | 识别优先级第一 |
| firewalld | RHEL 系常见的防火墙管理器，规则分永久（permanent）/运行态（runtime）两层 | 识别优先级第二；MVP 端口级映射、zone 用默认 |
| 端口规则（firewall_rule） | 端口级防火墙规则：端口/端口段、协议 tcp/udp、方向（入站）、来源限制、动作 | 后端实况投影不落库；操作即时生效并审计（R-03） |
| 来源限制 | 规则适用的来源范围：任意来源或 CIDR 网段 | |
| 动作（action） | 规则的处理语义：allow 放行 / deny 丢弃 / reject 拒绝 / limit 限速放行 | ufw 全动作；firewalld MVP 仅 allow |
| 永久 + 运行态双写 | firewalld 下规则同时写入永久配置并即时生效运行态 | D1 落定口径，保证重启有效 |
| 监听端口 | 系统网络栈当前处于监听状态的端口（含监听地址与进程） | 只读读取，取数通道为技术实现 |
| 端口开放状态 | 监听端口与规则投影的对照结论：已被规则放行 / 无放行规则 | 仅入站方向 |
| 面板端口保护 | 对直接命中面板自身端口的规则删除放行/添加阻断动作执行警示 + 二次确认 | M7 明示项；判定依据为面板基座监听配置 |
