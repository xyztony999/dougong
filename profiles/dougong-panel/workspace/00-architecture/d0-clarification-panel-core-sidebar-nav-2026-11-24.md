### 7.1 主因确认：页面首次打开要现下载页面文件，期间界面零反馈

代码事实（v0.4.0 / main=273fb5f）：

| 事实 | 位置 |
|------|------|
| 全部页面路由懒加载（`component: () => import(...)`） | `frontend/src/router/index.ts:44-276` |
| 侧栏点击只做 `void router.push(key)`，不跟踪结果 | `frontend/src/layouts/MainLayout.vue:177-179` |
| 菜单选中项绑定**当前**路由，导航完成前不会变 | `MainLayout.vue:175`（`activeKey = computed(() => route.path)`）、`:230`（`:value="activeKey"`） |
| `<router-view />` 不带任何加载态 | `MainLayout.vue:259`、`frontend/src/App.vue:43` |
| 全仓没有 `router.onError`、没有 `vite:preloadError` 处理、没有全局加载条（grep 0 命中） | `frontend/src` |
| 导航要等懒加载组件解析完才切换；非导航类错误转给 errorListeners 后继续 reject | `node_modules/vue-router/dist/vue-router.mjs`（`extractComponentsGuards` 调用 `rawComponent()`；`pushWithRedirect` :1308） |

### 7.2 放大因素确认：后端从不压缩页面文件

- `backend/internal/api/server.go:105-114`：只设缓存头与 Content-Type，随后 `io.Copy` 原样写出，
  没有任何压缩。实测带 `Accept-Encoding: gzip, deflate, br, zstd` 请求入口脚本，响应没有
  `Content-Encoding`。项目也不随发 nginx 配置（`install.sh` 不生成站点配置）。
- 即：用 IP:端口直连永远是未压缩；经 nginx 时取决于用户自己的 `gzip_types`（nginx 默认只压
  `text/html`）。
- 对照（7.1 表）：重页面提速 2.2–2.5 倍（P3 历史趋势 10.9s → 4.4s，终端 6.6s → 2.2s；登录进首页
  10.6s → 5.1s）；轻页面以延迟为主，压缩收益很小（约 0.1s）。

### 7.3 「完全没反应、点多下也没用」之一：面板升级后旧页面还开着

- 读码 + 实测：`server.go:92-99` 对不存在的文件走 SPA 兜底。`GET /assets/SitesHub-OLDBUILD0.js`
  实测返回 **200 + `text/html; charset=utf-8` + index.html（441 字节）**。升级后二进制内嵌的分包
  文件名哈希全变，旧页面请求的文件已不存在，拿到的却是 HTML。
- 复现（无头浏览器）：登录后访问两个页面 → 令「升级前没下载过」的分包按服务器真实应答返回
  （回放上面这份 200+HTML，不是手写响应）→ 点「计划任务」：
  - 第 1 次、第 2 次：路由都停在 `/monitoring`，toast 0 条；router error = `Failed to fetch dynamically
    imported module: …/assets/cron-backup-BMD9H9UD.js`；控制台 1 条未处理的 Promise 拒绝。
  - 升级前打开过的页面（「防火墙」）仍可用（文件在缓存里）。
  - 手动刷新后：同一页面一次点开。
- 结论：升级后只要不刷新，所有还没打开过的页面都点不动，且没有任何提示。这能完整解释
  「完全没反应、要多点几下也不行，刷新一下就好」。

### 7.4 「完全没反应」之二：分包请求被网络抖动打断

- 复现（P1 直出，首次点「防火墙」，令分包请求 `ConnectionReset`）：路由停在 `/monitoring`，
  toast 0 条；router error = `Unable to preload CSS for /assets/firewall-CBRmp_MC.css`；
  1 条未处理的 Promise 拒绝。网络恢复后再点一次 → 正常打开。
- 结论：跨境直连常见的连接重置会让这一次点击静默失败；要等用户再点一次才会重试。失败处理
  完全缺失（`router/index.ts:298-375` 只有前置守卫）。

### 7.5 「跟时机有关」确认：关闭弹窗/抽屉后的短暂吃点击（次要）

- 在会出帧的浏览器里实测（计划任务「新建任务」弹窗 ×「取消」/ ×；备份「新建备份任务」抽屉 ×）：

| 关闭方式 | 关闭后侧栏重新可点 | 被吃掉的点击 |
|---------|-------------------|-------------|
| 弹窗（取消按钮） | 264ms | 13 / 113 / 209ms 的点击被吃（落在全屏滚动层 `n-modal-scroll-content` 上） |
| 弹窗（右上角 ×） | 266ms | 13 / 109 / 206 / 261ms 被吃 |
| 抽屉（右上角 ×） | 217ms | 13 / 107 / 200ms 被吃（落在 `.n-drawer-mask…leave-active` 上） |
| 关闭后主线程忙 800ms（模拟电脑卡顿） | 弹窗 1,068ms / 抽屉 817ms | 忙碌窗口内点了 8 次，3–4 次被吃 |

- 机制：Naive UI 弹窗遮罩离场动画 0.25s、抽屉遮罩 0.2s（`naive-ui/es/_styles/transitions/`、
  `es/modal/src/styles/index.cssr.mjs`），动画结束前遮罩仍在最上层且 `pointer-events` 有效。
- 结论：关掉弹窗/抽屉后立刻（约 0.25 秒内，卡顿时更久）点侧栏，那一下会丢。这是真实的次要因素，
  只解释「偶尔丢一下」，解释不了「点多下都没用」。

### 7.7 结论

「有时点不动」= 页面文件首次下载的等待 + 零反馈（主因）；「完全没反应、点多下也没用」=
分包请求失败后的静默（网络抖动，或面板升级后旧页面）；「偶尔丢一下」= 关闭弹窗/抽屉后的遮罩。
慢链路与「后端不压缩」把等待放大到秒级。都是面板侧可以修的缺陷，不依赖用户改 nginx。

## 9. 需要用户在服务器侧核对的事项（本机无法代做）

本机没有到服务器的 SSH，以下三项只能请用户执行，结果用于确认修复效果：

1. 面板访问地址是域名（HTTPS）还是 IP:端口（HTTP）。
2. 现在的 nginx 有没有压缩 JS：在服务器上执行
   `curl -s http://127.0.0.1:<面板端口>/ | grep -o '/assets/index-[^"]*\.js'` 取得入口脚本路径，再对
   `http://127.0.0.1:<面板端口><该路径>` 与经 nginx 的同一地址分别执行
   `curl -sI -H 'Accept-Encoding: gzip'`，看有没有 `Content-Encoding: gzip`。
   （修复后前一个一定有；后一个没有也不影响，面板自己已经压缩，nginx 会原样透传。）
3. 「完全没反应」是否出现在面板升级之后没刷新的页面上（刷新一次就恢复）——对应 7.3。

## 10. 取证中发现的另一缺陷：安全入口路径开启后面板在浏览器里打不开

### 10.1 现象（无头 Edge 实测，2026-11-24，隔离实例 v0.4.0 构建）

在隔离实例上用面板自己的接口开启安全入口（`POST /panel/config/update {"entryPathEnabled":true}`，

| 请求 | 结果 |

| `GET /0BhXOwHtKWdIc5nZ/` | 200，`text/html`，入口 HTML |

### 10.3 文档层面的缺口

- PageSpec 声明「前端不感知 `/{entryPath}` 前缀：**静态资源与 API 均相对路径**」
  （`02-detailed/interaction/admin/panel-core/panel-core.md` 第 7 节「安全入口前缀」行），实现并未做到：
  资源与接口都是根路径。设计与实现在这里不一致，而验收没有发现。
- 验收只到 HTTP 级：`backend/internal/api/panel/module_test.go:368` `TestEntryPathGuardOverHTTP` 只用
  带前缀 / 不带前缀的**接口**请求验证网关本身；Gate 2 报告 `05-reports/gate2-panel-core-2026-11-14.md`
  也是以这些 HTTP 级用例作为依据，没有在浏览器里开着入口路径把页面走通。
