## 第一部分：文档概述

### 1.1 背景与目标

容器管理（docker-mgmt）是斗拱面板里程碑 M9 的容器运维模块，也是「接管存量环境」哲学在容器侧的落点：连接服务器上已有的 Docker daemon（`/var/run/docker.sock`），既有的容器、镜像、卷、网络与 Compose 项目自动纳入管理，一律接管而非要求重装（规则 R-12、R-15）。与 1Panel 的应用商店路线明确切割——只管理已有环境，不做应用商店/一键部署（R-12）；与 DPanel 同哲学（接管既有容器），本项目补齐宿主机建站能力后两者卖点合一（idea.md §8 竞品分析）。

业务输入来源：idea.md §4.1 M9（daemon 连接、容器/镜像/卷/网络/Compose 管理、明确边界）与 §5.3（dockerx 适配器：Docker 官方 Go SDK + `docker compose` CLI）、D0 需求澄清报告（d0-clarification-docker-mgmt.md，2026-11-12，A7 已拍板关闭）、知识库对象 container / image / volume / network / compose_project（均为 Docker API 实态投影，面板不落库）、规则 R-03（全变更审计）、R-08（命令一律参数数组、禁 shell 拼接）、ADR-013（Compose 走 `docker compose` CLI 不走 SDK 编排）、ADR-025（容器状态枚举含 paused，running/stopped/paused 为面板操作映射核心态）。

本业务架构设计目标：

1. 以 L1-L4 层级刻画容器管理「接管接入 → 容器运维 → 资源治理 → Compose 治理」的业务主线；
2. 将已拍板的业务规则与边界（R-12 只接管不重装且不做应用商店、R-13 Compose 经 label 识别 + CLI 参数数组、ADR-013 CLI 编排方式、ADR-025 三核心态含 paused）落到确定的业务活动节点上；
3. 落定 D0 移交本阶段的三个次要细化口径（容器状态枚举全集与面板动作映射矩阵、Compose 工作目录定位失败兜底、日志尾部行数与跟踪口径，均按 D0 建议方向落定，见 2.2.2.1 / 2.4.1.2 / 2.2.1.2 与附录B）；
4. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

- 应用商店 / 一键部署应用：**明确不做**（R-12，与 1Panel 路线切割的立身之本；**v1.1 修订：用户自建容器 / 自建 Compose 项目 / 新建网络与卷的创建类能力已纳入**〔见 ⚠️A18~A21，2026-11-21 D0 五项拍板〕——不做的是「预设应用目录商店」，用户自建动作与本轮纳入不冲突）；
- 容器内终端：二期可选（idea.md M9 标注，二期前容器排障经容器日志达成）；
- **v1.1 新增 OUT**：容器创建高级项（启动命令/入口点覆写、labels 手工编辑、设备挂载、CPU/内存限制）——基础全集起步，高级项后续增量；Compose 项目删除（down 后工作目录/配置文件清理）——本轮 down 即止；compose.yml 在线编辑器——经文件管理器或重新创建；镜像构建（Dockerfile build）——镜像仅拉取既有形态；
- 镜像构建 / Dockerfile 管理、Registry / 私有仓库管理：非目标（材料未列）；
- Swarm / Kubernetes 编排、跨主机 / 多服务器集中管理：非目标（idea.md §4.2 二期或不做）；
- 远程 daemon 接入（TCP/TLS 连接远端 Docker）：不做——只接管本机 daemon（sock），与单机面板定位一致；
- dockerx 适配器封装（官方 Go SDK 客户端 + `docker compose` CLI 调用，R-08 参数数组纪律）为零业务语义的技术实现，归后端工程实现，不构成业务活动；
- Docker 自身的安装执行（安装引导仅做检测与指引文案，不代为安装）：不做——引导页指引安装但不提供代装动作，避免面板引入发行版包管理差异（pkgmg 适配器为独立技术资产）。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

容器管理遵循「接得上（接管既有 daemon）→ 管得住（容器运维）→ 清得掉（资源治理）→ 编得了（Compose 治理）」的业务主线，划分为四个业务阶段：

- **接管接入阶段**：探测并连接本机已有 Docker daemon，作为本域全部业务的唯一通道；未安装 Docker 时以安装引导页呈现而非报错，不将「未安装」误呈现为「无容器」；
- **容器运维阶段**：容器的只读观测（列表/状态/日志/资源占用）与生命周期操作（启停/重启/暂停恢复/删除），状态与动作受面板核心三态映射矩阵约束（ADR-025）；
- **资源治理阶段**：镜像（列表/拉取/删除）、卷（列表/删除）、网络（列表/删除）三类 Docker 资源的治理，删除受 daemon 侧引用约束；
- **Compose 治理阶段**：经容器 label 自动识别既有 Compose 项目并聚合呈现，支持 up/down/restart/logs 四类项目级操作（经 `docker compose` CLI，ADR-013）。

四阶段为支撑依赖序而非严格时间序：接管接入为其余三阶段提供通道前提（未接管时本域全部业务降级为安装引导）；容器运维与资源治理消费通道执行单对象操作；Compose 治理在通道之上叠加「label 聚合 + CLI 编排」的项目级视角，且其容器仍可经容器运维逐个操作（项目级操作不可用时的兜底通道）。全部对象为 Docker API 实态投影、面板不落库（kb 拍板口径），面板外变更（docker CLI 直接操作）如实呈现；全部变更类操作按 R-03 记入审计（经账户与安全基座审计契约，跨域约定见应用架构附录B）。

### 2.1 接管接入阶段

**业务说明**：「识别即接管」在本域的落点（R-15）。面板不安装、不配置、不重启 Docker daemon，仅以「本机 unix sock 探测 + 连接可用性判定」产出接管结论；接管结论决定本域其余三个阶段的可呈现性——daemon 可用时全部业务就绪，不可用时整体降级为安装引导呈现。接入为进入容器业务时的被动自动行为，无需用户发起，也无任何「登记/纳管」动作（区别于数据库管理需要凭据配置：本机 sock 接管无凭据）。

##### 2.1.1 Docker daemon 接管

**业务说明**：对本机已有 Docker daemon 的探测、连接与降级呈现，是本域全部业务的前提。所属 L2：接管接入阶段。

###### 2.1.1.1 daemon 探测与连接

**业务说明**：探测本机 Docker daemon（`/var/run/docker.sock`）并建立连接、判定可用性的业务能力：探测结论为「daemon 可用（含版本信息呈现）」或「不可用」两种；探测与连接为只读行为，不改变 daemon 任何状态；daemon 版本作为接管结论的伴随信息呈现（用于识别 daemon 能力代际，不参与业务判定）。容器/镜像/卷/网络/Compose 的一切读取与操作均经该唯一通道执行。所属 L3：Docker daemon 接管。

###### 2.1.1.2 未装 Docker 安装引导

**业务说明**：未探测到可用 daemon 时的降级呈现：容器业务以安装引导页呈现，说明本机未检测到可用的 Docker daemon，并指引安装 Docker 后再使用（指引文案含官方安装途径说明，不提供代为安装动作，见 1.4 边界）。业务约束：daemon 不可用时本域全部业务不可用，不得将「未安装」呈现为「无容器」的空列表（与防火墙「无后端 ≠ 无规则」同判：空列表会误导操作者误判环境状态）。所属 L3：Docker daemon 接管。

### 2.2 容器运维阶段

**业务说明**：本域业务主链——对已有容器的观测与生命周期操作。观测侧呈现容器实况（名称/镜像/状态/资源占用/所属 Compose 项目 label）；操作侧提供启动/停止/重启/暂停/恢复/删除六类动作，动作可用性受「Docker API 全态 → 面板核心三态」映射矩阵约束（ADR-025）。容器状态为 daemon 实况投影，面板操作即时生效、无草稿/审批环节。

##### 2.2.1 容器观测

**业务说明**：容器实况的只读呈现能力，是生命周期操作的对象来源与结果反馈视图。所属 L2：容器运维阶段。

###### 2.2.1.1 容器列表与状态查看

**业务说明**：呈现 daemon 上全部容器的实况清单：名称、镜像、状态（按附录B 状态映射呈现为面板核心三态或过渡态透传）、所属 Compose 项目（透传容器 label，未参与 Compose 的容器如实呈现为无项目归属）。清单为实况投影不落库，面板外变更（docker CLI 直接创建/删除）如实呈现；观测为只读行为。所属 L3：容器观测。

###### 2.2.1.2 容器日志查看与跟踪

**业务说明**：单个容器运行日志的查看业务：默认呈现日志尾部（D0 建议方向落定：尾部 500 行，行数为呈现参数）并支持实时跟踪（跟随容器日志流输出，断开查看即止）；日志为 daemon 实况流，面板不做日志持久化与轮转（无历史回溯语义——面板启用前的日志经 daemon 尾部读取达成，面板自身不存储）。业务口径：跟踪期间容器被删除或停止时，日志流终止并如实提示原因。所属 L3：容器观测。

###### 2.2.1.3 容器资源占用查看

**业务说明**：单个容器资源占用的实时快照查看业务：CPU 占用率与内存用量（kb 对象表要点：资源占用）。快照为查看时刻的实况值，不提供历史趋势（容器级历史指标不在本域，整体主机指标归系统监控业务域）。所属 L3：容器观测。

##### 2.2.2 容器生命周期管理

**业务说明**：容器状态迁移的操作业务，本域业务主链核心。容器状态机已拍板（ADR-025）：面板操作映射核心三态 running / stopped / paused，动作集为 start / stop / restart / pause / unpause；Docker API 全态（created / running / paused / restarting / removing / exited / dead）按附录B 映射矩阵归并呈现，动作可用性随当前态约束（矩阵见附录B.2）。全部操作经接管通道即时生效，无草稿/审批环节；操作结果经容器观测刷新确认；变更记审计（R-03）。所属 L2：容器运维阶段。

###### 2.2.2.1 容器启停与重启

**业务说明**：容器的启动（start）、停止（stop）与重启（restart）业务：启动面向 stopped 态容器；停止与重启面向 running / paused 态容器（对 paused 容器执行停止/重启等效先恢复后执行，由 daemon 语义保证）；操作按当前态约束入口开放（矩阵见附录B.2），动作与当前态不匹配时明确报错、不盲目下发。变更记审计（R-03）。所属 L3：容器生命周期管理。

###### 2.2.2.2 容器暂停与恢复

**业务说明**：容器的暂停（pause）与恢复（unpause）业务：暂停面向 running 态容器（暂停后进程冻结、容器与资源保留）；恢复面向 paused 态容器。暂停/恢复为 ADR-025 拍板的面板动作集组成部分（区别于多数面板只做启停——排障场景需冻结进程保留现场）。变更记审计（R-03）。所属 L3：容器生命周期管理。

###### 2.2.2.3 容器删除

**业务说明**：容器的删除业务：删除前经确认；删除入口仅对 stopped 态容器开放，运行中（running/paused）与过渡态容器的删除入口禁用并提示先停止（D1 落定口径：MVP 不提供强制删除语义，避免误删运行中服务——与 R-12「接管而非破坏」哲学一致）；删除后容器实况从清单消失，其占用的镜像引用随之解除。变更记审计（R-03）。所属 L3：容器生命周期管理。

###### 2.2.2.4 容器创建（v1.1 新增）

**业务说明**：经面板表单创建并启动容器的业务（⚠️A18，2026-11-21 D0 拍板——docker run 语义一步到位）：填写镜像（本地不存在时自动先拉取，复用镜像拉取通道，拉取失败如实报错不创建）、容器名、端口映射（多组宿主端口:容器端口）、环境变量（多组键值）、挂载（卷名或主机路径:容器路径，多组）、重启策略（不重启/总是/除非手动停止/失败时）、网络选择（既有网络下拉，默认 bridge）。创建前服务端逐项校验（容器名格式/端口映射格式/环境变量格式——R-14）；创建后容器即时进入实况清单（零台账哲学不变：daemon 为事实源，动作矩阵按新容器状态天然覆盖）。表单的网络/挂载下拉数据源消费网络管理/卷管理清单实况（新建网络/卷创建后即时可选，⚠️A21）。变更记审计（R-03）。所属 L3：容器生命周期管理。

### 2.3 资源治理阶段

**业务说明**：容器运行的三类支撑资源——镜像、卷、网络——的治理业务。三者均为 daemon 实况投影：镜像支持列表/拉取/删除，卷与网络支持列表与删除（idea.md M9「卷与网络：列表与基本操作」，D0 IN 落定为列表与删除，创建经容器/Compose 运行时按需发生，面板不单列创建业务）。删除受 daemon 侧引用约束：镜像被容器引用、卷被容器挂载、网络被容器接入时删除被 daemon 拒绝，面板如实呈现拒绝原因，不做前置引用推导、不提供强制删除绕过（引用关系随容器实况漂移，前置推导无权威性；daemon 拒绝为唯一权威判定）。

##### 2.3.1 镜像管理

**业务说明**：容器镜像的列表、拉取与删除业务。所属 L2：资源治理阶段。

###### 2.3.1.1 镜像列表查看

**业务说明**：呈现 daemon 上全部镜像实况：名称、tag、大小（kb 对象表要点）。清单为实况投影不落库；引用情况不做前置推导标注（删除以 daemon 校验为准，见 2.3 阶段说明）。所属 L3：镜像管理。

###### 2.3.1.2 镜像拉取

**业务说明**：从镜像仓库拉取指定镜像（名称:tag）的业务：拉取为用户主动发起的变更类操作（面向 Docker Hub 等公有仓库，私有仓库管理为 OUT），拉取进度如实呈现，完成后镜像进入清单。变更记审计（R-03）。所属 L3：镜像管理。

###### 2.3.1.3 镜像删除

**业务说明**：删除指定镜像的业务：删除前经确认；镜像被容器引用时删除被 daemon 拒绝并如实呈现拒绝原因（不提供强制删除绕过，见 2.3 阶段说明）；删除后释放镜像存储。变更记审计（R-03）。所属 L3：镜像管理。

##### 2.3.2 卷管理

**业务说明**：Docker 卷的列表与删除业务。所属 L2：资源治理阶段。

###### 2.3.2.1 卷列表查看

**业务说明**：呈现 daemon 上全部卷实况：名称、挂载点、大小（kb 对象表要点）。清单为实况投影不落库。所属 L3：卷管理。

###### 2.3.2.2 卷删除

**业务说明**：删除指定卷的业务：删除前经确认；卷被容器挂载时删除被 daemon 拒绝并如实呈现拒绝原因（daemon 为最终权威，面板不做引用前置推导）。变更记审计（R-03）。所属 L3：卷管理。

###### 2.3.2.3 卷创建（v1.1 新增）

**业务说明**：创建命名卷的业务（⚠️A21）：名称、驱动（默认 local）；重名与 daemon 拒绝（如非法名称）如实透传呈现（daemon 为最终权威）；创建后卷进入清单实况并即时可选为容器挂载源（2.2.2.4 表单联动）。变更记审计（R-03）。所属 L3：卷管理。

##### 2.3.3 网络管理

**业务说明**：Docker 网络的列表与删除业务。所属 L2：资源治理阶段。

###### 2.3.3.1 网络列表查看

**业务说明**：呈现 daemon 上全部网络实况：名称、驱动、子网（kb 对象表要点）。清单为实况投影不落库。所属 L3：网络管理。

###### 2.3.3.2 网络删除

**业务说明**：删除指定网络的业务：删除前经确认；网络被容器接入时删除被 daemon 拒绝并如实呈现拒绝原因；daemon 预定义网络（如 bridge / host / none）不可删除，如实呈现 daemon 拒绝语义（不提供绕过）。变更记审计（R-03）。所属 L3：网络管理。

###### 2.3.3.3 网络创建（v1.1 新增）

**业务说明**：创建自定义网络的业务（⚠️A21）：名称、驱动（默认 bridge）、子网与网关可选；重名与 daemon 拒绝（非法名称/子网冲突等）如实透传呈现（daemon 为最终权威）；创建后网络进入清单实况并即时可选为容器创建的网络源（2.2.2.4 表单联动）。变更记审计（R-03）。所属 L3：网络管理。

### 2.4 Compose 治理阶段

**业务说明**：既有 Compose 项目的自动识别与项目级操作业务。识别经容器 label 自动聚合（R-13：label 携带项目名、工作目录、配置文件等元数据），操作经 `docker compose` CLI 执行（ADR-013：参数数组方式、经 label 定位工作目录与配置文件，不走 SDK 编排）。项目为 label 聚合的派生投影（面板不落库、无自有状态机——项目运行态为其容器组实况的汇总呈现）；项目级操作与容器级操作并存：项目内容器仍可经容器运维阶段逐个操作（项目级操作不可用时的兜底通道）。

##### 2.4.1 Compose 项目治理

**业务说明**：Compose 项目的识别、生命周期操作与日志查看三类业务。所属 L2：Compose 治理阶段。

###### 2.4.1.1 Compose 项目自动识别

**业务说明**：经容器 label 自动识别既有 Compose 项目并聚合呈现的业务：扫描容器 label 中的项目元数据（项目名、工作目录、配置文件），按项目名聚合为项目清单（名称、工作目录、配置文件、容器清单，kb 对象表要点）；识别为只读行为，无任何登记动作（与「接管而非登记」哲学一致）；未携带 Compose label 的容器不归属任何项目（作为普通容器经容器运维阶段管理）。所属 L3：Compose 项目治理。

###### 2.4.1.2 Compose 项目生命周期操作

**业务说明**：项目级的 up / down / restart 操作业务：经 label 定位工作目录与配置文件后调用 `docker compose` CLI 执行（参数数组方式，R-08/R-13/ADR-013）。定位失败兜底（D0 移交口径落定）：label 记录的工作目录已移除或配置文件缺失时，操作不可用并明确提示缺失原因（呈现 label 记录的路径）；此时项目内容器仍可经容器运维阶段逐个操作（兜底通道），不因项目级操作失效而失去管理能力。变更记审计（R-03）。所属 L3：Compose 项目治理。

###### 2.4.1.3 Compose 项目日志查看

**业务说明**：项目级日志查看业务：呈现项目全部容器聚合的日志尾部（口径同容器日志：尾部 500 行 + 实时跟踪）；经 `docker compose` CLI 执行，定位失败兜底同 2.4.1.2。所属 L3：Compose 项目治理。

###### 2.4.1.4 Compose 项目创建（v1.1 新增）

**业务说明**：经面板创建新 Compose 项目的业务（⚠️A20，2026-11-21 D0 拍板）：表单粘贴 compose.yml 文本（服务端 YAML 语法校验，失败报错带行号）→ 项目名（=工作目录名，小写连字符白名单校验 R-14）→ 面板在工作目录根（/opt/dougong-compose/{项目名}/，编译期常量，落盘目录防逃逸——项目名白名单+根前缀约束）自动创建目录并写入 docker-compose.yml → 自动执行 `docker compose up -d`（复用既有 CLI 通道与项目级互斥）→ 项目经既有 label/文件识别进入清单（投影哲学不变：面板不落库，配置文件为唯一事实源）。支持可选归属标签预埋（⚠️A22：labels 追加至 compose.yml 的 labels 段——供应用管理容器化应用标记归属，全网视图经标签区分归属但保持可见）。重名项目（工作目录已存在）如实拒绝并提示。创建记审计（R-03，detail 含项目名，**不含 compose.yml 全文**）。所属 L3：Compose 项目治理。

### 附录B：容器状态映射与面板动作矩阵（D1 口径落定）

> ADR-025 拍板：面板操作映射核心三态 running / stopped / paused（含 paused）；Docker API 全态由 D1 列全并映射。本附录为两个映射表的唯一权威口径，AA/FL/D2 沿用。

**B.1 Docker API 全态 → 面板核心态映射**

| Docker API 状态 | 含义 | 面板呈现 |
|----------------|------|---------|
| running | 运行中 | running（核心态） |
| paused | 已暂停（进程冻结） | paused（核心态，ADR-025 拍板纳入） |
| created | 已创建未启动 | stopped（核心态） |
| exited | 已退出 | stopped（核心态） |
| dead | 异常死锁（daemon 标记不可用） | stopped（核心态） |
| restarting | 重启中（过渡态） | 过渡态：如实透传原始值，操作入口禁用，操作完成/失败后回落三态 |
| removing | 删除中（过渡态） | 过渡态：如实透传原始值，操作入口禁用，操作完成/失败后回落三态 |

**B.2 面板动作 × 当前面板态 可用性矩阵**（✓ = 入口开放；— = 入口禁用并提示原因）

| 面板动作 | running | paused | stopped | 过渡态 |
|---------|---------|--------|---------|--------|
| 启动（start） | — | — | ✓ | — |
| 停止（stop） | ✓ | ✓（等效先恢复后停止，daemon 语义保证） | — | — |
| 重启（restart） | ✓ | ✓ | —（stopped 容器经「启动」达成） | — |
| 暂停（pause） | ✓ | — | — | — |
| 恢复（unpause） | — | ✓ | — | — |
| 删除（delete） | —（提示先停止） | —（提示先恢复并停止） | ✓ | — |

补充口径：动作与当前态不匹配时服务端明确报错（不盲目下发 daemon 调用）；MVP 不提供强制删除（对运行中容器带强制参数删除）语义。

### 附录C：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| Docker daemon 接管 | 连接本机已有 Docker daemon 并以其为唯一管理通道，不安装不重装 | R-12/R-15；`/var/run/docker.sock` |
| 容器（container） | 已有 Docker daemon 上的容器对象 | 实态投影不落库；名称/镜像/状态/资源占用/所属 Compose 项目 label |
| 镜像（image） | 容器镜像：名称、tag、大小 | 拉取面向公有仓库；私有仓库管理 OUT |
| 卷（volume） | Docker 卷：名称、挂载点、大小 | 删除即数据销毁，确认文案明示不可恢复 |
| 网络（network） | Docker 网络：名称、驱动、子网 | 预定义网络不可删，如实呈现 daemon 拒绝 |
| Compose 项目（compose_project） | 经容器 label 自动识别聚合的项目：名称、工作目录、配置文件、容器清单 | label 聚合派生投影，不落库无自有状态机 |
| Compose label | 容器携带的 Compose 元数据标签（项目名/工作目录/配置文件等） | R-13；识别与定位的唯一依据 |
| 面板核心三态 | 容器面板操作映射核心态：running / stopped / paused | ADR-025；stopped 归并 created/exited/dead |
| 过渡态 | restarting / removing 两类瞬时 API 态 | 如实透传、操作入口禁用、自然回落三态 |
| 未装引导 | 未检测到可用 daemon 时的安装引导呈现 | 不代装；「未安装」≠「无容器」空列表 |
| 拉取（pull） | 从镜像仓库获取指定镜像的主动变更操作 | 进度如实呈现；变更记审计 |
| 定位失败兜底 | Compose 项目 label 记录的工作目录/配置文件缺失时的处理口径 | 项目级操作不可用 + 明确提示；容器级操作兜底可达 |
