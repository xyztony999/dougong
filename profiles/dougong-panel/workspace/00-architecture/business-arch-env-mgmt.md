## 第一部分：文档概述

### 1.1 背景与目标

环境管理（env-mgmt）是斗拱面板的运行环境供给模块（v0.1.2 用户反馈第 4 项，/pipeline 增量轮新增模块，参照宝塔「软件商店」按本项目定位裁剪）：面板此前只能「接管已有环境」（site-mgmt 接管 nginx、database-mgmt 纳管已运行数据库实例、docker-mgmt 管理已有 daemon 的容器），缺失「从无到有安装环境本体」的能力。本模块补位软件包层：经发行版包管理器（apt / dnf·yum 双系）安装、升级、卸载六类常用运行环境（nginx、Apache、Docker、MySQL、Redis、PHP-FPM），并提供已装环境的版本/服务状态观测与服务启停自启入口。业务输入来源：v0.1.2 用户反馈（D0 增量澄清拍板 2026-11-16——范围=六环境 + 双包管理器系）、项目支持矩阵（install.sh：Debian 11+ / Ubuntu 20.04+ / RHEL 9 系）、既有模块边界（database-mgmt=实例层、docker-mgmt=容器层、service-mgmt=通用 systemd 单元层、site-mgmt=站点层）。

本业务架构设计目标：

1. 以 L1-L4 层级刻画「观测 → 供给 → 运行」的环境全生命周期主线；
2. 将安全纪律落到业务口径（apt/yum 包操作最小权限、幂等、审计，沿用 R-01~R-18 与 SEC-GATE；外部命令一律字面量参数数组 R-08）；
3. 明确与既有模块的边界与交叠（环境本体/实例/容器/通用单元四层分界），为关联模块提供安装引导回链；
4. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

> ⚠️假设（本设计新增，承接 D0 增量澄清与边界裁定，如裁剪需同步三文档）：
>
> - ⚠️A1 目录范围口径：首轮环境目录为面板内置静态清单，六条目——nginx、Apache（httpd）、Docker、MySQL、Redis、PHP-FPM（D0 增量澄清拍板 2026-11-16）；每条目含显示名、描述、关联模块提示（如 Docker → docker-mgmt）与发行版族包名映射（⚠️A7）；目录扩展（更多环境）走面板版本迭代。
> - ⚠️A2 双包管理器口径：Debian 系（Debian/Ubuntu）经 apt，RHEL 系（RHEL/CentOS Stream/Rocky/Alma 9+）经 dnf（无 dnf 回退 yum）；运行时探测择一，两者皆无（或非 Linux/无 systemd）时环境变更能力如实不可用（报错提示，不虚构）；个别环境在特定发行版需第三方官方仓库（典型：RHEL 系 Docker CE 不在 AppStream 内）时，由面板写入发行版仓库源配置（/etc/apt/sources.list.d/ 或 /etc/yum.repos.d/）后再安装，仓库配置写入同样审计留痕（D0 拍板：apt+dnf/yum 双系）。
> - ⚠️A3 异步任务口径：安装/卸载为异步变更任务（包安装可达数分钟，同步等待必超时）：任务状态 pending → running → succeeded / failed；同环境同时至多一个在途任务（互斥）；任务失败原因与命令输出尾部如实呈现；任务取消 MVP 不做（OUT——包管理器中断态不安全）。
> - ⚠️A4 升级口径：已装环境再次执行安装=升级语义（先刷新包索引 apt update / dnf makecache，再安装仓库最新版，幂等）；「检测可升级版本并提示」MVP 不做（OUT 二期）；降级/指定版本安装不做（OUT）。
> - ⚠️A5 服务联动口径：安装完成后不强制 start/enable（尊重发行版包脚本默认行为），服务实况经环境实况探测如实呈现；启停/自启经环境服务运维入口显式操作。
> - ⚠️A6 卸载口径：卸载=包 remove（保留系统配置与数据目录，安全保守），purge 与数据目录清理二期 OUT；卸载前强确认（呈现关联模块在用风险提示——如 Docker 有运行容器、MySQL 有 database-mgmt 纳管实例、nginx 有已纳管站点时列出警示，知情决策不硬阻断），卸载动作审计留痕。
> - ⚠️A7 包名与单元映射口径：每环境每发行版族的包名、systemd 服务单元名、版本查询方式经目录条目内置映射表承载（如 Debian：nginx/apache2/docker.io/mysql-server/redis-server/php-fpm；RHEL 系：nginx/httpd/docker-ce/mysql-server/redis/php-fpm；单元名 apache2 vs httpd 等），映射表为面板编译期数据非用户可配。

### 1.4 范围

| 范围 | 说明 |
|------|------|
| 业务域 | 环境管理（env-mgmt）：环境目录与实况、环境安装与变更、环境服务运维 |
| 业务阶段 | 环境观测阶段、环境供给阶段、环境运行阶段 |

边界声明（OUT，沿 D0 增量澄清结论）：源码编译安装不做（仅发行版仓库包，含个别官方仓库源配置）；多版本并存与切换不做（如 PHP 多版本、MySQL 多发行通道）；「应用市场/插件商店」形态不做（目录内置六环境，按本项目轻量定位裁剪宝塔软件商店面）；任务取消不做（⚠️A3）；purge 卸载与数据目录清理二期（⚠️A6）；可升级版本检测二期（⚠️A4）；Windows/无 systemd 环境不支持（install.sh 支持矩阵外，如实报错）；运行环境内部配置管理不做（nginx 站点配置归 site-mgmt、MySQL 实例管理归 database-mgmt、容器归 docker-mgmt——本模块止步软件包层）。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

环境管理遵循「看得见实况 → 装得上环境 → 管得住服务」的业务主线，按环境供给生命周期划分三个业务阶段：

- **环境观测阶段**：环境目录呈现（内置六环境条目）与环境实况探测（包管理器查询已装版本、systemd 查询服务状态、通道可用性探测）——是供给与运行两阶段的共同数据底座；
- **环境供给阶段**：经包管理器安装/升级/卸载环境本体，异步任务化执行与跟踪，安全纪律（强确认、审计、幂等）贯穿；
- **环境运行阶段**：已装环境的服务启停与自启管理（复用 systemd 通道），衔接 service-mgmt 的通用单元治理。

三阶段为顺序依赖关系：观测产出实况 → 供给改变实况 → 运行作用于供给产物；观测同时为运行阶段提供状态依据。

### 2.1 环境观测阶段

**业务说明**：环境目录与实况的数据底座：面板内置六环境静态目录（⚠️A1），叠加运行时实况探测（已装/版本/服务状态/通道可用性）形成环境全景；观测结果同时是供给动作的前置依据（未装才可安装、已装才可卸载/启停）与关联模块的引导数据源（Docker 未装 → docker-mgmt 引导态提示可安装）。

##### 2.1.1 环境目录与实况

**业务说明**：内置环境目录与运行时实况的合并呈现能力。所属 L2：环境观测阶段。目录为面板版本内置（非用户可配），实况每请求实时探测（不缓存不虚构——nginx 未检出返回未安装，与 site-mgmt 投影真实性同哲学）。

###### 2.1.1.1 环境目录呈现

**业务说明**：呈现内置六环境条目：显示名、描述、关联模块提示（Docker → docker-mgmt、MySQL → database-mgmt、nginx/PHP-FPM → site-mgmt 等，安装后即打通对应模块）；目录随面板版本迭代扩展。所属 L3：环境目录与实况。

###### 2.1.1.2 环境实况探测

**业务说明**：逐环境探测实况：已装状态与版本（经包管理器查询，⚠️A7 映射）、服务运行状态与自启状态（经 systemd 单元查询）、包管理器通道可用性（apt/dnf·yum 探测择一，⚠️A2——通道不可用时变更能力如实标注不可用）；探测为纯读操作。所属 L3：环境目录与实况。

### 2.2 环境供给阶段

**业务说明**：环境本体的安装/升级/卸载能力：经发行版包管理器执行（⚠️A2 双系），异步任务化（⚠️A3），升级与安装同通道幂等（⚠️A4），卸载强确认保守执行（⚠️A6）；全部变更动作审计留痕（R-03），外部命令一律参数数组（R-08），包操作以最小权限执行。

##### 2.2.1 环境安装与变更

**业务说明**：环境供给的变更主链。所属 L2：环境供给阶段。安装/升级/卸载三个动作共用异步任务通道与审计纪律；任务产出（命令输出尾部、失败原因）如实呈现，不虚构成功。

###### 2.2.1.1 环境安装与升级

**业务说明**：安装目录环境：先刷新包索引再经包管理器安装（已装环境同动作为升级到仓库最新版，幂等，⚠️A4）；需第三方官方仓库的环境由面板先配置仓库源再安装（⚠️A2，仓库写入审计）；安装完成后服务状态尊重包脚本默认行为（⚠️A5），实况经观测阶段如实反映。所属 L3：环境安装与变更。

###### 2.2.1.2 环境卸载

**业务说明**：卸载已装环境：强确认交互（呈现关联模块在用风险提示——Docker 有容器/MySQL 有纳管实例/nginx 有站点时列警示，知情决策不硬阻断，⚠️A6）；执行包 remove（保留系统配置与数据目录）；卸载后环境条目回到未装态。所属 L3：环境安装与变更。

###### 2.2.1.3 环境变更任务跟踪

**业务说明**：异步任务的观测与结果确认：任务状态（pending → running → succeeded / failed，⚠️A3）、执行动作、命令输出尾部（排障）；同环境在途任务互斥（重复提交如实拒绝）。所属 L3：环境安装与变更。

### 2.3 环境运行阶段

**业务说明**：已装环境的服务层运维：启停/重启/自启管理（经 systemd 单元通道，与 service-mgmt 共用同一通道资产）；细粒度单元治理（全部系统服务清单）仍归 service-mgmt，本域仅面向目录环境的直达入口。

##### 2.3.1 环境服务运维

**业务说明**：已装环境的服务管控入口。所属 L2：环境运行阶段。操作对象限定目录环境对应的服务单元（⚠️A7 映射），结果如实反馈。

###### 2.3.1.1 环境服务启停与自启

**业务说明**：对已装环境执行服务启动/停止/重启与自启开关：经 systemd 通道生效，结果与失败原因如实呈现；操作审计留痕（R-03）。所属 L3：环境服务运维。

## 第三部分：业务架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：L1 > L2 > L3 > L4。

```
环境管理（env-mgmt）
├── 环境观测阶段
│   └── 环境目录与实况
│       ├── 环境目录呈现
│       └── 环境实况探测
├── 环境供给阶段
│   └── 环境安装与变更
│       ├── 环境安装与升级
│       ├── 环境卸载
│       └── 环境变更任务跟踪
└── 环境运行阶段
    └── 环境服务运维
        └── 环境服务启停与自启
```

### 附录A：L3 业务依赖关系

> 描述 L3 关键业务之间的上下游依赖关系，为后续应用架构中模块调用分析提供依据。

| 上游 L3 | 依赖方向 | 下游 L3 | 依赖说明 |

| 环境目录与实况 | → | 环境安装与变更 | 实况（已装态/通道可用性）是安装/卸载动作的前置依据与按钮态数据源 |
| 环境安装与变更 | → | 环境目录与实况 | 变更任务完成后实况刷新（安装结果经观测反映） |
| 环境目录与实况 | → | 环境服务运维 | 服务运行/自启状态是启停入口的状态依据 |
| 环境目录与实况 | → | docker-mgmt（他域）/ database-mgmt（他域）/ site-mgmt（他域） | 环境未装实况为关联模块引导态提供数据（软引导，无跨模块硬调用） |

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 环境（environment） | 面板可供给的运行环境软件包条目：nginx/Apache/Docker/MySQL/Redis/PHP-FPM 六类 | ⚠️A1 目录范围 |
| 环境目录 | 面板内置的环境静态清单（显示名/描述/关联模块/发行版包名映射） | 编译期数据非用户可配（⚠️A7） |
| 环境实况 | 运行时探测结果：已装/版本/服务状态/自启/通道可用性 | 每请求实时探测不缓存 |
| 包管理器通道 | apt（Debian 系）或 dnf·yum（RHEL 系）的发行版包操作能力 | ⚠️A2 双系探测择一 |
| 官方仓库源 | 个别环境所需的第三方仓库配置（如 RHEL 系 Docker CE） | 面板代写仓库源配置并审计 |
| 环境变更任务 | 安装/升级/卸载的异步执行单元：pending → running → succeeded/failed | ⚠️A3；同环境互斥 |
| 升级（upgrade） | 已装环境再次安装到仓库最新版的幂等语义 | ⚠️A4；先刷新包索引 |
| 卸载（remove） | 包卸载但保留系统配置与数据目录 | ⚠️A6；purge 二期 OUT |
