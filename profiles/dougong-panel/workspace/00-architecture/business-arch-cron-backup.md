## 第一部分：文档概述

### 1.1 背景与目标

斗拱面板是面向个人自托管场景的单机运维面板，计划任务与备份（cron-backup）是其里程碑 M8 模块，承载两条业务线：**计划任务线**——接管服务器既有 cron 定时任务（系统 crontab 读写治理），与项目「接管存量环境、不要求重装」的核心哲学一致；**备份线**——站点目录与数据库的定时备份任务治理、执行记录与产物轮转（规则 R-11）。业务输入来源：idea.md §4.1 M8（cron 管理：CRUD、表达式校验、执行日志尾部、手动触发；备份任务：站点目录 + 数据库 → 本地目录 / 远程〔MVP：本地 + 可选 rsync 目标〕；保留份数轮转）、D0 需求澄清报告（d0-clarification-cron-backup.md，2026-11-12）及其沉淀的决策（ADR-016 backup_run 独立执行记录实体与状态机、R-11 保留份数轮转、R-03 全变更与手动触发记审计、R-08 命令参数数组、ADR-018 只读边界）。

本业务架构设计目标：

1. 以 L1-L4 层级刻画「计划任务接管 → 备份任务治理 → 备份执行治理」的业务全貌：计划任务线覆盖系统 crontab 的接管与全生命周期治理；备份线覆盖任务定义、执行触发（定时/手动）、执行记录（backup_run）、产物消费与按保留份数轮转清理（R-11）；
2. 落定 D0 移交本阶段细化的两个口径（均按 D0 建议方向落定，见 2.1.1、2.3.1.1 与附录B）：
   - **cron 接管边界**：以面板运行用户（通常 root）的 crontab 为主读写域；`/etc/cron.d/` 与 `/etc/cron.hourly|daily|weekly|monthly` 等系统预置位只读展示、不提供写操作；
   - **备份调度器归属**：备份定时调度由面板内置调度器承载（随面板进程运行），独立于系统 cron、不写 crontab——计划任务管理与备份调度解耦，避免写 crontab 的双写一致性问题；
3. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

计划任务与备份包含两条相互独立的业务线，按「接管 → 定义 → 执行」组织为三个业务阶段：

- **计划任务接管阶段**：接管面板运行用户（通常 root）的既有 crontab：系统已有任务自动纳入管理（列表如实呈现面板外变更），面板提供创建、编辑、删除、表达式校验、执行日志尾部查看与手动触发；
- **备份任务治理阶段**：备份任务（backup_job）的定义侧治理——备份源（站点目录〔联动站点清单〕+ 数据库〔联动数据库实例/库清单〕）、备份目标（本地目录 / rsync 远程）、保留份数与调度配置的建立与维护；
- **备份执行治理阶段**：备份的执行侧与记录侧——定时调度执行（面板内置调度器）与立即执行产生备份执行记录（backup_run：running → success / failure，ADR-016），执行历史与产物可查可下载，产物按保留份数轮转清理（R-11）。

三阶段关系：计划任务线与备份线**解耦并行**（D1 落定口径：备份调度由面板内置调度器承载、不写 crontab，计划任务治理不感知备份调度）；备份线内部为「定义 → 执行 → 记录与轮转」的严格前后序——任务定义是执行的输入，执行产出记录与产物，记录与产物按任务定义的保留份数轮转。全部变更类操作与手动触发按 R-03 记入审计（经账户与安全基座审计契约，跨域约定见应用架构附录B）；数据库备份取数复用数据库管理已存凭据（跨域联动，见附录A）。

### 2.1 计划任务接管阶段

**业务说明**：服务器既有 cron 定时任务的接管与全生命周期治理。接管边界（D1 落定口径）：以面板运行用户（通常 root）的 crontab 为读写域——系统已有任务自动纳入管理、如实呈现；`/etc/cron.d/` 与 `/etc/cron.hourly|daily|weekly|monthly` 等系统预置位只读展示（呈现其存在与内容，不提供写操作），避免误改系统预置任务。任务在面板外的变更（手工编辑 crontab）如实反映，不维护面板侧副本。

##### 2.1.1 计划任务管理

**业务说明**：cron 定时任务（cron_job：表达式、命令、备注、来源标注）的接管呈现与读写治理；含表达式校验、执行日志尾部查看与面板代执行的手动触发。所属 L2：计划任务接管阶段。

###### 2.1.1.1 计划任务列表查看

**业务说明**：呈现 root crontab 全部任务（表达式、命令、面板侧备注与来源标注——区分面板创建与系统既有）；同屏只读展示 `/etc/cron.d/` 等系统预置位清单；面板外变更如实呈现（实况投影）。所属 L3：计划任务管理。

###### 2.1.1.2 计划任务创建与编辑

**业务说明**：在 root crontab 新建任务或编辑既有任务（表达式、命令、备注）；提交前经表达式校验（见 2.1.1.4）；来源标注为「面板创建」或「系统既有」（编辑既有任务保留其来源）。变更记审计（R-03）。所属 L3：计划任务管理。

###### 2.1.1.3 计划任务删除

**业务说明**：从 root crontab 删除指定任务（删除前确认）；系统预置位任务不提供删除。变更记审计（R-03）。所属 L3：计划任务管理。

###### 2.1.1.4 cron 表达式校验与执行预览

**业务说明**：对输入的 cron 表达式做合法性解析，并预览未来若干次执行时间；作为创建/编辑提交的前置校验内嵌使用，也可独立试算。所属 L3：计划任务管理。

###### 2.1.1.5 计划任务执行日志查看

**业务说明**：查看系统 cron 执行日志的尾部片段（任务的触发记录），定位任务是否按期执行；日志来源按发行版适配（journalctl -u cron / /var/log/cron，技术实现细节）。只读查看。所属 L3：计划任务管理。

###### 2.1.1.6 计划任务手动触发

**业务说明**：对面板管理的任务由面板代为立即执行一次（不等下一个调度点），受超时控制约束；执行结果与输出呈现给操作者；手动触发记审计（R-03）。所属 L3：计划任务管理。

### 2.2 备份任务治理阶段

**业务说明**：备份任务（backup_job）定义侧的治理：备份源为站点目录（联动站点清单）与数据库（联动数据库实例/库清单，取数复用数据库管理已存凭据）的组合；备份目标为本地目录或 rsync 远程（MVP 范围，跨服务器 rsync 管理界面不做）；保留份数与调度周期随任务定义。任务定义是备份执行治理阶段全部活动的输入。

##### 2.2.1 备份任务管理

**业务说明**：backup_job 的建立、维护与清单呈现；备份源/目标/保留份数/调度构成任务定义五要素。所属 L2：备份任务治理阶段。

###### 2.2.1.1 备份任务列表查看

**业务说明**：呈现全部备份任务（名称、备份源构成、目标、保留份数、调度周期、最近一次执行结论）；任务清单为执行与历史查看的入口。只读查看。所属 L3：备份任务管理。

###### 2.2.1.2 备份任务创建

**业务说明**：建立备份任务：选择备份源（站点目录、数据库实例/库，可多选组合）、配置目标（本地目录或 rsync 远程地址）、保留份数与调度周期。变更记审计（R-03）。所属 L3：备份任务管理。

###### 2.2.1.3 备份任务编辑与删除

**业务说明**：调整既有任务的源/目标/保留份数/调度，或删除任务（删除前确认；任务删除不连带清理既有产物与历史记录）。变更记审计（R-03）。所属 L3：备份任务管理。

### 2.3 备份执行治理阶段

**业务说明**：备份的执行触发与记录治理。执行由两条触发路径产生：定时调度执行（面板内置调度器按任务定义的周期触发，D1 落定口径——独立于系统 cron、不写 crontab）与立即执行（手动触发）；每次执行产生一条备份执行记录（backup_run），状态机为 running → success / failure（ADR-016 已拍板），记录开始/结束时间、耗时、产物路径与大小、触发方式（cron / 手动）；产物可供下载（恢复流程 MVP 不做，手动下载后自行恢复）；记录与产物按任务保留份数轮转清理（R-11）。

##### 2.3.1 备份执行与历史管理

**业务说明**：备份执行的触发（定时/手动）、执行记录（backup_run）全生命周期与产物治理、按保留份数的轮转清理。所属 L2：备份执行治理阶段。

###### 2.3.1.1 备份定时调度执行

**业务说明**：面板内置调度器按各任务定义的调度周期自动触发备份执行，产生 backup_run（触发方式=cron）；调度随面板进程运行，不写系统 crontab。系统内部机制，无用户入口。所属 L3：备份执行与历史管理。

###### 2.3.1.2 备份立即执行

**业务说明**：对指定任务手动发起一次立即备份（不等下一个调度点），产生 backup_run（触发方式=manual）；手动触发记审计（R-03）。所属 L3：备份执行与历史管理。

###### 2.3.1.3 备份历史列表查看

**业务说明**：按任务（或全任务）检索备份执行记录列表（任务、触发方式、状态、开始时间、耗时、产物大小）；running 记录呈现进行中状态。只读查看。所属 L3：备份执行与历史管理。

###### 2.3.1.4 备份执行详情查看

**业务说明**：查看单条 backup_run 的完整信息：状态与起止时间、耗时、触发方式、备份源明细、产物路径与大小、失败原因（如失败）。只读查看。所属 L3：备份执行与历史管理。

###### 2.3.1.5 备份产物下载

**业务说明**：将指定执行记录的备份产物从目标位置取回并下载留存（供恢复使用；自动恢复流程 MVP 不做）。所属 L3：备份执行与历史管理。

###### 2.3.1.6 备份保留轮转清理

**业务说明**：备份执行成功后按任务保留份数自动轮转：超出的最旧产物与对应执行记录清理（R-11）；清理结果反映于备份历史。系统内部机制，无用户入口。所属 L3：备份执行与历史管理。

## 第三部分：业务架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：L1 > L2 > L3 > L4。

```
计划任务与备份（cron-backup）
├── 计划任务接管阶段
│   └── 计划任务管理
│       ├── 计划任务列表查看
│       ├── 计划任务创建与编辑
│       ├── 计划任务删除
│       ├── cron 表达式校验与执行预览
│       ├── 计划任务执行日志查看

├── 备份任务治理阶段
│   └── 备份任务管理
│       ├── 备份任务列表查看
│       ├── 备份任务创建
│       └── 备份任务编辑与删除
└── 备份执行治理阶段
    └── 备份执行与历史管理
        ├── 备份定时调度执行
        ├── 备份立即执行
        ├── 备份历史列表查看
        ├── 备份执行详情查看
        ├── 备份产物下载
        └── 备份保留轮转清理
```
