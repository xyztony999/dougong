# D0 需求澄清报告：account-auth（账户与安全基座）

> 引擎 design 阶段 D0 产物（2026-11-12，主会话澄清）。作为 D1 架构设计的直接输入。
> 需求来源：idea.md §4.1 M1 + knowledge/business-concepts（panel_user/session/audit_log、R-01/R-02/R-03/R-10/R-14）。

## 1. 业务概念解析

| 维度 | 内容 |
|------|------|
| 业务术语 | 初始化引导、登录、TOTP 两步验证、会话、CSRF、登录锁定、RBAC、审计日志 |
| 业务流程 | 初始化引导（创建管理员）→ 登录（密码 [+TOTP]）→ 会话建立（HttpOnly Cookie + CSRF token）→ 操作（变更类记审计）→ 登出/过期/强制下线 |
| 业务角色 | 管理员 admin、只读 readonly（MVP 两类） |
| 业务规则 | R-01 连续 5 次失败锁 15 分钟；R-02 HttpOnly Cookie 会话、token 不入 localStorage、全站 CSRF；R-03 全部变更操作审计；R-10 随机高位端口/安全入口/HTTPS；R-14 服务端校验 |
| 业务数据 | panel_user、session、audit_log、role（admin/readonly） |

## 2. 架构匹配与类型判定

- 匹配结果：workspace 无既有设计文档（idea.md 为项目计划书）→ **全部无匹配**
- 需求类型：**新增** → D1 走初始生成路径
- 模块定位：account-auth 为**横切基座模块**——审计被所有业务模块调用（R-03），会话鉴权被 Web 终端/WS 复用（R-18），RBAC 是全部页面/接口的权限基线

## 3. 澄清问答记录（一次一个，2026-11-12）

| # | 问题 | 结论 | 落点 |
|---|------|------|------|
| Q1 | 初始化引导方式（材料"首次访问设置密码（或 CLI 生成）"二选一未拍板） | **双入口**：Web 首次访问向导（强制，未初始化前拦截一切路由）+ CLI 子命令（`dougong` set-admin 类，供无浏览器/自动化场景）；两入口互斥生效（先到先得，初始化完成后另一入口拒绝） | ADR-017 |
| Q2 | 只读角色权限边界（kb 假设 A5） | **全可看（含审计日志）+ 禁一切变更 + 禁 Web 终端 + 禁上传下载** | ADR-018，A5 关闭 |
| Q3 | 会话过期策略（kb 假设 A9 之会话部分） | **绝对过期 12h + 空闲超时 2h（滑动续期），两项均可配置**；强制下线=管理员立即吊销 | ADR-019，A9 会话部分关闭 |
| Q4 | 审计日志保留策略 | **保留 90 天，后台每日任务清理过期记录**，清理动作本身记审计；到期前可手动导出 | ADR-020，A9 审计部分关闭 |

## 5. D1 输入摘要（结构化需求）

**模块边界**：
- IN：初始化引导（Web 向导 + CLI）、登录（密码 + 可选 TOTP）、登录锁定、会话管理（过期/空闲/强制下线/CSRF）、RBAC（2 角色）、审计日志（记录 + 查询 + 90 天清理）
- OUT：各业务模块的审计埋点调用约定仅定接口；面板自身 HTTPS/监听配置归 panel-core；终端会话限流归 terminal

**核心实体（初步）**：panel_user（用户名/密码哈希/TOTP secret+开关/角色/状态）、session（token/创建时间/最后活跃/过期/CSRF token/用户）、audit_log（操作者/时间/action/对象/变更内容/结果）、role（admin/readonly 固定枚举，MVP 不做角色管理 CRUD）

**状态机（已确认）**：panel_user 正常⇄锁定（5 次失败锁 15 分钟，期满自动解除）；session 有效→过期（12h/2h 空闲）→强制下线（吊销）

**待 D1 细化（次要，不阻断）**：
- ⚠️A10 密码复杂度策略：默认最小长度 8，无强制字符类（个人自托管场景从宽）
- TOTP 参数按 RFC 6238 标准（30s 窗口 ±1），材料/kb 无异议
- API 面板是"谁初始化谁"的并发仲裁（两管理员同时首次访问）——D1 设计时定（建议：初始化锁单行 INSERT 仲裁）
