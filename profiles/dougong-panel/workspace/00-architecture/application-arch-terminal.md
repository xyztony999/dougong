## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 Web 终端（terminal）业务架构》（business-arch-terminal.md v1.0）的 5 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **核心业务域**：会话生命周期管控——终端会话对象（terminal_session，内存态）的聚合根所在，有明确状态机「活跃 → 断开」（空闲超时/连接硬上限/面板会话失效/用户主动断开四类触发，D0 已确认），承载双阈值时长策略（ADR-023），是终端业务主链的存续环节；与账户基座「会话治理（C-03）」同构（会话对象 + 状态机 + 时长策略），判定为核心；
- **支撑业务域**：终端接入控制（含 R-18 鉴权复用、ADR-018 角色禁用、ADR-023 并发阈值等准入业务规则，被连接建立流程调用——与账户基座「访问控制（S-03）」同判为支撑）、运行身份选择（含 R-18 运行身份规则，只读引用 system_user）、终端交互通道（会话交互的承载能力，被会话编排）、会话断开与资源释放（终结执行与善后，被核心域各断开判定调用）；
- **基础数据域**：本模块无独立基础数据 L3——系统用户清单（system_user）为系统侧发现的外部引用数据，本模块只读消费、不独立维护；
- **平台支撑域**：本模块无零业务语义的纯技术 L3——PTY 进程创建、WebSocket 传输、xterm 渲染协议等为实现细节（承载 R-18 业务规则的交互通道不是纯技术机制），不构成功能模块。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|
| 本文档做什么 | 将业务架构映射为应用域、功能模块、功能子模块的层级结构，标注用户类型、模块间调用关系及应用域分层 |
| 本文档不做什么 | 不涉及具体功能点描述、不涉及系统详细设计、不涉及技术实现和部署方案 |

### 1.3 范围

| 范围 | 说明 |
|------|------|
| 业务域 | Web 终端（terminal） |
| 应用域 | 核心业务域（会话生命周期管控）、支撑业务域（终端接入控制、运行身份选择、终端交互通道、会话断开与资源释放） |
| 用户类型 | 管理员（admin）、只读用户（readonly） |

> 用户类型语义：**管理员（admin）**——Web 终端的唯一使用者，建立/使用/断开终端会话；**只读用户（readonly）**——按 ADR-018「禁 Web 终端」被整体拒绝，无任何本模块功能（越界握手被拒并明确提示边界原因）。未认证操作者（访客）无面板会话，在握手鉴权处即被拒绝，不进入本模块用户类型清单。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层聚为两个应用域：

- **核心业务域**承载终端会话对象的存续治理：会话生命周期管控持有 terminal_session（内存态聚合根），以空闲 30 分钟/硬上限 8 小时双阈值（ADR-023）与面板会话失效联动（R-18）判定断开时机；
- **支撑业务域**为会话主链提供四项支撑：终端接入控制在会话建立前执行鉴权与并发准入（安全第一道闸），运行身份选择确定会话的系统身份（R-18），终端交互通道承载建立后的双向交互，会话断开与资源释放统一执行各断开路径的终结善后。

调用关系总脉络：连接建立流程依次经 S-38 准入（鉴权→并发）与 S-39 身份确定后建立会话；会话运行期 S-40 承载交互并向 C-11 登记活跃；C-11 的各断开判定与用户主动断开（S-41-01）统一收敛到 S-41-02 清理，清理时向 S-38-02 释放并发配额，形成「准入→交互→终结→释放」闭环。跨模块契约（面板会话鉴权复用、会话失效联动、审计接入、系统用户清单引用）与模块边界见附录B。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 L3→DDD 四层归类原则归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | 会话生命周期管控（C-11） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 终端接入控制（S-38）、运行身份选择（S-39）、终端交互通道（S-40）、会话断开与资源释放（S-41） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | —（本模块无；system_user 为系统侧发现的外部引用数据，只读消费不独立维护） |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | —（本模块无；PTY 创建与 WebSocket 传输为实现细节，不构成功能模块） |

### 2.1 核心业务域

**应用域概述**：承载 Web 终端的业务主链存续环节——终端会话对象（terminal_session）的时长治理。服务的用户群体：管理员（admin）的全部终端会话（机制自动执行，操作者无感知）。

#### 2.1.1 会话生命周期管控（C-11）

**功能说明**：终端会话存续期的时长治理：持有 terminal_session（内存态聚合根，不落库），以空闲 30 分钟/硬上限 8 小时双阈值（ADR-023）与面板会话失效联动（R-18）判定并执行断开。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

##### 2.1.1.1 空闲超时断开（C-11-01）

**功能说明**：会话连续 30 分钟无操作者输入即自动断开（ADR-023）；判定口径从严——以无输入为准，服务端持续输出不重置计时（BA 2.2.2.1 落定口径）。系统自动机制，无直接用户交互。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统自动机制，作用于全部存续会话）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 会话断开与资源释放（S-41） | 空闲判定成立后经统一断开清理执行终结 |

##### 2.1.1.2 连接硬上限断开（C-11-02）

**功能说明**：单个终端连接自建立起最长 8 小时，到时强制断开（ADR-023），与是否活跃无关。系统自动机制，无直接用户交互。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统自动机制，作用于全部存续会话）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 会话断开与资源释放（S-41） | 硬上限到时经统一断开清理执行终结 |

##### 2.1.1.3 面板会话失效联动断开（C-11-03）

**功能说明**：面板登录会话过期/登出/被强制下线时，联动断开该操作者的全部终端连接（R-18 反向联动；里程碑 M5 验收口径）。系统自动机制，无直接用户交互。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统自动机制，联动作用对象为面板会话失效的操作者）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 会话断开与资源释放（S-41） | 联动断开经统一断开清理执行终结 |
| account-auth 会话治理（C-03-01/02/03） | 面板会话过期/登出/强制下线事件为联动触发源（R-18） |

### 2.2 支撑业务域

**应用域概述**：为终端会话主链提供准入、身份、交互与善后四项支撑能力。服务的用户群体：管理员（admin）为唯一使用者；只读用户（readonly）在准入处被边界拒绝（ADR-018）。

#### 2.2.1 终端接入控制（S-38）

**功能说明**：终端连接的身份准入与配额准入：WS 握手复用面板会话鉴权与角色判定（R-18），并按操作者粒度执行并发准入（每用户 5，ADR-023）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）

##### 2.2.1.1 WS 握手鉴权与角色判定（S-38-01）

**功能说明**：终端连接握手时复用面板会话鉴权与角色判定（R-18，鉴权载体同 R-02）：无有效面板会话拒绝连接；仅管理员角色可用，只读角色一律拒绝并明确提示边界原因（ADR-018）。被动准入机制，随连接握手自动执行。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（只读角色被边界拒绝连入终端，ADR-018）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| account-auth WS 鉴权复用（S-03-03） | 握手时复用面板会话鉴权与角色判定（R-18） |
| account-auth 审计记录（S-04） | 会话建立作为安全事件写审计（D1 解释性决策，见 FL 附录B） |

##### 2.2.1.2 并发准入控制（S-38-02）

**功能说明**：同一操作者同时存续的终端连接数上限 5（ADR-023）：达到上限拒绝新连接并提示先关闭既有会话；配额随连接断开即时释放（释放回写见 S-41-02）。被动准入机制，随连接建立自动执行。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）（配额判定对象为通过鉴权的管理员）

**调用关系**：

*（无调用，作为被连接建立流程调用的配额判定点；配额释放由 S-41-02 回写）*

#### 2.2.2 运行身份选择（S-39）

**功能说明**：确定终端会话的系统运行身份：默认面板运行用户（通常 root），或管理员指定一个具备登录 shell 的系统用户（R-18；指定范围与切换语义按 D0 建议落定，见 FL 附录B）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

##### 2.2.2.1 默认身份接入（S-39-01）

**功能说明**：不指定身份时，以面板运行用户（通常 root）身份建立与运行终端会话（R-18 默认语义）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

*（无调用，身份随会话建立生效）*

##### 2.2.2.2 指定系统用户接入（S-39-02）

**功能说明**：从系统用户清单选择一个具备登录 shell 的用户（nologin/false 不进入清单），以面板运行用户权限代为启动所选用户的登录 shell（su 语义），不做密码代输；身份在会话建立时一次确定，会话期间不变更。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 系统用户清单（system_user，只读引用） | 读取可指定用户清单（系统侧发现的外部引用数据；取数通道 D3 接口设计定） |

#### 2.2.3 终端交互通道（S-40）

**功能说明**：终端会话建立后的双向交互承载：服务器输出实时回传呈现、操作者键入实时下发执行、窗口尺寸同步；全屏程序（vim/top）正常渲染（里程碑 M5 验收口径）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

##### 2.2.3.1 终端输出呈现（S-40-01）

**功能说明**：将服务器 shell 输出实时回传并在浏览器终端界面呈现，支持全屏程序正常渲染。输出不重置空闲计时（BA 2.2.2.1 从严口径）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

*（无调用，输出回传通道）*

##### 2.2.3.2 终端输入传递（S-40-02）

**功能说明**：将操作者键入（命令、控制键）实时下发到服务器 shell 执行；窗口尺寸变化随输入通道同步。每次输入同时作为会话活跃信号。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 会话生命周期管控（C-11） | 每次输入更新会话最后活跃时间，作为空闲判定（C-11-01）的输入源 |

#### 2.2.4 会话断开与资源释放（S-41）

**功能说明**：终端会话终结的执行与善后：用户主动断开入口，以及覆盖全部断开路径（主动/空闲/硬上限/面板会话失效/网络异常中断）的统一清理——进程回收、内存态会话记录销毁、并发配额释放。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

##### 2.2.4.1 用户主动断开（S-41-01）

**功能说明**：操作者关闭终端标签页或会话时立即断开连接，服务器侧 shell 进程随之终止。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 断连清理与资源释放（S-41-02） | 主动断开与其他断开路径统一收敛到清理善后 |

##### 2.2.4.2 断连清理与资源释放（S-41-02）

**功能说明**：任一断开路径触发后的统一善后：回收服务器侧 shell 进程、销毁内存态会话记录（不落库、断开即无痕）、释放并发配额。系统内部机制，无直接用户交互。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 并发准入控制（S-38-02） | 清理完成时释放该操作者并发配额 |
| account-auth 审计记录（S-04） | 会话断开作为安全事件写审计（D1 解释性决策，见 FL 附录B） |

```
├── 基础数据域
│   └── —（无；system_user 为系统侧发现的外部引用数据，只读消费不独立维护）

    └── —（无；PTY 创建与 WebSocket 传输为实现细节，不构成功能模块）
```
