## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 计划任务与备份（cron-backup）业务架构》（business-arch-cron-backup.md v1.0）的 3 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。cronx / backupx 适配器（crontab 读写、cron 日志读取、备份执行与 rsync 传输的命令封装，含 R-08 参数数组纪律）为技术实现资产（idea.md §5.1 后端适配层），归后端工程，本架构不涉及。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **核心业务域**：备份执行与历史管理（C-13）——backup_run 为已拍板的独立执行记录实体（ADR-016），有明确生命周期状态机（running → success / failure，kb 状态机表在册）、对应聚合根候选、单据驱动（每次执行产生记录 + 产物 + 时间戳目录编号），承载 R-11 保留轮转这一领域硬规则，是备份业务的执行主链（与 terminal C-11 会话生命周期、docker-mgmt C-12 容器生命周期的「有状态机即核心域」先例同判）；
- **支撑业务域**：计划任务管理（S-51）、备份任务管理（S-52）——计划任务管理为 crontab 实况投影的读写治理（cron_job 无生命周期状态机、kb 状态机表无条目，与 firewall 规则投影同判），但含本领域特有业务规则（接管边界口径、来源标注、手动触发超时控制），支撑面板「接管存量」核心价值；备份任务管理为 backup_job 配置单据治理（落 SQLite 但无生命周期状态机——任务定义本身无状态流转，类比 database-mgmt db_instance 治理面全支撑归类），是核心域执行与轮转的输入；
- **基础数据域**：无——本模块不提供系统级引用数据（cron_job 为后端实况投影非面板维护的引用数据，backup_job 为业务单据非字典/分类）；
- **平台支撑域**：无——cronx / backupx 适配器与面板内置调度器的时间触发机制为纯技术通道资产（零业务语义，换一个领域仍可用）；「接管边界、来源标注、保留轮转、触发方式语义」等业务规则均已承载于上述功能模块（与 firewall 对 firewallx、database-mgmt 对 dbmysql/dbredis 的处理口径一致）。

> 领域建模起步提示（供 D2）：backup_run 为核心域聚合根候选（状态机 running → success / failure，ADR-016）；backup_job 为支撑域实体候选（配置单据，落 SQLite）；cron_job 为后端实况投影对象候选（不落库；面板侧备注与来源标注的存储载体待 D2 定）。备份产物目录命名（D0 建议：{job名}/{时间戳}/ + manifest.json）与备份调度周期表达格式（建议复用 cron 表达式与 S-51-04 校验能力）为 D2 细化项，本架构不拍板。

> 模块编码衔接说明（编码规则的跨模块执行口径）：功能模块编码全局唯一，承接 account-auth 已占用的 C-01~C-03、S-01~S-05，panel-core 已占用的 S-06~S-12，monitoring 已占用的 S-13~S-16，service-mgmt 已占用的 C-04~C-05、S-17~S-18，file-manager 已占用的 C-06、S-19~S-25，site-mgmt 已占用的 C-07~C-10、S-26~S-30，database-mgmt 已占用的 S-31~S-37，terminal 已占用的 C-11、S-38~S-41，firewall 已占用的 S-42~S-44，docker-mgmt 已占用的 C-12、S-45~S-50；本模块核心业务域 1 个模块编 C-13，支撑业务域 2 个模块自 S-51 起编至 S-52（依据「新模块在域内最大序号后递增」）。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层归为两个应用域，其下共 3 个功能模块、15 个功能子模块：

- **核心业务域——备份执行线**：备份执行与历史管理（C-13）承载备份执行的触发（定时调度 / 立即执行）、执行记录（backup_run）生命周期与产物治理、按保留份数轮转清理（R-11），是备份业务的单据主链；
- **支撑业务域——计划任务线**：计划任务管理（S-51）承载 root crontab 的接管读写治理（列表/创建编辑/删除/表达式校验/执行日志/手动触发），cronx 通道与 cron 日志读取为技术实现；
- **支撑业务域——备份定义线**：备份任务管理（S-52）承载 backup_job 定义五要素（源/目标/保留份数/调度）的建立与维护，为核心域提供执行输入。

调用关系总脉络：计划任务创建与编辑（S-51-02）提交前调用 cron 表达式校验与执行预览（S-51-04）；备份任务创建（S-52-02）/编辑与删除（S-52-03）联动 site-mgmt 站点清单与 database-mgmt 实例/库清单选取备份源；备份定时调度执行（C-13-01）与备份立即执行（C-13-02）成功后触发备份保留轮转清理（C-13-06）；备份历史列表查看（C-13-03）按任务归组供任务清单视角回显最近执行结论；全部变更类操作与手动触发经 account-auth 审计契约留痕（R-03）；全部接口位于登录会话之后并受只读边界管控（account-auth S-03，全局中间件层面生效，不在本模块内单列调用）。跨模块契约与模块边界见附录B。两条业务线解耦：备份调度由面板内置调度器承载、不写 crontab（BA 落定口径），S-51 与 C-13/S-52 之间无调用关系。

全部 L3 的 L4 组织模式判定（d1 分册 Step 1 自动判定）：均为 **standard 模式**——各 L4 相互独立、可分别操作，无「开始→结束」时序引导流程，L4 一一映射为功能子模块。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | 备份执行与历史管理（C-13） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 计划任务管理（S-51）、备份任务管理（S-52） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | —（本模块无：cron_job 为后端实况投影、backup_job 为业务单据，均非系统级引用数据） |

### 2.1 核心业务域

**应用域概述**：承载备份业务的执行主链「触发 → 记录 → 产物 → 轮转」：定时调度（面板内置调度器）与立即执行（手动）两条触发路径产生 backup_run（running → success / failure，ADR-016），执行历史与详情可查、产物可下载，成功执行后按保留份数轮转清理（R-11）。服务的用户群体：管理员（admin）发起立即执行并下载产物；只读用户（readonly）按 ADR-018 查看备份历史与执行详情，无下载与触发入口。

#### 2.1.1 备份执行与历史管理（C-13）

**功能说明**：备份执行的触发治理（定时调度/立即执行）、backup_run 执行记录全生命周期与产物消费、按任务保留份数的轮转清理（R-11）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）

##### 2.1.1.1 备份定时调度执行（C-13-01）

**功能说明**：面板内置调度器按各任务定义的调度周期自动触发备份执行，产生 backup_run（触发方式=cron）；调度随面板进程运行、独立于系统 cron、不写 crontab（BA 落定口径）。系统内部机制，无独立用户入口。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，执行结论经备份历史与任务清单呈现被两角色消费）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 备份保留轮转清理（C-13-06） | 执行成功后按任务保留份数触发轮转清理（R-11） |

##### 2.1.1.2 备份立即执行（C-13-02）

**功能说明**：管理员对指定任务手动发起一次立即备份（不等下一个调度点），产生 backup_run（触发方式=manual）；手动触发记审计（R-03）。仅管理员可执行（ADR-018 禁变更）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 备份保留轮转清理（C-13-06） | 执行成功后按任务保留份数触发轮转清理（R-11） |
| 审计记录（account-auth S-04） | 立即执行为手动触发类操作，写审计（R-03） |

##### 2.1.1.3 备份历史列表查看（C-13-03）

**功能说明**：按任务（或全任务）分页检索备份执行记录（任务、触发方式、状态、开始时间、耗时、产物大小）；running 记录呈现进行中状态；任务的最近执行结论回显于备份任务清单（S-52-01 宿主呈现）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

*（无调用，为备份任务清单视角提供最近执行结论回显）*

##### 2.1.1.4 备份执行详情查看（C-13-04）

**功能说明**：查看单条 backup_run 完整信息：状态与起止时间、耗时、触发方式、备份源明细、产物路径与大小、失败原因（如失败）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

*（无调用）*

##### 2.1.1.5 备份产物下载（C-13-05）

**功能说明**：将指定成功执行记录的备份产物从目标位置（本地目录 / rsync 远程）取回并下载留存，供面板外恢复使用（自动恢复流程 MVP 不做）。仅管理员可执行（ADR-018 禁上传下载）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

*（无调用）*

##### 2.1.1.6 备份保留轮转清理（C-13-06）

**功能说明**：备份执行成功后按任务保留份数自动轮转：超出保留份数的最旧产物与对应执行记录清理（R-11）；清理结果反映于备份历史。系统内部机制，随成功执行触发，无独立用户入口。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，被 C-13-01/C-13-02 编排触发）

**调用关系**：

*（无调用，清理结果写回备份历史台账）*

### 2.2 支撑业务域

**应用域概述**：承载「接得住（接管既有 crontab）+ 定得下（备份任务定义五要素）」：计划任务线治理 root crontab 读写（接管存量、如实投影、来源标注、手动触发），备份定义线维护 backup_job 配置单据并联动站点与数据库清单选取备份源。服务的用户群体：管理员（admin）执行全部变更类操作；只读用户（readonly）按 ADR-018 查看任务清单与执行日志，无任何变更入口。

#### 2.2.1 计划任务管理（S-51）

**功能说明**：root crontab 的接管读写治理：实况投影列表（含系统预置位只读展示）、创建/编辑/删除、cron 表达式校验与执行预览、执行日志尾部查看、面板代执行的手动触发（超时控制）；cronx 命令通道为技术实现（R-08）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）

##### 2.2.1.1 计划任务列表查看（S-51-01）

**功能说明**：呈现 root crontab 全部任务（表达式、命令、面板侧备注、来源标注——区分面板创建与系统既有）；同屏只读展示 `/etc/cron.d/` 等系统预置位清单（不提供写操作，BA 落定口径）；面板外变更如实呈现（实况投影，不维护面板侧副本）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看；创建/编辑/删除/触发入口仅管理员）

**调用关系**：

*（无调用，crontab 投影读取为技术通道）*

##### 2.2.1.2 计划任务创建与编辑（S-51-02）

**功能说明**：在 root crontab 新建任务或编辑既有任务（表达式、命令、备注），提交前经表达式校验；来源标注为「面板创建」或「系统既有」（编辑既有任务保留其来源）；变更记审计（R-03）。仅管理员可执行（ADR-018）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| cron 表达式校验与执行预览（S-51-04） | 提交前对表达式做合法性校验与执行时间预览 |
| 审计记录（account-auth S-04） | 任务创建/编辑为变更类操作，写审计（R-03） |

##### 2.2.1.3 计划任务删除（S-51-03）

**功能说明**：从 root crontab 删除指定任务（删除前确认）；系统预置位任务不提供删除；变更记审计（R-03）。仅管理员可执行（ADR-018）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 任务删除为变更类操作，写审计（R-03） |

##### 2.2.1.4 cron 表达式校验与执行预览（S-51-04）

**功能说明**：对输入的 cron 表达式做合法性解析并预览未来若干次执行时间；作为创建/编辑提交的前置校验内嵌使用，也可独立试算。系统内部机制型子模块，无独立菜单（内嵌于创建/编辑表单）。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（机制型：经创建/编辑表单内嵌被管理员使用，无独立入口）

**调用关系**：

*（无调用，被 S-51-02 调用提供校验与预览能力）*

##### 2.2.1.5 计划任务执行日志查看（S-51-05）

**功能说明**：查看系统 cron 执行日志的尾部片段（任务触发记录），定位任务是否按期执行；日志来源按发行版适配（journalctl -u cron / /var/log/cron，技术实现细节）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看，日志查看属查看类）

##### 2.2.1.6 计划任务手动触发（S-51-06）

**功能说明**：对面板管理的任务由面板代为立即执行一次（不等下一个调度点），受超时控制约束，执行结果与输出呈现给操作者；手动触发记审计（R-03）。仅管理员可执行（ADR-018）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

|---------------|---------|
| 审计记录（account-auth S-04） | 手动触发写审计（R-03） |

#### 2.2.2 备份任务管理（S-52）

**功能说明**：backup_job 定义五要素（备份源/目标/保留份数/调度）的建立、维护与清单呈现；任务定义是核心域执行与轮转的输入（源/目标决定执行内容，保留份数决定轮转水位，调度决定定时触发周期）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）

##### 2.2.2.1 备份任务列表查看（S-52-01）

**功能说明**：呈现全部备份任务（名称、备份源构成、目标、保留份数、调度周期、最近一次执行结论）；任务清单为执行发起与历史查看的入口；最近执行结论数据由备份历史（C-13-03）回显（宿主呈现）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看；创建/编辑/删除/立即执行入口仅管理员）

**调用关系**：

*（无调用，最近执行结论为 C-13-03 的宿主回显）*

##### 2.2.2.2 备份任务创建（S-52-02）

**功能说明**：建立备份任务：备份源选取站点目录（联动 site-mgmt 站点清单）与数据库实例/库（联动 database-mgmt 实例/库清单，可多选组合）；目标配置为本地目录或 rsync 远程地址（MVP 范围）；设定保留份数与调度周期；变更记审计（R-03）。仅管理员可执行（ADR-018）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 站点信息管理（site-mgmt S-28） | 读取站点清单，作为备份源站点目录项的联动选取来源 |
| 实例发现与纳管（database-mgmt S-31） | 读取数据库实例/库清单，作为备份源数据库项的联动选取来源（执行取数复用其已存凭据） |
| 审计记录（account-auth S-04） | 任务创建为变更类操作，写审计（R-03） |

##### 2.2.2.3 备份任务编辑与删除（S-52-03）

**功能说明**：调整既有任务的源/目标/保留份数/调度，或删除任务（删除前确认；任务删除不连带清理既有产物与历史记录——历史与产物按既有记录留存至自身轮转）；变更记审计（R-03）。仅管理员可执行（ADR-018）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 站点信息管理（site-mgmt S-28） | 编辑时联动站点清单调整备份源 |
| 实例发现与纳管（database-mgmt S-31） | 编辑时联动实例/库清单调整备份源 |
| 审计记录（account-auth S-04） | 任务编辑/删除为变更类操作，写审计（R-03） |

## 第三部分：应用架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：应用域 > 功能模块 > 功能子模块（含功能说明）。

```
斗拱面板 计划任务与备份（cron-backup）

│       ├── 备份产物下载（C-13-05） — 产物取回下载，供面板外恢复（仅管理员）

└── 支撑业务域
    ├── 计划任务管理（S-51）
    │   ├── 计划任务列表查看（S-51-01） — root crontab 实况投影 + 系统预置位只读展示
    │   ├── 计划任务创建与编辑（S-51-02） — 写 root crontab，来源标注，记审计
    │   ├── 计划任务删除（S-51-03） — 确认后删除，系统预置位不可删
    │   ├── cron 表达式校验与执行预览（S-51-04） — 合法性解析 + 未来执行时间预览
    │   ├── 计划任务执行日志查看（S-51-05） — 系统 cron 日志尾部片段
    │   └── 计划任务手动触发（S-51-06） — 面板代执行 + 超时控制，记审计
    └── 备份任务管理（S-52）
        ├── 备份任务列表查看（S-52-01） — 任务清单 + 最近执行结论回显
        ├── 备份任务创建（S-52-02） — 源/目标/保留份数/调度定义，联动站点与数据库清单
        └── 备份任务编辑与删除（S-52-03） — 定义调整；删除不连带清理产物与历史
```

### 附录B：跨模块契约与模块边界

**跨模块契约（本模块对外提供）**：无——本模块不向其他业务模块提供能力；本模块消费的外部契约如下：

| 消费契约 | 提供方 | 用途 |
|---------|--------|------|
| 审计写入接口约定（account-auth S-04-03） | account-auth | 计划任务/备份任务全部变更类操作与手动触发（计划任务手动触发、备份立即执行）写审计（R-03） |
| 站点清单（site-mgmt S-28 站点信息管理） | site-mgmt | 备份源站点目录项的联动选取（任务创建/编辑） |
| 数据库实例/库清单与已存凭据（database-mgmt S-31 实例发现与纳管） | database-mgmt | 备份源数据库项的联动选取；执行取数复用已存凭据（凭据不回显、不出面板） |

**模块边界（OUT，沿 D0 结论与 BA 1.4）**：

| 事项 | 归属 |
|------|------|
| 备份自动还原流程 | MVP 不做（产物手动下载后自行恢复；D0 口径） |
| 云存储备份目标 S3/OSS | 二期 |
| 增量/去重备份 | 二期 |
| 跨服务器 rsync 管理界面 | MVP 仅备份目标地址配置（D0 OUT） |
| cron 服务自身启停治理 | service-mgmt（systemd 服务管理） |
| 备份产物日常浏览/下载通道 | file-manager（文件管理器）；本模块仅提供按执行记录的产物下载 |
| crontab 读写、cron 日志读取、备份执行与 rsync 传输封装（cronx/backupx 适配器，R-08） | 后端工程实现，不构成功能模块 |
| rsync 远程目标连接认证凭据的存储与使用链路 | D2/D3 细化（本架构不拍板载体与加密方案） |
