## 第一部分：文档概述

### 1.1 背景与目标

依据《斗拱面板 数据库管理（database-mgmt）应用架构》（application-arch-database-mgmt.md v1.2），按用户类型分章列出数据库管理可操作的菜单项与功能点描述，作为功能开发、页面设计（D4）与权限配置的依据。功能点遵循的业务规则：R-15 存量自动发现（发现即接管）、R-03 全变更审计、R-08 命令一律参数数组（mysqldump 等落点）、ADR-007 范围边界（MVP 仅 MySQL/MariaDB + Redis）、ADR-018 只读边界，及 D1 落定口径 ⚠️A18（凭据密文不回显）/⚠️A19（探测范围）/⚠️A20（实例移除纳管）；v1.2 增量规则：TCP 优先探测/socket 兜底（Q1）、状态语义可见（F2）、MySQL 表级治理（Q3）、MongoDB 库/集合/文档治理（Q4，ADR-031 修订 D-18）、顶栏面包屑返回导航（F5）、Q6 角色口径（元数据两角色全可看，数据内容与全部写操作 admin 专属）。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|
| 本文档做什么 | 按用户类型分章，列出每个用户可操作的菜单项和功能点描述，作为功能开发和权限配置的依据 |
| 本文档不做什么 | 不涉及技术实现方案、不涉及数据库设计、不涉及接口定义和系统架构 |

## 第二部分：功能清单

> 本章按用户类型分章，每章按应用域→功能模块→功能子模块逐层描述菜单和功能点。

### 本清单概览

数据库管理面向两类操作者（访客不涉及——全部功能位于登录会话之后）：

- **管理员（admin）**：覆盖本域全部功能——实例纳管治理（凭据/清单/移除）、MySQL 库与用户/授权/密码治理、MySQL 表级治理（v1.2）、多引擎观测、备份导出导入、Redis key 浏览、MongoDB 库/集合/文档治理（v1.2）；
- **只读用户（readonly）**：按 D0 口径与 ADR-018「全模块可查看」——可查看纳管实例清单、数据库列表、数据库用户列表、MySQL 状态概览/进程列表、Redis info 状态/慢日志；v1.2 起元数据面扩展至表清单/表结构/集合清单（Q6）；数据内容（key 值/行数据/文档）属数据内容取出，不对只读角色开放（D0 readonly 查看清单未含 key 浏览，Q6 沿先例扩展至行/文档），浏览页数据区呈现「数据内容仅管理员可见」负空间。

全局行为说明（无独立菜单，作用于全部章节）：存量实例探测（S-31-01）随模块进入自动执行、新实例自动进入纳管清单（R-15 发现即接管；v1.2 起 TCP 优先两阶段登记+socket 兜底，rescan 保守清理无凭据冗余 socket 行、已配凭据行保留+标注），重新探测经实例清单菜单由管理员触发；全部变更类操作自动记入审计（R-03，凭据值脱敏）；实例凭据任何界面与接口不回显（⚠️A18）；连接状态/凭据配置状态 Tag 附语义 tooltip+图例（v1.2 F2：绿=可达/橙=不可达，仅连通性不代表凭据正确）；数据库域多级页面顶栏面包屑返回导航（v1.2 F5：数据库→治理·identity→库→表/集合，动态段取 dbStore 档案+路由 params，能力消费 panel-core S-09-01）。

## 2.1 管理员（admin）

**用户类型概述**：数据库管理域全部变更类操作与数据内容浏览（key 值/行数据/文档）的执行者：纳管存量实例、治理库/用户/授权/密码、MySQL 表级治理（v1.2）、观测多引擎实况、执行库级备份导出导入、MongoDB 库/集合/文档治理（v1.2）；所有变更动作自动记入审计（R-03）。

#### 2.1.1 支撑业务域

**应用域概述**：管理员经纳管线接管存量实例，经 MySQL/MariaDB 与 Redis 两条治理线管理实例内对象与访问设置，经数据保护线执行库级备份。

## 2.2 只读用户（readonly）

**用户类型概述**：按 D0 口径与 ADR-018「全模块可查看 + 禁一切变更」：可查看纳管实例清单、数据库列表、数据库用户列表、MySQL 状态概览/进程列表、Redis info 状态/慢日志；v1.2 起元数据面扩展至 MySQL 表清单/表结构与 MongoDB 集合清单（Q6），可经「浏览」入口进入表/集合浏览页；无凭据配置、无任何治理变更、无备份导出导入、无数据内容浏览（key 值/行数据/文档属数据内容取出，D0 readonly 查看清单未含 key 浏览，Q6 沿先例扩展）——浏览页数据区呈现「数据内容仅管理员可见」负空间，操作列整列不渲染；越界操作被拒绝并明确提示边界原因。
