## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 环境管理（env-mgmt）业务架构》（business-arch-env-mgmt.md v1.0）的 3 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。包管理器调用（apt/dnf·yum，R-08 参数数组）与 systemd 通道为技术实现承载，其业务纪律（强确认/审计/幂等，⚠️A2~A6）落在本架构的模块说明中，实现归 D3 与后端工程。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **核心业务域**：环境安装与变更（承载 env_install_task 聚合根候选与四态任务状态机 pending → running → succeeded/failed，是环境供给的单据型主链动作，审计与互斥业务规则齐备）——满足原则一（状态机 + 聚合根候选 + 主链变更动作 + 产生任务记录）；
- **支撑业务域**：环境目录与实况（含目录范围/包名映射/通道探测领域规则，被供给与运行两链消费）、环境服务运维（含目录环境单元限定与结果如实反馈规则，复用 systemd 通道）——两者含运维领域特有业务规则、被主链消费，自身无独立状态机（服务启停状态为 systemd 实况投影非面板状态机）；
- **基础数据域**：本模块无基础数据 L3——环境目录虽为内置静态引用数据，但其 L3 整体含实况探测运行时规则（非纯字典），按整体归类支撑业务域（与 site-mgmt「PHP-FPM pool 实况投影不建基础数据 L3」同判）；
- **平台支撑域**：本模块无零业务语义的纯技术 L3——包管理器执行器与 systemd 通道为实现细节（前者本模块自建适配层，后者复用 service-mgmt 既有 SysdGateway 通道资产），业务规则承载于 S-53/C-14/S-54。

> env_install_task（环境变更任务）为本模块聚合根候选（四态状态机 + 同环境互斥 + 审计单据），持久化口径（任务台账落库）归 D2 领域建模落定；环境目录为编译期常量（非领域对象候选）。

> 模块编码衔接说明（编码规则的跨模块执行口径）：功能模块编码全局唯一，承接既有占用——account-auth C-01~C-03/S-01~S-05、panel-core S-06~S-12、monitoring S-13~S-16、service-mgmt C-04~C-05/S-17~S-18、file-manager C-06/S-19~S-25、site-mgmt C-07~C-10/S-26~S-30、database-mgmt S-31~S-37、terminal C-11/S-38~S-41、firewall S-42~S-44、docker-mgmt C-12/S-45~S-50、cron-backup C-13/S-51~S-52；本模块核心业务域模块编为 C-14，支撑业务域模块自 S-53 起编至 S-54（依据「新模块在域内最大序号后递增」）。

### 1.3 范围

| 范围 | 值 |
|------|-----|
| 业务域 | 环境管理（env-mgmt） |
| 应用域 | 核心业务域（环境安装与变更）、支撑业务域（环境目录与实况、环境服务运维） |
| 用户类型 | 管理员（admin）、只读用户（readonly） |

> 用户类型语义（与既有十一模块应用架构一致）：**管理员（admin）**——全部环境变更类操作（安装/升级/卸载/服务启停自启）与任务观测的执行者；**只读用户（readonly）**——按 ADR-018「全模块可查看」：查看环境目录、实况与任务状态/输出，禁一切变更。**访客（未认证操作者）不涉及**：本模块全部功能位于登录会话之后。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层聚为两个应用域：

- **核心业务域**承载环境供给状态链：环境安装与变更维持 env_install_task 四态任务状态机（pending → running → succeeded/failed，同环境互斥），安装/升级/卸载三动作共用任务通道与审计纪律；
- **支撑业务域**承载「看得见 + 管得住」：环境目录与实况以内置目录叠加实时探测供给环境全景（供给与运行的共同数据底座），环境服务运维提供目录环境的服务直达管控（复用 systemd 通道）。

调用关系总脉络：实况探测结果是安装/卸载/启停按钮态的前置依据；变更任务完成后实况刷新；服务运维作用于已装环境单元；环境未装实况为 docker-mgmt/database-mgmt/site-mgmt 引导态提供软引导数据（无跨模块硬调用，边界见附录B）；全部变更类操作经 account-auth 审计契约留痕（R-03）；全部接口位于登录会话之后并受只读边界管控（ADR-018）。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 L3→DDD 四层归类原则归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | 环境安装与变更（C-14） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 环境目录与实况（S-53）、环境服务运维（S-54） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | —（本模块无；环境目录为编译期常量随 S-53 承载，实况为运行时投影，二者不构成独立基础数据 L3） |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | —（本模块无；包管理器执行器为本模块适配层实现、systemd 通道复用 service-mgmt 既有 SysdGateway 资产，业务规则承载于 S-53/C-14/S-54） |

### 2.1 核心业务域

**应用域概述**：承载环境供给的变更主链与任务状态机：安装/升级/卸载经异步任务执行（互斥、审计、输出如实），任务记录构成环境变更的可追溯台账。服务的用户群体：管理员（admin）执行全部变更；只读用户（readonly）仅可查看任务状态与输出（ADR-018）。

#### 2.1.1 环境安装与变更（C-14）

**功能说明**：环境本体的供给主链：安装与升级（同通道幂等，先刷新索引）、卸载（强确认+风险提示）、异步任务跟踪（四态状态机，输出尾部排障）；安全纪律贯穿（参数数组 R-08、审计 R-03、幂等、最小权限）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（变更动作仅管理员，任务状态与输出两角色可看）

##### 2.1.1.1 环境安装与升级（C-14-01）

**功能说明**：安装目录环境：包管理器通道可用性前置（⚠️A2，不可用如实拒绝）；先刷新包索引再安装（已装环境同动作为升级，幂等，⚠️A4）；需官方仓库源的环境先由面板写入仓库配置（审计）再安装（⚠️A2）；异步任务化执行（⚠️A3），完成后服务状态尊重包脚本默认（⚠️A5）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境实况探测（S-53-02） | 安装前置：未装态/通道可用性依据；已装态升级语义判定 |
| 环境变更任务跟踪（C-14-03） | 安装/升级动作产生异步任务，进度与结果经任务跟踪呈现 |
| 审计记录（account-auth S-04） | 安装/升级为变更类操作，写审计（R-03，含仓库源写入） |

##### 2.1.1.2 环境卸载（C-14-02）

**功能说明**：卸载已装环境：强确认交互呈现关联模块在用风险提示（Docker 容器/MySQL 纳管实例/nginx 站点，知情决策不硬阻断，⚠️A6）；执行包 remove（保留系统配置与数据目录）；异步任务化执行，卸载后环境回未装态。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境实况探测（S-53-02） | 卸载前置：已装态依据与风险提示数据（关联模块在用探测） |
| 环境变更任务跟踪（C-14-03） | 卸载动作产生异步任务 |
| 审计记录（account-auth S-04） | 卸载为高危变更类操作，写审计（R-03，detail 含风险提示呈现记录） |

##### 2.1.1.3 环境变更任务跟踪（C-14-03）

**功能说明**：异步任务的观测与结果确认：任务状态（pending → running → succeeded/failed）、目标环境与动作、命令输出尾部（排障）、失败原因；同环境在途互斥（重复提交如实拒绝，⚠️A3）；任务列表与单任务详情。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 任务终态（成功/失败）结果一并留痕（R-03） |

### 2.2 支撑业务域

**应用域概述**：承载「看得见 + 管得住」：环境目录与实况供给环境全景（内置目录 + 实时探测，供给与运行的共同数据底座，关联模块引导数据源），环境服务运维提供已装环境的服务直达管控。服务的用户群体：管理员（admin）查看与执行；只读用户（readonly）同等查看（ADR-018），无任何变更入口。

#### 2.2.1 环境目录与实况（S-53）

**功能说明**：内置六环境目录（⚠️A1）与运行时实况（已装/版本/服务状态/自启/通道可用性，⚠️A2/A7）的合并呈现；纯读能力，是供给与运行两链的状态依据。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

##### 2.2.1.1 环境目录呈现（S-53-01）

**功能说明**：环境全景列表：显示名、描述、关联模块提示、已装版本、服务状态、通道可用性、在途任务标记；未装环境呈现安装入口（admin），已装呈现升级/卸载/服务运维入口。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（变更入口仅管理员可见，ADR-018 负空间）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境实况探测（S-53-02） | 列表条目的实况字段为探测结果投影 |

##### 2.2.1.2 环境实况探测（S-53-02）

**功能说明**：逐环境探测：已装与版本（包管理器查询，⚠️A7 映射）、服务运行/自启状态（systemd 单元查询）、包管理器通道可用性（apt/dnf·yum 探测择一，⚠️A2）；纯读机制，被目录呈现/安装/卸载/服务运维共同消费。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，结果经 S-53-01 等呈现）

**调用关系**：

*（无调用，作为实况数据源被编排消费）*

#### 2.2.2 环境服务运维（S-54）

**功能说明**：已装环境的服务层管控：启动/停止/重启/自启开关，经 systemd 通道生效（复用 service-mgmt 既有 SysdGateway 通道资产，非模块间调用）；操作对象限定目录环境对应单元（⚠️A7）；细粒度全部单元治理归 service-mgmt。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

##### 2.2.2.1 环境服务启停与自启（S-54-01）

**功能说明**：对已装环境执行服务启动/停止/重启与自启 enable/disable：结果与失败原因如实反馈；操作审计留痕（R-03）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境实况探测（S-53-02） | 启停前置：服务实况状态依据；操作后实况刷新 |
| 审计记录（account-auth S-04） | 服务启停/自启为变更类操作，写审计（R-03） |

### 附录B：跨模块契约、模块边界与 D1 设计口径

**跨模块契约**：

| 契约 | 方向 | 内容 |
|------|------|------|
| 审计写入（account-auth S-04） | 本模块消费 | 全部变更类操作（安装/升级/卸载/服务启停自启/仓库源写入）按 R-03 写入审计；任务终态结果一并留痕 |
| 会话鉴权与只读边界（account-auth S-03） | 本模块消费 | 全部接口位于登录会话之后；只读角色查看目录/实况/任务，全部变更被全局边界管控拒绝（ADR-018） |
| systemd 通道复用（service-mgmt SysdGateway） | 本模块消费（共享适配层资产） | 环境服务启停/自启与实况服务状态查询复用同一 systemd 网关实现（进程内适配器共享，非 HTTP 调用）；全部系统服务清单治理仍归 service-mgmt |
| 环境就绪引导（docker-mgmt / database-mgmt / site-mgmt） | 本模块被消费（软引导） | 关联模块的未装引导态（docker daemon 不可用/无数据库实例/nginx 未检出）可在其 PageSpec 呈现「到环境管理安装」的指引链接；无跨模块 API 硬依赖 |

**模块边界（与既有模块分界，沿 D0 增量澄清与 BA 1.4）**：

| 事项 | 归属 |
|------|------|
| 环境本体（软件包层）：安装/升级/卸载/版本 | env-mgmt（本模块） |
| 已运行数据库实例管理（库/用户/凭据/备份） | database-mgmt（实例层；环境安装后由其纳管） |
| 容器/镜像/卷/网络/Compose 管理 | docker-mgmt（容器层；引擎安装后即打通） |
| 全部 systemd 单元通用治理（清单/详情/启停） | service-mgmt（通用单元层；本模块仅目录环境直达入口） |
| nginx 站点配置与证书治理 | site-mgmt（站点层；nginx 环境安装为其前置补位） |
| 源码编译安装 / 多版本并存切换 / 应用市场 | 不做（OUT，BA 1.4） |
