## 第一部分：文档概述

### 1.1 背景与目标

斗拱面板是面向个人自托管场景的单机运维面板，Web 终端（terminal）是其里程碑模块 M6（idea.md §4.1 M6）：为管理员提供浏览器内的服务器 shell 交互（浏览器 xterm.js ↔ WebSocket ↔ 服务端 PTY），免去 SSH 客户端即可完成日常运维操作。Web 终端是全面板安全暴露面最大的能力——它直接把 shell（默认面板运行用户，通常 root）交给浏览器，因此其业务设计以「复用既有安全基座 + 严格限流」为中心：鉴权复用面板会话（R-18），连接超时与并发限制按 ADR-023 标准档执行。业务输入来源：idea.md §4.1 M6、§5 里程碑 M5 验收口径（浏览器打开终端可交互——vim/top 正常渲染；面板会话过期后终端连接断开）、D0 需求澄清报告（d0-clarification-terminal.md，2026-11-12）及其拍板决策 ADR-023 与既有规则 R-18/R-02/ADR-018。

本业务架构设计目标：

1. 以 L1-L4 层级刻画 Web 终端「接入准入 → 会话运行 → 会话终结」的业务全生命周期；
2. 将已拍板的业务规则（R-18 会话鉴权复用与运行身份、ADR-023 并发 5/空闲 30 分钟/硬上限 8 小时、R-02 同源 Cookie 会话、ADR-018 只读角色禁 Web 终端）落到确定的业务活动节点上；
3. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

> D0 报告遗留的三项「待 D1 细化（次要，不阻断）」口径在本架构落定并按 D0 建议采纳：指定系统用户范围与切换语义（2.1.2.2）、空闲判定口径（2.2.2.1）、多标签前端形态（不入业务架构，归 D4 交互设计，功能清单备注承载）。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

Web 终端遵循「先准入、再交互、终善后」的业务主线，按时间序划分三个业务阶段：

- **接入准入阶段**：发起终端连接时的三重准入判定——操作者身份与角色（复用面板会话鉴权，仅管理员可用）、操作者并发配额（每用户 5）、运行身份（默认面板运行用户或指定系统用户）；三项全部通过方可建立终端会话；
- **会话运行阶段**：终端会话建立后的双向交互（服务器输出回传呈现、操作者键入下发执行），以及会话存续期的时长治理（空闲 30 分钟断开、单连接硬上限 8 小时、面板会话失效联动断开）；
- **会话终结阶段**：会话终结的执行与善后——操作者主动断开，或任一自动断开条件触发后，统一执行连接关闭、服务器侧 shell 进程回收与内存态会话记录销毁。

三阶段为严格时间序依赖：接入准出产出合法会话 → 会话运行承载交互与存续管控 → 会话终结保证任何断开路径都不遗留资源。终端会话全程内存态、不落库，断开即释放（D0 结论）。

### 2.1 接入准入阶段

**业务说明**：终端连接的准入治理阶段。Web 终端直接暴露服务器 shell，准入是全部安全规则的第一道闸：先判定操作者是谁、可不可用终端（鉴权与角色），再判定还能不能再开一条（并发配额），最后确定这条会话以谁的身份运行（运行身份）。三项判定全部通过，终端会话方可建立并进入会话运行阶段。

##### 2.1.1 终端接入控制

**业务说明**：终端连接的身份准入与配额准入：复用面板登录会话完成握手鉴权与角色判定，并按操作者粒度控制同时存续的终端连接数。所属 L2：接入准入阶段。

###### 2.1.1.1 WS 握手鉴权与角色判定

**业务说明**：终端连接握手时复用面板会话鉴权与角色判定（R-18，鉴权载体同 R-02 同源 Cookie 会话）：无有效面板会话的连接请求被拒绝；仅管理员角色可使用 Web 终端，只读角色一律拒绝并明确提示边界原因（ADR-018 禁 Web 终端）；会话中途失效时已建立的终端连接随之断开（联动执行见 2.2.2.3）。所属 L3：终端接入控制。

###### 2.1.1.2 并发准入控制

**业务说明**：同一操作者同时存续的终端连接数上限为 5（ADR-023 标准档）：达到上限后新连接请求被拒绝并提示需先关闭既有会话；连接断开后配额即时释放（释放执行见 2.3.1.2）。所属 L3：终端接入控制。

##### 2.1.2 运行身份选择

**业务说明**：终端会话以哪个系统身份运行的业务选择：默认以面板运行用户（通常 root）身份运行，也可由管理员指定一个系统用户身份接入（R-18）。身份在会话建立时一次确定，会话期间不变更。所属 L2：接入准入阶段。

###### 2.1.2.1 默认身份接入

**业务说明**：不指定身份时，终端会话以面板运行用户（通常 root）的身份建立与运行（R-18 默认语义）。所属 L3：运行身份选择。

###### 2.1.2.2 指定系统用户接入

**业务说明**：管理员从系统用户清单（system_user）中选择一个用户身份建立终端（R-18「可选指定系统用户」）：以面板运行用户权限代为启动所选用户的登录 shell（su 语义），不做密码代输；可指定范围为系统内具备登录 shell 的系统用户（nologin/false 等非交互 shell 用户不进入选择清单）——以上口径按 D0 待细化项 1 的建议落定（D1 解释性决策，汇总见功能清单附录B）。所属 L3：运行身份选择。

### 2.2 会话运行阶段

**业务说明**：终端会话建立后的运行期：一方面承载操作者与服务器 shell 的双向交互——服务器输出实时回传浏览器呈现、操作者键入实时下发执行，全屏程序（vim/top 等）须正常渲染（§5 里程碑 M5 验收口径）；另一方面对会话存续期施以时长治理——空闲超时与连接硬上限双阈值自动断开，叠加面板会话失效的联动断开，保证任何一条终端连接都不会无限期存续。

##### 2.2.1 终端交互通道

**业务说明**：操作者浏览器与服务器 shell 之间的双向交互业务：输出回传呈现与输入下发执行。是 Web 终端业务价值的直接承载。所属 L2：会话运行阶段。

###### 2.2.1.1 终端输出呈现

**业务说明**：将服务器 shell 的输出（命令回显、程序输出）实时回传并在浏览器终端界面呈现，支持全屏程序的正常渲染（vim/top，里程碑 M5 验收口径）。所属 L3：终端交互通道。

###### 2.2.1.2 终端输入传递

**业务说明**：将操作者的键入（命令、控制键）实时下发到服务器 shell 执行；终端窗口尺寸变化随输入通道同步，保证全屏程序按实际尺寸渲染。每次输入同时作为会话活跃的判定输入（供 2.2.2.1 空闲判定消费）。所属 L3：终端交互通道。

##### 2.2.2 会话生命周期管控

**业务说明**：终端会话存续期的时长治理：空闲超时（30 分钟）与单连接硬上限（8 小时）双阈值自动断开（ADR-023），叠加面板会话失效的联动断开（R-18 反向联动）。终端会话全程内存态、不落库（D0 结论）。所属 L2：会话运行阶段。

###### 2.2.2.1 空闲超时断开

**业务说明**：终端会话连续 30 分钟无操作者输入即自动断开（ADR-023）。判定口径从严：以「无操作者输入」为准，服务端持续输出（如日志跟踪）不重置空闲计时——按 D0 待细化项 2「双阈值从严取小」的建议落定（D1 解释性决策，汇总见功能清单附录B）。所属 L3：会话生命周期管控。

###### 2.2.2.2 连接硬上限断开

**业务说明**：单个终端连接自建立起最长 8 小时，到时强制断开（ADR-023），与是否活跃无关；需要继续使用须重新建立终端会话（重新走接入准入）。所属 L3：会话生命周期管控。

###### 2.2.2.3 面板会话失效联动断开

**业务说明**：面板登录会话过期、登出或被强制下线时，该操作者的全部终端连接联动断开（R-18 会话鉴权复用的反向联动；里程碑 M5 验收口径：面板会话过期后终端连接断开）。所属 L3：会话生命周期管控。

### 2.3 会话终结阶段

**业务说明**：终端会话终结的执行与善后阶段。无论主动还是被动断开，终结路径统一收敛到同一套清理动作：关闭连接、回收服务器侧 shell 进程、销毁内存态会话记录、释放并发配额——保证任何断开路径都不遗留进程或配额占用。

##### 2.3.1 会话断开与资源释放

**业务说明**：终端会话终结与资源善后：覆盖用户主动断开与全部被动断开路径（空闲/硬上限/面板会话失效/网络异常中断）的统一清理。所属 L2：会话终结阶段。

###### 2.3.1.1 用户主动断开

**业务说明**：操作者关闭终端会话（关闭终端标签页或会话）时立即断开连接，服务器侧 shell 进程随之终止，并发配额即时释放。所属 L3：会话断开与资源释放。

###### 2.3.1.2 断连清理与资源释放

**业务说明**：任一断开路径（主动/空闲超时/硬上限/面板会话失效/网络异常中断）触发后的统一善后：回收服务器侧 shell 进程、销毁内存态会话记录（不落库、断开即无痕，D0 结论）、释放该操作者的并发配额。所属 L3：会话断开与资源释放。

## 第三部分：业务架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：L1 > L2 > L3 > L4。

```
Web 终端（terminal）
├── 接入准入阶段
│   ├── 终端接入控制
│   │   ├── WS 握手鉴权与角色判定
│   │   └── 并发准入控制
│   └── 运行身份选择
│       ├── 默认身份接入
│       └── 指定系统用户接入
├── 会话运行阶段
│   ├── 终端交互通道
│   │   ├── 终端输出呈现
│   │   └── 终端输入传递
│   └── 会话生命周期管控
│       ├── 空闲超时断开
│       ├── 连接硬上限断开
│       └── 面板会话失效联动断开
└── 会话终结阶段
    └── 会话断开与资源释放
        ├── 用户主动断开
        └── 断连清理与资源释放
```

### 附录A：L3 业务依赖关系

> 描述 L3 关键业务之间的上下游依赖关系，为后续应用架构中模块调用分析提供依据。跨业务域契约（面板会话鉴权复用、会话失效联动、审计接入）不在此表，见应用架构文档附录B。

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 终端会话（terminal_session） | 一次 Web 终端连接自建立至断开的完整实例，含运行用户、建立时间、最后活跃、连接来源、鉴权会话引用 | 内存态不落库，断开即释放（kb 对象表、D0） |
| 面板运行用户 | 面板进程自身的操作系统身份，通常为 root | R-18 默认运行身份 |
| 指定系统用户 | 管理员建立终端时选定的系统身份（system_user），以面板运行用户权限代启其登录 shell | R-18 可选项；不做密码代输 |
| WS 握手鉴权 | 终端连接握手时复用面板会话鉴权与角色判定的准入机制 | R-18 / R-02 同源 Cookie 会话 |
| 并发准入 | 同一操作者同时存续终端连接数的上限控制，标准档 5 | ADR-023 |
| 空闲超时 | 连续无操作者输入的时长阈值，标准档 30 分钟，到时自动断开 | ADR-023；口径见 2.2.2.1 |
| 连接硬上限 | 单个终端连接自建立起的最长存活时间，标准档 8 小时，到时强制断开 | ADR-023 |
| 面板会话失效联动 | 面板登录会话过期/登出/强制下线时，联动断开该操作者全部终端连接 | R-18 反向联动 |
| 断连清理 | 任一断开路径触发后的统一善后（进程回收、会话记录销毁、配额释放） | D0「断连清理与资源释放」 |
