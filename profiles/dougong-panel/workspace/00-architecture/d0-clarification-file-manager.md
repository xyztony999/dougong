# D0 需求澄清报告：file-manager（文件管理器）

> 引擎 design 阶段 D0 产物（2026-11-12，批量澄清）。作为 D1 架构设计的直接输入。
> 需求来源：idea.md §4.1 M3 + §5.4（安全路径层）+ knowledge/business-concepts（file_entry、R-04/R-05/R-17、A6）。

## 1. 业务概念解析

| 维度 | 内容 |
|------|------|
| 业务术语 | 目录导航、面包屑、分块上传、在线编辑（Monaco）、回收站、权限属主（chmod/chown）、压缩解压、安全路径层 |
| 业务流程 | 路径请求 → EvalSymlinks 解析真实路径 → 白名单前缀校验（R-04）→ 执行操作；删除 → 移入回收站（含原路径元数据）→ 可还原/清空；上传 → 临时文件 + rename，大文件分块（R-05） |
| 业务角色 | admin 全操作；readonly 仅浏览/下载受限于 ADR-018（**禁上传下载删除**） |
| 业务规则 | R-04 路径白名单（默认 `/`，可配置排除 `/proc`、`/sys` 等）防目录逃逸；R-05 上传临时文件+rename/分块；R-17 **已拍板：删除进回收站**（2026-11-12 批量 D0 Q1，方向修正原 A6 假设）；R-03 变更操作记审计 |
| 业务数据 | file_entry（路径/大小/权限/属主/内容）、trash_entry（新增：原路径/删除时间/操作者/类型/大小，落 SQLite） |

## 5. D1 输入摘要（结构化需求）

**模块边界**：
- IN：浏览（列表/图标视图）、目录导航与面包屑、上传（多文件/拖拽/分块大文件）、下载、在线编辑（Monaco，语法高亮）、新建/重命名/移动/删除（进回收站）、回收站管理（列表/还原/清空）、权限与属主修改（chmod/chown，含 system_user/system_group 选择）、压缩/解压（tar/tar.gz/zip）
- OUT：磁盘配额管理（非目标）、编辑器版本历史/协同（非目标）、跨文件系统回收站语义细节（D1 设计单一回收站方案，见下）

**核心实体**：file_entry（实时文件系统投影，元数据不落库）、trash_entry（回收站记录，落 SQLite：原路径、删除时间、操作者、类型、大小、trash 内标识）

**状态机**：file_entry 无（文件系统实态）；trash_entry：在站 → 已还原 / 已清空（记录删除）

**待 D1 细化（次要，不阻断）**：
- ⚠️ 回收站位置方案：建议单一 `/（受管根）/.dougong-trash/` 目录 + trash 内唯一标识目录（避免跨挂载点 rename 失败的复杂处理；跨设备移动降级为 copy+delete 并记审计）
- ⚠️ 还原冲突策略（原路径已存在时：自动改名 vs 要求用户选择，建议后者）
- 回收站自动清理策略（建议：默认仅手动清空；可选配置保留天数，二期）
- 大文件分块大小与断点续传口径（建议 5MB 分块，断点续传二期）
