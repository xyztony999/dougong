## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 数据库管理（database-mgmt）业务架构》（business-arch-database-mgmt.md v1.2）的 10 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。dbmysql/dbredis 适配器为材料给定技术资产（idea.md §5.3 后端适配层），连接通道与命令承载（含 mysqldump 参数数组纪律 R-08）为实现细节，归后端工程，本架构不涉及。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **支撑业务域**：全部 10 个 L3 归入此层——实例发现与纳管（含 R-15「发现即接管」领域规则、TCP 优先/socket 兜底探测登记策略（v1.2 Q1）、探测范围与多实例标识口径、凭据只进不出的敏感数据规则）、数据库管理（含名称/字符集建库规则与依托实例存在的对象语义）、数据库用户与授权管理（含用户名+host 标识、库级授权语义、root 密码修改与面板凭据同步规则）、MySQL 实例运维观测（只读实况投影）、Redis 实例观测与设置（info/slowlog 观测口径与密码设置同步规则）、Redis 数据浏览（MVP 严格只读边界）、数据库备份导出与导入（R-08 参数化命令纪律与导出属数据取出的定界）、MongoDB 实例治理与观测（v1.1；v1.2 库清单可管理+删库，ADR-031）、MySQL 表级治理（v1.2：表清单/结构元数据两角色可看、行数据 admin 专属、单列主键行写限制规则）、MongoDB 集合与文档治理（v1.2：隐式建库经显式建集合达成、文档 CRUD 按 _id 定位、数据内容 admin 专属）——十者均含数据库运维领域特有业务规则、支撑面板「接管存量环境」核心价值，但均无生命周期状态机与单据聚合根，故不入核心业务域；
- **核心业务域**：无——本模块对象均无生命周期状态机（D0 拍板：实例连接状态 reachable/unreachable 为探测得出的状态值、非流转语义；kb 状态机表无本模块对象）；库/用户为实例内实况 CRUD、无审批链、不产生业务编号，不构成单据驱动主链，不满足原则一（与 monitoring 全支撑归类同判）；
- **基础数据域**：无——database/db_user 为实例内实况对象（随实例实时增删改、随实例消失），不是面板维护、读远大于写的系统级引用数据，不满足原则三；
- **平台支撑域**：无——dbmysql/dbredis 适配器为纯技术通道资产（零业务语义，换一个领域仍可用），但「怎么发现、怎么授权、怎么备份、凭据怎么保护」均为 DBA 领域业务语义且已承载于上述功能模块；按归类边界关键问题自检（该功能是否含本领域特有业务规则）→ 适配器不含 → 归实现细节，不构成功能模块（与 site-mgmt 对 nginxx/lego 的处理口径一致）。

> 聚合根候选（供 D2 领域建模起步）：db_instance 为 MySQL 侧聚合根候选（database/db_user 为其实例内对象，随实例存在）；redis_instance 为独立聚合根候选。实例档案与凭据的持久化（密文落 SQLite，⚠️A18）为确定需求；库/用户清单的持久化口径（落库缓存 vs 每次实时投影）归 D2 落定。

> 模块编码衔接说明（编码规则的跨模块执行口径）：功能模块编码全局唯一，承接 account-auth 已占用的 C-01~C-03、S-01~S-05，panel-core 已占用的 S-06~S-12，monitoring 已占用的 S-13~S-16，service-mgmt 已占用的 C-04~C-05、S-17~S-18，file-manager 已占用的 C-06、S-19~S-25，site-mgmt 已占用的 C-07~C-10、S-26~S-30；本模块全部功能模块属支撑业务域，自 S-31 起编至 S-37（依据「新模块在域内最大序号后递增」）；v1.1 追加 S-55（MongoDB 实例治理与观测，承接当时全局最大序号）；v1.2 追加 S-56（MySQL 表级治理）、S-57（MongoDB 集合与文档治理），承接当前全局最大序号 S-55 后递增（已核验全仓 application-arch-*.md 无 S-56/S-57 占用）。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层聚为唯一应用域——**支撑业务域**，其下按「纳管 → MySQL 治理 → Redis 治理 → 数据保护 → MongoDB 治理」组织 10 个功能模块：

- **纳管线**：实例发现与纳管（S-31）产出双引擎统一实例档案（含密文凭据），是全部模块的操作前提与数据源头；
- **MySQL/MariaDB 治理线**：数据库管理（S-32）、数据库用户与授权管理（S-33）承载实例内对象治理，MySQL 实例运维观测（S-34）承载只读观测，MySQL 表级治理（S-56，v1.2 追加）承载库内表清单/结构/数据浏览/单列主键行写/删表；
- **Redis 治理线**：Redis 实例观测与设置（S-36）承载观测与实例级访问设置，Redis 数据浏览（S-37）承载 key 只读浏览；
- **数据保护线**：数据库备份导出与导入（S-35）承载库级逻辑备份（mysqldump，R-08）；
- **MongoDB 治理线（v1.1 追加，v1.2 扩展）**：MongoDB 实例治理与观测（S-55）承载 MongoDB 状态概览、库清单（v1.2 起可管理：浏览集合入口+删库，ADR-031 修订 D-18）与用户/角色治理（三档库级角色）；MongoDB 集合与文档治理（S-57，v1.2 追加）承载集合清单/建集合/删集合与文档分页浏览/插入/编辑/删除；通道=进程内官方 mongo-driver Go 库（拍板 Q2=A，纯 Go 无外部二进制依赖）。

调用关系总脉络：纳管实例清单查看（S-31-03）为全部引擎内操作的入口（清单为探测与纳管结果投影）；MySQL/Redis/MongoDB 各侧治理与观测动作均以已纳管实例为对象；表级治理（S-56）经数据库列表（S-32-01）「浏览」入口进入，MongoDB 集合与文档治理（S-57）经 MongoDB 库清单（S-55-02）「浏览集合」入口进入（v1.2）；多级治理/浏览页面的返回导航消费 panel-core 应用骨架与导航（S-09-01）顶栏面包屑能力（v1.2 F5 呈现层变更，跨模块契约见附录B）；root 密码修改（S-33-05）与 Redis 密码设置（S-36-03）成功后经实例凭据配置通道（S-31-02）同步面板侧凭据密文，维持纳管关系；备份导出/导入（S-35）以数据库清单（S-32-01）为对象来源；全部变更类操作经 account-auth 审计契约留痕（R-03，凭据值脱敏）；全部接口位于登录会话之后并受只读边界管控（account-auth S-03，全局中间件层面生效，不在本模块内单列调用）。跨模块契约与模块边界见附录B。

全部 L3 的 L4 组织模式判定（d1 分册 Step 1 自动判定）：均为 **standard 模式**——各 L4 相互独立、无「开始→结束」时序引导流程，L4 一一映射为功能子模块。

### 2.1 支撑业务域

**应用域概述**：承载「接得住 + 管得了 + 护得住」：实例发现与纳管以自动探测接管存量多引擎实例（R-15 核心卖点入口，v1.2 起 TCP 优先/socket 兜底登记），MySQL/MariaDB、Redis 与 MongoDB 三条治理线提供库/用户/授权/密码/表级/集合文档级治理与观测能力，数据保护线提供库级备份导出导入。服务的用户群体：管理员（admin）执行全部治理与备份操作及数据内容浏览；只读用户（readonly）按 ADR-018 与 v1.2 Q6 口径查看实例/库/表/结构/集合/用户/状态类元数据清单与观测视图，无任何变更入口，数据内容（行/文档/key 值）不可见（负空间呈现）。

#### 2.1.1 实例发现与纳管（S-31）

**功能说明**：本机存量 MySQL/MariaDB 与 Redis 实例的自动探测（R-15）、凭据接入与连接验证、纳管实例统一清单、纳管解除；产出双引擎统一实例档案（含密文凭据，⚠️A18），是本模块全部功能的前提。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（探测为系统机制；清单查看两角色开放，凭据配置/移除纳管仅管理员）

##### 2.1.1.1 存量实例探测（S-31-01）

**功能说明**：对本机多引擎实例的自动探测：按默认探测范围（localhost:3306/6379/27017 TCP + socket 常见路径，不做全网段扫描，⚠️A19）发现存活实例并登记进纳管清单，同时得出连接状态（reachable/unreachable 探测态）；系统内部机制，随模块进入自动执行，重新探测动作经实例清单菜单由管理员触发。登记策略（v1.2 拍板 Q1，rule_changed）：两阶段探测——先探本机 TCP 目标记录各引擎本机 TCP 可达性，再探 socket 目标；该引擎本机 TCP 可达时 socket 不登记为独立实例（冗余通道），仅该引擎无任何本机 TCP 可达时 socket 兜底登记（覆盖 skip-networking）；identity_key 语义不变（引擎|连接方式|地址），仅注册策略变。rescan 保守清理：同引擎本机 TCP 现已可达时，仅解除「未配置凭据」的冗余 socket 行纳管（审计同事务 R-03）；「已配置凭据」的 socket 行保留并在清单标注，不做凭据自动迁移。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，被清单查看编排触发）

**调用关系**：

*（无调用，作为纳管管线入口被编排）*

##### 2.1.1.2 实例凭据配置与连接验证（S-31-02）

**功能说明**：为已发现实例配置/更新连接方式（socket/TCP）与访问凭据，保存即验证连通：通过则实例可管理；凭据以密文落库（⚠️A18）、明文仅内存态建连使用，任何接口不回显；同时是 root 密码修改（S-33-05）与 Redis 密码设置（S-36-03）后同步面板侧凭据的存储通道。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 凭据配置/更新为变更类操作，写审计（R-03）；凭据值脱敏不入审计 |

##### 2.1.1.3 纳管实例清单查看（S-31-03）

**功能说明**：多引擎统一实例清单：引擎类型、标识（host:port / socket 路径）、连接方式、版本、连接状态（探测态）；是进入各引擎治理/观测/备份业务的操作入口；管理员可在此触发重新探测（S-31-01）。呈现口径（v1.2，rule_changed）：TCP 优先登记下常见情况天然一行 TCP（socket-only 时一行 socket），无归并展开 UI；清单说明文案明示 TCP 优先/socket 兜底策略；连接状态与凭据配置状态 Tag 附语义 tooltip（绿=可达/橙=不可达，仅连通性不代表凭据正确；凭据=是否已配置、未配置时治理与观测不可用）并补图例说明（F2），治理页摘要条同款 Tag 复用同一语义助手；已配凭据的冗余 socket 行保留并标注（Q1）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看；重新探测仅管理员）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 存量实例探测（S-31-01） | 清单为探测与纳管结果的投影；重新探测动作触发重扫 |

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

|---------------|---------|

#### 2.1.2 数据库管理（S-32）

**功能说明**：已纳管 MySQL/MariaDB 实例内数据库对象的治理：清单查看、创建（名称/字符集）、删除；库对象依托实例存在，不脱离实例独立管理。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（列表查看两角色开放，创建/删除仅管理员）

##### 2.1.2.1 数据库列表查看（S-32-01）

**功能说明**：查看指定实例内数据库清单（名称、字符集）；是建库/删库、授权（S-33-04）与备份导出导入（S-35）的操作前依据；v1.2 起行操作增「浏览」入口（admin+readonly 均可见，进入表级治理 S-56 表清单页；数据内容按 Q6 角色口径）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

*（无调用，只读消费实例内库清单）*

**功能说明**：在指定实例内创建数据库：指定名称与字符集；创建结果即时反映到数据库清单。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）
