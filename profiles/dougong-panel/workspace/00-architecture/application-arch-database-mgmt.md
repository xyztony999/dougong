## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 数据库管理（database-mgmt）业务架构》（business-arch-database-mgmt.md v1.0）的 7 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。dbmysql/dbredis 适配器为材料给定技术资产（idea.md §5.3 后端适配层），连接通道与命令承载（含 mysqldump 参数数组纪律 R-08）为实现细节，归后端工程，本架构不涉及。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **支撑业务域**：全部 7 个 L3 归入此层——实例发现与纳管（含 R-15「发现即接管」领域规则、探测范围与多实例标识口径、凭据只进不出的敏感数据规则）、数据库管理（含名称/字符集建库规则与依托实例存在的对象语义）、数据库用户与授权管理（含用户名+host 标识、库级授权语义、root 密码修改与面板凭据同步规则）、MySQL 实例运维观测（只读实况投影）、Redis 实例观测与设置（info/slowlog 观测口径与密码设置同步规则）、Redis 数据浏览（MVP 严格只读边界）、数据库备份导出与导入（R-08 参数化命令纪律与导出属数据取出的定界）——七者均含数据库运维领域特有业务规则、支撑面板「接管存量环境」核心价值，但均无生命周期状态机与单据聚合根，故不入核心业务域；
- **核心业务域**：无——本模块对象均无生命周期状态机（D0 拍板：实例连接状态 reachable/unreachable 为探测得出的状态值、非流转语义；kb 状态机表无本模块对象）；库/用户为实例内实况 CRUD、无审批链、不产生业务编号，不构成单据驱动主链，不满足原则一（与 monitoring 全支撑归类同判）；
- **基础数据域**：无——database/db_user 为实例内实况对象（随实例实时增删改、随实例消失），不是面板维护、读远大于写的系统级引用数据，不满足原则三；
- **平台支撑域**：无——dbmysql/dbredis 适配器为纯技术通道资产（零业务语义，换一个领域仍可用），但「怎么发现、怎么授权、怎么备份、凭据怎么保护」均为 DBA 领域业务语义且已承载于上述功能模块；按归类边界关键问题自检（该功能是否含本领域特有业务规则）→ 适配器不含 → 归实现细节，不构成功能模块（与 site-mgmt 对 nginxx/lego 的处理口径一致）。

> 聚合根候选（供 D2 领域建模起步）：db_instance 为 MySQL 侧聚合根候选（database/db_user 为其实例内对象，随实例存在）；redis_instance 为独立聚合根候选。实例档案与凭据的持久化（密文落 SQLite，⚠️A18）为确定需求；库/用户清单的持久化口径（落库缓存 vs 每次实时投影）归 D2 落定。

> 模块编码衔接说明（编码规则的跨模块执行口径）：功能模块编码全局唯一，承接 account-auth 已占用的 C-01~C-03、S-01~S-05，panel-core 已占用的 S-06~S-12，monitoring 已占用的 S-13~S-16，service-mgmt 已占用的 C-04~C-05、S-17~S-18，file-manager 已占用的 C-06、S-19~S-25，site-mgmt 已占用的 C-07~C-10、S-26~S-30；本模块全部功能模块属支撑业务域，自 S-31 起编至 S-37（依据「新模块在域内最大序号后递增」）。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层聚为唯一应用域——**支撑业务域**，其下按「纳管 → MySQL 治理 → Redis 治理 → 数据保护」组织 7 个功能模块：

- **纳管线**：实例发现与纳管（S-31）产出双引擎统一实例档案（含密文凭据），是全部模块的操作前提与数据源头；
- **MySQL/MariaDB 治理线**：数据库管理（S-32）、数据库用户与授权管理（S-33）承载实例内对象治理，MySQL 实例运维观测（S-34）承载只读观测；
- **Redis 治理线**：Redis 实例观测与设置（S-36）承载观测与实例级访问设置，Redis 数据浏览（S-37）承载 key 只读浏览；
- **数据保护线**：数据库备份导出与导入（S-35）承载库级逻辑备份（mysqldump，R-08）。

调用关系总脉络：纳管实例清单查看（S-31-03）为全部引擎内操作的入口（清单为探测与纳管结果投影）；MySQL/Redis 两侧治理与观测动作均以已纳管实例为对象；root 密码修改（S-33-05）与 Redis 密码设置（S-36-03）成功后经实例凭据配置通道（S-31-02）同步面板侧凭据密文，维持纳管关系；备份导出/导入（S-35）以数据库清单（S-32-01）为对象来源；全部变更类操作经 account-auth 审计契约留痕（R-03，凭据值脱敏）；全部接口位于登录会话之后并受只读边界管控（account-auth S-03，全局中间件层面生效，不在本模块内单列调用）。跨模块契约与模块边界见附录B。

全部 L3 的 L4 组织模式判定（d1 分册 Step 1 自动判定）：均为 **standard 模式**——各 L4 相互独立、无「开始→结束」时序引导流程，L4 一一映射为功能子模块。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 L3→DDD 四层归类原则归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | —（本模块无：无生命周期状态机与单据主链，D0 拍板 reachable/unreachable 为探测态非流转语义；归类推导见 1.1） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 实例发现与纳管（S-31）、数据库管理（S-32）、数据库用户与授权管理（S-33）、MySQL 实例运维观测（S-34）、数据库备份导出与导入（S-35）、Redis 实例观测与设置（S-36）、Redis 数据浏览（S-37） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | —（本模块无：database/db_user 为实例内实况对象，非面板维护的系统级引用数据） |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | —（本模块无：dbmysql/dbredis 适配器为技术实现资产，业务规则承载于各功能模块） |

### 2.1 支撑业务域

**应用域概述**：承载「接得住 + 管得了 + 护得住」：实例发现与纳管以自动探测接管存量双引擎实例（R-15 核心卖点入口），MySQL/MariaDB 与 Redis 两条治理线提供库/用户/授权/密码与观测能力，数据保护线提供库级备份导出导入。服务的用户群体：管理员（admin）执行全部治理与备份操作；只读用户（readonly）按 ADR-018 同等查看实例/库/用户/状态类清单与观测视图，无任何变更与 key 浏览入口。

#### 2.1.1 实例发现与纳管（S-31）

**功能说明**：本机存量 MySQL/MariaDB 与 Redis 实例的自动探测（R-15）、凭据接入与连接验证、纳管实例统一清单、纳管解除；产出双引擎统一实例档案（含密文凭据，⚠️A18），是本模块全部功能的前提。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（探测为系统机制；清单查看两角色开放，凭据配置/移除纳管仅管理员）

##### 2.1.1.1 存量实例探测（S-31-01）

**功能说明**：对本机双引擎实例的自动探测：按默认探测范围（socket 常见路径 + localhost:3306/6379，不做全网段扫描，⚠️A19）发现存活实例并登记进纳管清单，同时得出连接状态（reachable/unreachable 探测态）；系统内部机制，随模块进入自动执行，重新探测动作经实例清单菜单由管理员触发。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，被清单查看编排触发）

**调用关系**：

*（无调用，作为纳管管线入口被编排）*

##### 2.1.1.2 实例凭据配置与连接验证（S-31-02）

**功能说明**：为已发现实例配置/更新连接方式（socket/TCP）与访问凭据，保存即验证连通：通过则实例可管理；凭据以密文落库（⚠️A18）、明文仅内存态建连使用，任何接口不回显；同时是 root 密码修改（S-33-05）与 Redis 密码设置（S-36-03）后同步面板侧凭据的存储通道。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 凭据配置/更新为变更类操作，写审计（R-03）；凭据值脱敏不入审计 |

##### 2.1.1.3 纳管实例清单查看（S-31-03）

**功能说明**：双引擎统一实例清单：引擎类型、标识（host:port / socket 路径）、连接方式、版本、连接状态（探测态）；是进入各引擎治理/观测/备份业务的操作入口；管理员可在此触发重新探测（S-31-01）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看；重新探测仅管理员）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 存量实例探测（S-31-01） | 清单为探测与纳管结果的投影；重新探测动作触发重扫 |

##### 2.1.1.4 实例移除纳管（S-31-04）

**功能说明**：解除实例的面板纳管关系（⚠️A20）：仅移除面板侧管理关系与已存凭据密文，不卸载实例、不停止实例进程、不删除数据；移除后可经重新探测再次纳管。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 移除纳管为变更类操作，写审计（R-03） |

#### 2.1.2 数据库管理（S-32）

**功能说明**：实例内数据库用户与权限治理：用户清单查看、用户创建/删除、库级授权管理、root 密码修改；用户由用户名 + host 标识，密码类信息只写不读；root 密码修改后面板侧凭据同步更新。

**功能说明**：查看指定实例内数据库用户清单（用户名、host、授权概况）；凭据字段任何角色不回显（解释性决策：密码只写不读）。

#### 2.1.4 MySQL 实例运维观测（S-34）

**功能说明**：已纳管 MySQL/MariaDB 实例的只读运维观测：状态概览（version/variables 摘要）与进程列表（processlist）；观测不改变实例状态。

**D1 设计口径落定（承接 D0「待 D1 细化」清单）**：

| 编号 | 口径 | 说明 |
|------|------|------|
| ⚠️A18 | 实例凭据密文存储：凭据（用户名/密码）为 db_instance/redis_instance 内嵌敏感字段，密文落 SQLite，明文仅内存态建连使用，任何接口不回显、审计脱敏 | 密钥来源（与首次初始化的绑定关系）与加密算法选型归 D2/D3 安全设计细化（D0 待细化项的业务口径落定） |
| ⚠️A19 | 实例探测范围：默认探测 socket 常见路径（/tmp/mysql.sock、/var/run/mysqld/ 等）+ localhost:3306（MySQL/MariaDB）/ localhost:6379（Redis）TCP 端口，不做全网段扫描 | D0 建议口径采纳 |
| ⚠️A20 | 实例移除纳管纳入范围：仅解除面板管理关系与已存凭据，不卸载实例、不停止进程、不删除数据；移除后可重新探测再纳管 | 材料未列，按纳管生命周期终局补全（与 R-15 接管语义对偶）；如裁剪需同步三文档 |
| 设计口径 | 实例唯一标识 = 引擎类型 + host:port（socket 接入以 socket 路径参与标识），多实例同机按标识消重展示 | D0 待细化项采纳 |
| 设计口径 | db_instance 为 MySQL 侧聚合根候选（database/db_user 为实例内对象）、redis_instance 为独立聚合根候选；实例档案与密文凭据确定落 SQLite，库/用户清单持久化口径（落库缓存 vs 实时投影）归 D2 | 供 D2 领域建模起步 |
| 解释 | 只读角色可看 MySQL 进程列表与数据库用户列表 | D0 readonly 枚举未列；按 ADR-018 全可看口径，与已放行的慢日志同敏感级；凭据字段任何角色不回显 |
| 解释 | root 密码修改与 Redis 密码设置成功后面板侧凭据密文同步更新 | 维持既有纳管关系不失效，避免改密后实例失管 |
| 解释 | 备份导出仅管理员 | 导出属数据取出（与 account-auth 审计导出同判），且 ADR-018 禁只读角色上传下载 |
| 解释 | 授权与状态概览的呈现口径（权限集合粒度、info/variables 摘要条目）不在 D1 落定 | 归 D2 PRD 与 D3 API 细化，本架构仅锁定业务边界 |
