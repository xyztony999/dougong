## 第一部分：文档概述

### 1.1 背景与目标

将《斗拱面板 网站管理（site-mgmt）业务架构》（business-arch-site-mgmt.md v1.0）的 9 个 L3 关键业务按 DDD 四层归类为应用域，组织为功能模块/功能子模块，标注涉及用户类型与模块间调用关系，作为 PRD（D2）、API 设计（D3）与交互设计（D4）的功能组织依据。nginxx 配置解析器（ADR-010 自研核心资产）与 lego ACME 客户端为材料给定事实（R-06/R-07 技术规约承载），其实现归 D2/D3 与后端工程，本架构不涉及。

DDD 归类结论（依据 d1 分册归类原则逐条判定）：

- **核心业务域**：站点运行操作（站点 enabled ⇄ disabled 状态机 kb 拍板，site 为本模块聚合根候选——含 Raw 内容保全语义与来源文件映射，启停/重载为站点管控主链核心动作）、证书签发与部署、证书续期治理、证书纳管与清理（三者共同承载 certificate 聚合根的完整生命周期，证书 6 状态机 ADR-024 拍板，续期调度与失败排障为 ADR-024 明示设计目标）——前者满足原则一（状态机 + 聚合根 + 主链动作），后三者满足原则一（单据型证书对象 + 明确生命周期状态机 + 状态流转支撑续期调度）；
- **支撑业务域**：nginx 配置存量导入（含 R-15 存量自动发现与「站点→来源文件」映射领域规则，被全部模块消费）、新建站点（含三模板与 PHP-FPM pool 对接业务规则，被主链消费）、站点信息管理（含 R-07 Raw 保留写回与编辑口径领域规则，是本模块验收主场景的承载点）、配置源码编辑（含保存前自动 nginx -t 业务规则）、安全写入治理（含 R-06 四步流程与 R-16 隔离写回业务规则，被全部写回动作强制前置）——五者均含网站运维领域特有业务规则、被主链调用或构成主链操作集合，但自身无独立状态机；
- **基础数据域**：本模块无基础数据 L3——PHP-FPM pool 清单为 php-fpm 实况的实时投影（读系统实况，非面板维护引用数据），仅作新建站点模板选择数据源；反代上游（upstream）为 site 内嵌结构非独立对象（D1 落定，见附录B）；
- **平台支撑域**：本模块无零业务语义的纯技术 L3——nginxx 解析器/生成器为 ADR-010 自研技术资产、ACME 客户端（lego）为选型实现、`nginx -t` 调用与 reload 通道为实现细节，其业务规则（R-06/R-07/R-16）承载在安全写入治理（S-30）与站点信息管理（S-28）中，与 account-auth 对密码哈希的处理口径一致，不构成功能模块。

> site 为本模块聚合根候选（enabled 状态机 kb 拍板、Raw 块内容保全、来源文件映射），其持久化口径（落库 vs 每次操作实时重解析投影）归 D2 领域建模落定；D0 建议维护「站点→来源文件」映射（⚠️A13），映射数据的持久化需求随 D2 一并确认。

> 模块编码衔接说明（编码规则的跨模块执行口径）：功能模块编码全局唯一，承接 account-auth 已占用的 C-01~C-03、S-01~S-05，panel-core 已占用的 S-06~S-12，monitoring 已占用的 S-13~S-16，service-mgmt 已占用的 C-04~C-05、S-17~S-18，file-manager 已占用的 C-06、S-19~S-25；本模块核心业务域模块自 C-07 起编至 C-10，支撑业务域模块自 S-26 起编至 S-30（依据「新模块在域内最大序号后递增」）。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

应用架构按 DDD 四层聚为两个应用域：

- **核心业务域**承载两条管控状态链：站点运行操作维持站点 enabled ⇄ disabled 运行维度状态（经安全写入流程变更后 reload 生效）；证书三模块（签发与部署、续期治理、纳管与清理）共同维持 certificate 六状态机全生命周期（ADR-024：pending → valid → expiring_soon → expired / renew_failed，重试成功回 valid）；
- **支撑业务域**承载「接得住 + 改得动 + 改不坏」：nginx 配置存量导入以自动管线产出站点对象与来源映射；新建站点以三模板扩充站点集合；站点信息管理与配置源码编辑提供双模式编辑；安全写入治理为全部写回动作的强制安全前置（R-06/R-16）。

调用关系总脉络：导入管线产出是站点信息管理的数据源；双模式编辑与新建站点、站点启停、证书部署的全部写回统一经安全写入治理（R-06 强制前置），校验通过后经 nginx 重载通道生效；证书续期复用签发通道并经部署落位；站点列表的证书状态列消费证书清单数据；全部变更类操作经 account-auth 审计契约留痕（R-03）；全部接口位于登录会话之后并受只读边界管控（account-auth S-03，全局中间件层面生效，不在本模块内单列调用）。跨模块契约与模块边界见附录B。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 L3→DDD 四层归类原则归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | 站点运行操作（C-07）、证书签发与部署（C-08）、证书续期治理（C-09）、证书纳管与清理（C-10） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | nginx 配置存量导入（S-26）、新建站点（S-27）、站点信息管理（S-28）、配置源码编辑（S-29）、安全写入治理（S-30） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | —（本模块无；PHP-FPM pool 清单为 php-fpm 实况实时投影仅作 S-27-02 数据源；upstream 为 site 内嵌结构非独立对象） |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | —（本模块无；nginxx 解析器为 ADR-010 自研技术资产、lego ACME 客户端与 nginx -t/reload 通道为实现细节，业务规则承载于 S-28/S-30） |

### 2.1 核心业务域

**应用域概述**：承载站点与证书两条管控状态链：站点运行操作维持站点运行维度状态（启停/重载/日志观测），证书三模块维持证书全生命周期（申请 → 部署 → 续期 → 终局）。服务的用户群体：管理员（admin）执行全部操作；只读用户（readonly）按 ADR-018 可查看日志尾部与证书清单，无任何操作入口。

#### 2.1.1 站点运行操作（C-07）

**功能说明**：站点运行维度的管控与观测：站点启停（enabled ⇄ disabled 状态流转，经安全写入流程生效）、访问/错误日志尾部查看、nginx 重载；启停保留站点配置与证书引用（停用≠删除）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（启停/重载仅管理员，日志尾部查看两角色开放）

##### 2.1.1.1 站点启停（C-07-01）

**功能说明**：通过 enabled 开关切换站点启用 ⇄ 停用（kb 状态机）：开关动作经安全写入流程（S-30）修改来源文件，校验通过后经 nginx 重载（C-07-03）生效；启停结果反映到站点列表 enabled 列。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 安全写入治理（S-30） | enabled 配置段修改经 R-06 流程写回来源文件 |
| nginx 重载（C-07-03） | 校验通过后 reload 使启停生效 |
| 审计记录（account-auth S-04） | 启停为变更类操作，写审计（R-03） |

##### 2.1.1.2 访问与错误日志尾部查看（C-07-02）

**功能说明**：查看站点访问日志与错误日志尾部：日志路径经解析 server 块 access_log/error_log 指令获得，无该指令时回退 nginx 默认路径（⚠️A15）；只读消费，无状态变更。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 站点详情查看（S-28-02） | 日志查看以站点对象及其来源文件解析结果为输入 |

##### 2.1.1.3 nginx 重载（C-07-03）

**功能说明**：用户主动触发的 nginx 平滑 reload 动作：使已通过校验写入的配置变更生效；与安全写入流程的生效环节共用同一 reload 通道；重载结果（成功/失败原因）如实反馈。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 审计记录（account-auth S-04） | 重载为变更类操作，写审计（R-03） |

#### 2.1.2 证书签发与部署（C-08）

**功能说明**：为站点获取并启用 TLS 证书：ACME 两种挑战方式（HTTP-01 / TLS-ALPN）申请、面板托管、部署到站点配置引用（⚠️A16）；ACME 申请是面板唯一的外部网络请求（R-09 除外条款）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

##### 2.1.2.1 ACME 证书申请 HTTP-01（C-08-01）

**功能说明**：以 HTTP-01 挑战申请站点域名证书：需域名可经 80 端口 HTTP 访问完成挑战；发出后证书入 pending，签发成功转 valid，失败呈现失败原因（ADR-024 状态机）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 证书部署（C-08-03） | 签发成功后经部署落位到目标站点 |
| 审计记录（account-auth S-04） | 证书申请为变更类操作，写审计（R-03） |

##### 2.1.2.2 ACME 证书申请 TLS-ALPN（C-08-02）

**功能说明**：以 TLS-ALPN 挑战申请证书：经 443 端口 TLS 握手内完成挑战验证，适用于仅 HTTPS 暴露的站点；状态流转同 HTTP-01（ADR-024 状态机）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 证书部署（C-08-03） | 签发成功后经部署落位到目标站点 |
| 审计记录（account-auth S-04） | 证书申请为变更类操作，写审计（R-03） |

##### 2.1.2.3 证书部署（C-08-03）

**功能说明**：将面板托管的有效证书部署到目标站点：修改站点配置的证书引用（经安全写入流程写回并 reload 生效），建立「证书 ⇄ 站点」引用关系；部署是续期替换与删除约束的依据。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 安全写入治理（S-30） | 证书引用修改经 R-06 流程写回站点来源文件 |
| nginx 重载（C-07-03） | 部署完成后 reload 使证书生效 |
| 审计记录（account-auth S-04） | 部署为变更类操作，写审计（R-03） |

#### 2.1.3 证书续期治理（C-09）

**功能说明**：证书有效期治理：到期前 30 天（expiring_soon）触发自动续期，成功回 valid 并替换托管证书、重新部署；失败转 renew_failed 支持手动重试（ADR-024）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）（自动续期为后台机制；失败排障与手动重试仅管理员）

##### 2.1.3.1 自动续期调度（C-09-01）

**功能说明**：后台自动续期任务机制：对 expiring_soon 证书按原挑战方式自动发起续期，成功后替换托管证书内容（原路径替换，⚠️A16）、经部署落位并回 valid，到期仍未成功转 expired；系统内部机制，无用户入口。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，被续期调度编排）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| ACME 证书申请 HTTP-01（C-08-01）/ ACME 证书申请 TLS-ALPN（C-08-02） | 续期复用原申请的 ACME 挑战通道 |
| 证书部署（C-08-03） | 续期成功后重新部署替换后的证书 |
| 审计记录（account-auth S-04） | 自动续期结果（成功/失败）写审计（R-03） |

##### 2.1.3.2 续期失败处理与手动重试（C-09-02）

**功能说明**：续期失败转 renew_failed 后的排障与恢复：呈现失败原因，支持手动重试（成功回 valid，到期仍未成功转 expired，ADR-024）；保证站点 TLS 不因续期失败静默中断。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 自动续期调度（C-09-01） | 手动重试进入同一续期调度通道 |
| 审计记录（account-auth S-04） | 手动重试为变更类操作，写审计（R-03） |

#### 2.1.4 证书纳管与清理（C-10）

**功能说明**：证书集合的纳管与终局治理：存量证书随站点导入自动识别纳管（来源 imported）、证书清单全集观测、证书删除（生命周期终局出口）。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（删除仅管理员，清单查看两角色开放）

##### 2.1.4.1 存量证书识别导入（C-10-01）

**功能说明**：存量导入管线自动识别站点配置 ssl_cert 证书引用并将已有证书纳入管理（来源 imported，保留源站原路径引用不迁移，⚠️A16）；系统内部机制，随站点导入自动发生，被 nginx 配置存量导入（S-26）编排。

**涉及用户类型**：- [ ] 管理员（admin） - [ ] 只读用户（readonly）（系统内部机制，被 S-26 编排）

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| server 块站点提取（S-26-03） | 以站点提取结果中的 ssl_cert 引用为输入 |

##### 2.1.4.2 证书清单查看（C-10-02）

**功能说明**：查看全部纳管证书：域名列表、签发者（issuer）、有效期、来源（acme/imported）、当前状态（ADR-024 状态机）；是证书排障（含 renew_failed 定位）与站点列表证书状态列的数据源。

**涉及用户类型**：- [✓] 管理员（admin） - [✓] 只读用户（readonly）（ADR-018 全可看）

**调用关系**：

##### 2.1.4.3 证书删除（C-10-03）

**功能说明**：删除面板托管的证书及其续期任务：仍有站点引用时提示先解除部署引用（解释性决策：防误删致站点 TLS 失效）；存量导入证书的删除仅解除面板管理关系，不删除源站原证书文件（⚠️A16 托管口径的终局语义）。

**涉及用户类型**：- [✓] 管理员（admin） - [ ] 只读用户（readonly）

### 2.2 支撑业务域

### 附录B：跨模块契约、模块边界与 D1 设计口径

**跨模块契约**：

| 契约 | 方向 | 内容 |
|------|------|------|
| 审计写入（account-auth S-04） | 本模块消费 | 全部变更类操作（新建/编辑/源码保存/启停/重载/证书申请/部署/续期重试/删除）按 R-03 写入审计；自动续期结果一并留痕 |
| 会话鉴权与只读边界（account-auth S-03） | 本模块消费 | 全部接口位于登录会话之后；只读角色查看站点列表/详情/证书清单/日志尾部，全部变更被全局边界管控拒绝（D0 口径 + ADR-018） |
| nginxx 解析器（ADR-010 自研资产） | 本模块消费 | 本模块为 nginxx 的唯一业务消费模块；round-trip 保真（R-07）与样本集 ≥ 20 验收由该资产承载，实现归后端工程 |
| ACME 外部请求例外（R-09） | 本模块消费 | 证书申请/续期是面板唯一允许的外部网络请求（R-09 除外条款），由用户主动触发或既有证书续期调度发起 |

**D1 设计口径落定（承接 D0「待 D1 细化」清单）**：

| 编号 | 口径 | 说明 |
|------|------|------|
| ⚠️A13 | 「站点 → 来源文件」映射消重、写回原文件 | conf.d 与 sites-enabled 并存场景的扫描去重与写回落点（D0 建议口径采纳） |
| ⚠️A14 | 发现已有 PHP-FPM pool 列出供选择，FastCGI 参数模板内置 | 不新装 PHP，接管已有环境（D0 建议口径采纳） |
| ⚠️A15 | 日志路径 = server 块 access_log/error_log 指令解析 + 默认路径回退 | D0 建议口径采纳 |
| ⚠️A16 | ACME 证书面板托管（签发 → 托管 → 部署引用 → 续期原路径替换）；存量证书保留源站原路径 | 具体存储路径常量归 D2/D3（建议值 /etc/dougong/certs/）；D0「D1 定」事项按业务口径落定 |
| ⚠️A17 | Monaco 源码编辑对象限定站点配置文件，不开放全局主配置编辑 | 沿「站点对象」语义推导；如需开放需同步三文档 |
| 设计口径 | upstream 作为 site 内嵌结构，不独立对象 | D0 留 D1 定事项；D2 领域建模按 site 聚合内嵌值对象处理 |
| 设计口径 | site 聚合根候选，持久化口径归 D2 | enabled 状态机 kb 拍板；「站点→来源文件」映射的持久化需求随 D2 确认 |
| 解释 | ADR-024 文本称「证书 6 状态机」而枚举命名 5 个状态（pending/valid/expiring_soon/expired/renew_failed） | 本架构按枚举命名与流转执行；「第 6 状态」语义待 ADR-024 侧澄清，如为申请中（processing）等中间态需修订 ADR-024 并同步三文档与枚举池 |
| 解释 | 站点配置文件亦可经文件管理器（file-manager S-22）作为普通文件编辑 | 两模块通道各自独立；该通用通道不受 R-06 管控的跨模块安全协同不在本模块范围内（如需约束在对应模块或 Gate 处置） |
| 解释 | 证书删除的引用提示 | 仍有站点引用时提示先解除部署引用（防误删致站点 TLS 失效）；存量证书删除仅解除管理关系不删源站文件 |
