## 第一部分：文档概述

### 1.1 背景与目标

斗拱面板是面向个人自托管场景的单机运维面板，核心卖点是「可接管存量环境」。数据库管理（database-mgmt）是里程碑 M4 的交付模块（idea.md §6 M4，对应功能清单 §4.1 M5）：对系统上已装的 MySQL/MariaDB 与 Redis 实例「发现即接管、不要求重装」（规则 R-15），提供库/用户/授权治理、实例观测与库级备份保护能力。业务输入来源：idea.md §4.1 M5、D0 需求澄清报告（d0-clarification-database-mgmt.md，2026-11-12）及其沿用的决策 ADR-007（MVP 仅 MySQL/MariaDB + Redis，PostgreSQL 二期）与 ADR-018（只读边界）；v1.2 增量输入：d0-clarification-database-mgmt-ux-2026-11-18.md（2026-11-18 用户实机反馈 5 项，拍板 Q1~Q6）与 ADR-031（D-18 修订：MongoDB 治理边界由只读投影改为库/集合/文档可管理）。

本业务架构设计目标：

1. 以 L1-L4 层级刻画数据库管理「纳管 → 治理 → 保护」的业务主线：先发现并纳管存量实例（共用阶段），再按引擎分线治理（MySQL/MariaDB 线与 Redis 线并行），最后对 MySQL/MariaDB 数据施以备份保护；
2. 将已拍板的业务规则（R-15 存量自动发现、R-03 全变更审计、R-08 命令一律参数数组、ADR-007 范围边界、ADR-018 只读边界）落到确定的业务活动节点上；
3. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

> ⚠️假设A20（本设计新增）：材料与 D0 均未显式列出「实例移除纳管」，但纳管关系作为面板侧管理态必须有终局出口（误纳管/退役场景），否则管理集合只增不减。本架构按「解除管理关系、不卸载实例、不删除数据」语义将其纳入业务范围（与 R-15「接管不重装」语义对偶），如后续裁剪需同步 BA/AA/FL 三文档。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

数据库管理遵循「接得住 → 管得了 → 护得住」的业务主线，划分四个业务阶段：

- **实例纳管阶段**（MySQL/MariaDB、Redis 与 MongoDB 共用）：探测本机存量实例（localhost 默认端口 TCP 优先、socket 常见路径兜底，不做全网段扫描；v1.2 拍板 Q1），管理员配置连接凭据并验证连通后纳入管理；提供纳管实例清单（含连接状态与凭据配置状态的语义化呈现，v1.2 F2）与移除纳管出口。纳管是全部后续业务的前提；
- **MySQL/MariaDB 治理阶段**：对已纳管 MySQL/MariaDB 实例的库（建/删/清单）、用户（建/删/清单）、授权与 root 密码治理，实例级运维观测（状态概览、进程列表），以及表级治理（表清单/结构/数据浏览/单列主键行写/删表，v1.2 新增）；
- **Redis 治理阶段**：对已纳管 Redis 实例的观测（info 状态概览、慢日志）与访问密码设置，以及 key 只读浏览；
- **数据保护阶段**：对 MySQL/MariaDB 实例内数据库的手动备份导出（mysqldump）与导入；
- **MongoDB 治理阶段**（v1.1 追加）：对已纳管 MongoDB 实例的状态概览、库清单与用户/角色治理，以及库/集合/文档治理（删库/建集合/删集合/文档 CRUD，v1.2 新增，ADR-031 修订 D-18 只读口径）。

阶段间关系：阶段 2、阶段 3 与阶段 5 为多引擎并行治理线，均以阶段 1 为前提；阶段 4 以阶段 1（已纳管实例）为前提、以阶段 2 的库对象为操作对象；表级治理以阶段 2 的库对象为入口与操作范围，MongoDB 集合/文档治理以阶段 5 的库清单为入口。全部变更类操作留痕审计（R-03）。角色口径（v1.2 拍板 Q6，沿 redis key 先例）：元数据（库/表/结构/集合/用户清单）两角色全可看；数据内容（MySQL 行数据/Mongo 文档/Redis key 值）与全部写操作管理员专属。

### 2.1 实例纳管阶段

**业务说明**：数据库管理业务的起点。按 R-15「存量自动发现」对本机已装 MySQL/MariaDB、Redis 与 MongoDB 实例自动探测（发现即接管，不要求重装）；探测仅覆盖本机 localhost 默认端口（TCP 优先）与 socket 常见路径（兜底），不做全网段扫描（v1.2 拍板 Q1：同一引擎本机 TCP 可达时 socket 视为同一服务的冗余通道不独立纳管，仅该引擎无任何本机 TCP 可达时 socket 兜底纳管，覆盖 skip-networking 场景）；被发现的实例经管理员配置连接凭据并验证连通后正式纳管。凭据为敏感数据，业务上只进不出（任何查看界面不回显）。

##### 2.1.1 实例发现与纳管

**业务说明**：存量实例的探测、凭据接入、清单呈现与纳管解除。多实例同机场景以「引擎类型 + host:port」标识区分（socket 接入以 socket 路径参与标识）。所属 L2：实例纳管阶段。

###### 2.1.1.1 存量实例探测

**业务说明**：对本机 MySQL/MariaDB、Redis 与 MongoDB 实例的自动探测：探测 localhost 默认端口（3306/6379/27017）与 socket 常见路径上存活的实例，得出实例清单与连接状态（reachable/unreachable——探测得出的状态值，非流转状态机）；发现新实例即登记进入纳管清单（R-15 发现即接管）。登记策略（v1.2 拍板 Q1，rule_changed）：TCP 优先、socket 兜底——先探本机 TCP 目标并记录各引擎本机 TCP 可达性，再探 socket 目标；该引擎本机 TCP 可达时 socket 即使可达也不登记为独立实例（视为同一服务的冗余通道），仅该引擎无任何本机 TCP 可达时 socket 兜底登记（覆盖 skip-networking）。重新探测（rescan）对存量冗余 socket 行保守清理：同引擎本机 TCP 现已可达时，仅解除「未配置凭据」的冗余 socket 行纳管（留痕审计）；「已配置凭据」的 socket 行保留并在清单标注，引导改配 TCP 行后手动移除，不做凭据自动迁移。实例唯一标识语义不变（引擎类型 + 连接方式 + 地址）。所属 L3：实例发现与纳管。

###### 2.1.1.2 实例凭据配置与连接验证

**业务说明**：管理员为已发现实例配置/更新连接方式（socket/TCP）与访问凭据，保存即尝试验证连通：验证通过则实例可管理；凭据为实例内嵌敏感信息，以受保护形态留存（具体保护方案归应用设计与安全设计），任何界面与查询均不回显凭据值。所属 L3：实例发现与纳管。

###### 2.1.1.3 纳管实例清单查看

**业务说明**：呈现全部已纳管实例的统一清单：引擎类型（MySQL/MariaDB/Redis/MongoDB）、标识（host:port 或 socket）、连接方式、版本与连接状态；是进入各引擎治理与观测业务的操作入口，管理员可自此触发重新探测。呈现口径（v1.2，rule_changed）：TCP 优先登记策略下常见情况清单天然一行 TCP（仅 socket-only 实例一行 socket），清单说明文案明示「面板优先经 TCP 纳管；仅当实例关闭 TCP（skip-networking）时经本机 Socket 兜底发现」；连接状态与凭据配置状态以语义化标注呈现并附解释（连接状态：绿=可达/橙=不可达，仅反映连通性、不代表凭据正确；凭据状态：是否已配置登录凭据，未配置时治理与观测不可用），消除状态标记歧义（F2）；已配凭据的冗余 socket 行保留并标注（Q1 保守清理口径）。所属 L3：实例发现与纳管。

###### 2.1.1.4 实例移除纳管

**业务说明**：解除实例的面板纳管关系（⚠️A20）：仅移除面板侧管理关系与已存凭据，不卸载实例、不停止实例进程、不删除任何数据；移除后实例可经重新探测再次纳管。所属 L3：实例发现与纳管。

### 2.2 MySQL/MariaDB 治理阶段

**业务说明**：对已纳管 MySQL/MariaDB 实例的数据治理与运维观测：库对象的创建/删除/清单（含字符集口径）、数据库用户的创建/删除/清单、用户授权与 root 密码治理，实例级状态概览与进程列表观测，以及表级治理（表清单/结构/数据浏览/单列主键行写/删表，v1.2 新增）。全部变更类活动留痕审计（R-03）。

##### 2.2.1 数据库管理

**业务说明**：实例内数据库（database）对象的全生命周期管理：清单查看、创建（名称与字符集）、删除；库对象依托实例存在，不脱离实例独立管理。所属 L2：MySQL/MariaDB 治理阶段。

###### 2.2.1.1 数据库列表查看

**业务说明**：查看指定实例内的数据库清单（名称、字符集）；是建库/删库/授权/备份导出等业务的操作前依据。所属 L3：数据库管理。

###### 2.2.1.2 数据库创建

**业务说明**：在指定实例内创建数据库：指定名称与字符集；创建结果即时反映到数据库清单。所属 L3：数据库管理。

###### 2.2.1.3 数据库删除

**业务说明**：删除指定实例内的数据库：不可逆操作，删除即连同库内数据移除；删除结果即时反映到数据库清单。所属 L3：数据库管理。

##### 2.2.2 数据库用户与授权管理

**业务说明**：实例内数据库用户（db_user）与权限的治理：用户清单查看、用户创建与删除、库级授权管理、root 密码修改。用户由用户名与 host 共同标识；修改 root 密码后面板侧留存的实例凭据同步更新，保证既有纳管关系不失效。所属 L2：MySQL/MariaDB 治理阶段。

###### 2.2.2.1 数据库用户列表查看

**业务说明**：查看指定实例内的数据库用户清单（用户名、host、授权概况）；密码类信息只写不读，任何界面不回显。所属 L3：数据库用户与授权管理。

###### 2.2.2.2 数据库用户创建

**业务说明**：在指定实例内创建数据库用户：指定用户名、host 与密码；创建结果即时反映到用户清单。所属 L3：数据库用户与授权管理。

###### 2.2.2.3 数据库用户删除

**业务说明**：删除指定实例内的数据库用户：删除前其既有授权一并回收；删除结果即时反映到用户清单。所属 L3：数据库用户与授权管理。

###### 2.2.2.4 用户授权管理

**业务说明**：对数据库用户执行库级授权与回收：指定用户与目标库建立/解除授权关系；授权关系是用户清单授权概况的呈现来源。所属 L3：数据库用户与授权管理。

###### 2.2.2.5 root 密码修改

**业务说明**：修改实例 root（管理账户）密码：修改成功后面板侧留存的该实例凭据同步更新，纳管关系与后续操作不失效；新密码值不回显、审计留痕不含密码内容。所属 L3：数据库用户与授权管理。

##### 2.2.3 MySQL 实例运维观测

**业务说明**：已纳管 MySQL/MariaDB 实例的只读运维观测：状态概览（版本与关键变量摘要）与进程列表（连接与执行中语句）。观测不改变任何实例状态。所属 L2：MySQL/MariaDB 治理阶段。

###### 2.2.3.1 MySQL 状态概览

**业务说明**：查看实例状态概览：version/variables 关键摘要（口径由后续设计细化），为实例健康判断提供只读依据。所属 L3：MySQL 实例运维观测。

###### 2.2.3.2 MySQL 进程列表查看

**业务说明**：查看实例进程列表（processlist）：连接来源、状态与执行中语句的实时快照；只读观测。所属 L3：MySQL 实例运维观测。

##### 2.2.4 MySQL 表级治理（v1.2 追加）

**业务说明**：实例内数据库之下的表（table）对象治理（v1.2 用户反馈 F3，拍板 Q3）：经数据库清单「浏览」入口进入表清单，查看表元数据与结构、分页浏览表数据，对单列主键表执行行级编辑/删除，以及删除表。表对象依托库存在，不脱离库独立管理。角色口径（Q6）：表清单与结构属元数据，两角色全可看；行数据属数据内容，管理员专属；全部写操作管理员专属。本轮不做插入行/建表/多列主键行写（边界见 1.4）。所属 L2：MySQL/MariaDB 治理阶段。

###### 2.2.4.1 表清单查看

**业务说明**：查看指定实例指定库内的表清单：表名、存储引擎、行数（估算）、数据大小、排序规则、注释；是表结构查看、数据浏览与删表的操作前依据；两角色可看（元数据）。所属 L3：MySQL 表级治理。

###### 2.2.4.2 表结构查看

**业务说明**：查看指定表的列结构：列名、类型、可空、键、默认值、额外、注释；是数据浏览列头呈现与行编辑表单的依据；两角色可看（元数据）。所属 L3：MySQL 表级治理。

###### 2.2.4.3 表数据浏览

**业务说明**：分页浏览指定表的行数据（默认每页 20、上限 100）：列头来自表结构，空值（NULL）显式标注，长文本截断呈现；行数据属数据内容，管理员专属（Q6，沿 redis key 值先例）；只读浏览，不提供任意 SQL 执行入口。所属 L3：MySQL 表级治理。

###### 2.2.4.4 表行编辑

**业务说明**：修改指定表内单行数据：仅对「单列主键」表开放（以主键旧值定位行，参数化执行）；无单列主键的表禁用行编辑并如实提示原因；按列呈现编辑输入，空值以 NULL 语义提交；管理员专属变更，留痕审计（R-03）。本轮不做插入行。所属 L3：MySQL 表级治理。

###### 2.2.4.5 表行删除

**业务说明**：删除指定表内单行数据：仅对「单列主键」表开放（以主键旧值定位行，参数化执行）；无单列主键的表禁用行删除并如实提示原因；管理员专属变更，留痕审计（R-03）。所属 L3：MySQL 表级治理。

###### 2.2.4.6 表删除

**业务说明**：删除指定库内的表（DROP TABLE）：不可逆操作，连同表内数据与结构移除，执行前强确认；删除结果即时反映到表清单；管理员专属变更，留痕审计（R-03）。本轮不做建表。所属 L3：MySQL 表级治理。

### 2.3 Redis 治理阶段

**业务说明**：对已纳管 Redis 实例的观测、访问密码治理与 key 只读浏览：info 状态概览与慢日志为只读观测；密码设置为实例级变更（变更后面板侧凭据同步）；key 浏览严格只读（含 TTL 查看，MVP 不做数据编辑）。全部变更类活动留痕审计（R-03）。

##### 2.3.1 Redis 实例观测与设置

**业务说明**：Redis 实例的只读观测（info 状态概览、慢日志）与实例级访问设置（密码设置）。所属 L2：Redis 治理阶段。

###### 2.3.1.1 Redis info 状态概览

**业务说明**：查看实例 info 实况的关键状态摘要（口径由后续设计细化）；只读观测。所属 L3：Redis 实例观测与设置。

###### 2.3.1.2 Redis 慢日志查看

**业务说明**：查看实例慢日志（slowlog）清单：慢命令与耗时等要素的只读呈现。所属 L3：Redis 实例观测与设置。

###### 2.3.1.3 Redis 密码设置

**业务说明**：设置/修改实例访问密码：修改成功后面板侧留存的该实例凭据同步更新，纳管关系不失效；密码值不回显、审计留痕不含密码内容。所属 L3：Redis 实例观测与设置。

##### 2.3.2 Redis 数据浏览

**业务说明**：Redis 实例内 key 的只读浏览能力（MVP 边界：只读 + TTL 查看，不做数据编辑/删除/发布订阅）。所属 L2：Redis 治理阶段。

###### 2.3.2.1 key 只读浏览

**业务说明**：浏览实例内 key 清单（名称、类型）并查看 TTL；严格只读，不提供任何编辑、删除或数据变更入口。所属 L3：Redis 数据浏览。

### 2.4 数据保护阶段

**业务说明**：MySQL/MariaDB 数据的库级手动备份保护：备份导出（mysqldump）与备份导入。导出/导入为管理员专属能力（导出属数据取出、导入属数据变更）；定时备份任务与保留轮转归计划任务与备份模块（cron-backup，M8），不在本阶段内。全部活动留痕审计（R-03）。

##### 2.4.1 数据库备份导出与导入

**业务说明**：实例内数据库的逻辑备份导出与恢复导入；导出与导入一律以受控命令形态执行（参数化命令，杜绝 shell 拼接，R-08 在本域的落点）。所属 L2：数据保护阶段。

###### 2.4.1.1 备份导出

**业务说明**：选定实例与数据库，经 mysqldump 逻辑导出为 SQL 备份文件供留存（执行一律参数化命令，R-08）；导出结果与产物去向如实反馈。所属 L3：数据库备份导出与导入。

###### 2.4.1.2 备份导入

**业务说明**：以既有 SQL 备份文件向指定实例/数据库执行恢复导入（执行一律参数化命令，R-08）；导入为数据变更操作，导入结果如实反馈。所属 L3：数据库备份导出与导入。

### 2.5 MongoDB 治理阶段（v1.1 追加）

**业务说明**：MongoDB 实例的纳管治理、观测与库/集合/文档治理（v0.1.4 用户反馈第 3 项，2026-11-17 拍板 Q1=A 对齐 MySQL/Redis 面；v1.2 用户反馈 F4 拍板 Q4 修订治理边界，ADR-031）：实例发现随 R-15 探测哲学扩容（mongod systemd 单元对应的默认 socket /tmp/mongodb-27017.sock + localhost:27017 TCP 探测，TCP 优先/socket 兜底登记策略同 2.1.1.1，探测集 D3 定）；凭据连接验证（SCRAM，admin 库）；库清单（名称/大小/集合数）与库治理（删除库 dropDatabase；建库为隐式语义——库随首集合写入产生，经显式建集合达成，不提供独立建库动作）；用户治理（db.createUser/db.dropUser + 三档库级角色 read/readWrite/dbAdmin 的授予与回收）；状态概览（serverStatus 白名单摘要）；集合治理（清单/显式建集合/删集合）与文档治理（分页浏览/插入/编辑/删除，v1.2 新增）。角色口径（Q6）：库/集合清单与用户清单属元数据两角色可看，文档内容属数据内容管理员专属，全部写操作管理员专属。变更类操作留痕审计（R-03）。通道为进程内官方 mongo-driver Go 库（2026-11-17 拍板 Q2=A——纯 Go 无外部二进制依赖，凭据结构化传递无 URI 转义面；区别于 dbmysql/dbredis 的 CLI 通道，R-08 参数数组纪律不适用、R-09 零外呼维持——仅连本机）。

##### 2.5.1 MongoDB 实例治理与观测（S-55）

**业务说明**：MongoDB 实例的状态概览、库清单与库治理（删库）、用户/角色治理四组业务活动；所属 L2：MongoDB 治理阶段。v1.2 修订（ADR-031）：库清单由只读投影改为可管理清单（「浏览集合」入口 + 「删除库」操作）；集合/文档级治理纳入本轮（见 2.5.2），mongodump 备份导出导入仍二期 OUT（附录 B 同步）。

###### 2.5.1.1 MongoDB 状态概览

**业务说明**：serverStatus 实况关键状态摘要（版本/运行时长/连接数/内存与操作计数白名单，呈现口径 D3 定）；只读观测，两角色可用（ADR-018）。所属 L3：MongoDB 实例治理与观测。

###### 2.5.1.2 MongoDB 库清单查看

**业务说明**：实例内数据库清单（名称/大小/集合数，ListDatabases 实况）；v1.2 修订（ADR-031，rule_changed）：由只读投影改为可管理清单——提供「浏览集合」入口（进入集合清单，两角色可见）与「删除库」操作（见 2.5.1.4，管理员专属）；不提供独立建库动作（MongoDB 隐式建库语义——库随首集合写入产生，经显式建集合达成，UI 如实说明）；清单两角色可看（元数据）。所属 L3：MongoDB 实例治理与观测。

###### 2.5.1.3 MongoDB 用户与角色治理

**业务说明**：实例内用户清单（admin 库 users 实况投影）与用户全生命周期治理：创建（用户名/密码/首库首角色）、删除、三档库级角色（mongo_role：read/readWrite/dbAdmin，D2 入池）授予与回收（grantRolesToUser/revokeRolesFromUser）；密码只写不读；管理员专属变更，清单两角色可看。所属 L3：MongoDB 实例治理与观测。

###### 2.5.1.4 MongoDB 数据库删除（v1.2 追加）

**业务说明**：删除实例内指定数据库（dropDatabase）：不可逆操作，连同库内全部集合与文档移除，执行前强确认；删除结果即时反映到库清单；管理员专属变更，留痕审计（R-03）。v1.2 拍板 Q4 纳入（ADR-031 修订 D-18「不提供删库」口径）。所属 L3：MongoDB 实例治理与观测。

##### 2.5.2 MongoDB 集合与文档治理（v1.2 追加）

**业务说明**：实例内数据库之下的集合（collection）与文档（document）治理（v1.2 用户反馈 F4，拍板 Q4，ADR-031）：经库清单「浏览集合」入口进入集合清单，查看集合元数据、显式新建集合、删除集合，分页浏览文档并执行文档插入/编辑/删除。集合依托库存在；MongoDB 库随首集合写入产生（隐式建库语义经显式建集合达成）。角色口径（Q6）：集合清单属元数据两角色可看；文档内容属数据内容管理员专属；全部写操作管理员专属。本轮不做聚合管道/索引管理/分片管理（边界见 1.4）。所属 L2：MongoDB 治理阶段。

###### 2.5.2.1 集合清单查看

**业务说明**：查看指定实例指定库内的集合清单：集合名、文档数、大小；是文档浏览与删集合的操作前依据；两角色可看（元数据）。所属 L3：MongoDB 集合与文档治理。

###### 2.5.2.2 集合创建

**业务说明**：在指定库内显式新建集合（createCollection）：指定集合名；库随首集合写入产生（隐式建库语义，UI 如实说明）；创建结果即时反映到集合清单；管理员专属变更，留痕审计（R-03）。所属 L3：MongoDB 集合与文档治理。

###### 2.5.2.3 集合删除

**业务说明**：删除指定库内的集合（dropCollection）：不可逆操作，连同集合内全部文档移除，执行前强确认；删除结果即时反映到集合清单；管理员专属变更，留痕审计（R-03）。所属 L3：MongoDB 集合与文档治理。

###### 2.5.2.4 文档浏览

**业务说明**：分页浏览指定集合内的文档（默认每页 20、上限 100）：文档以 JSON 呈现（_id 置顶）；文档内容属数据内容，管理员专属（Q6，沿 redis key 值先例）；只读浏览。所属 L3：MongoDB 集合与文档治理。

###### 2.5.2.5 文档插入

**业务说明**：向指定集合插入新文档（InsertOne）：以 JSON 编辑形态提交，JSON 非法时拒绝执行并如实提示；管理员专属变更，留痕审计（R-03）。所属 L3：MongoDB 集合与文档治理。

###### 2.5.2.6 文档编辑

**业务说明**：替换指定集合内单个文档（ReplaceOne，按 _id 定位）：以 JSON 编辑形态提交，JSON 非法时拒绝执行并如实提示；管理员专属变更，留痕审计（R-03）。所属 L3：MongoDB 集合与文档治理。

###### 2.5.2.7 文档删除

**业务说明**：删除指定集合内单个文档（DeleteOne，按 _id 定位）：执行前强确认；管理员专属变更，留痕审计（R-03）。所属 L3：MongoDB 集合与文档治理。

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 数据库实例（db_instance） | 发现并接管的 MySQL/MariaDB 实例 | 连接方式（socket/TCP）、版本、连接状态；kb 对象表已登记 |
| Redis 实例（redis_instance） | 发现并接管的 Redis 实例 | 连接方式、info 状态、慢日志、密码；kb 对象表已登记 |
| 数据库（database） | MySQL/MariaDB 实例内的库对象 | 名称、字符集；依托实例存在 |
| 数据库用户（db_user） | MySQL/MariaDB 实例内的用户对象 | 用户名 + host 标识，含授权关系；密码只写不读 |
| 纳管 | 面板对存量实例建立管理关系（发现即接管，不要求重装） | R-15；解除纳管不卸载不删数据（⚠️A20） |
| 实例凭据 | 面板连接实例所用的访问凭据 | 敏感数据：受保护留存、不回显、不入审计明文 |
| 连接方式 | 实例接入通道：socket 或 TCP | 多实例同机以「引擎类型 + host:port」标识（socket 路径参与标识） |
| 连接状态（reachable/unreachable） | 探测得出的实例连通状态 | 探测态，非流转状态机（D0 拍板）；清单语义化呈现：绿=可达/橙=不可达，仅反映连通性、不代表凭据正确（v1.2 F2） |
| TCP 优先探测 / socket 兜底 | 本机实例探测登记策略：同引擎本机 TCP 可达时 socket 不独立登记，仅无本机 TCP 可达时 socket 兜底登记 | v1.2 拍板 Q1；覆盖 skip-networking；identity_key 语义不变 |
| 数据表（table） | MySQL/MariaDB 库内的表对象 | 表名/引擎/行数(估)/大小/排序规则/注释；依托库存在（v1.2 追加） |
| 表结构 | 表的列定义（列名/类型/可空/键/默认/额外/注释） | 元数据，两角色可看（v1.2 追加） |
| 单列主键行写 | 仅对单列主键表开放的行编辑/行删除（主键旧值定位行） | 无单列主键禁用并如实提示；本轮不做插入行/多列主键行写（v1.2 追加） |
| 数据内容 | 行数据/文档/key 值等实例内存储的业务数据本身 | 管理员专属（Q6 沿 redis key 先例）；区别于元数据（清单/结构）两角色可看（v1.2 追加） |
| MongoDB 集合（collection） | MongoDB 库内的集合对象 | 集合名/文档数/大小；显式 createCollection 创建，库随首集合写入产生（v1.2 追加） |
| MongoDB 文档（document） | MongoDB 集合内的 JSON 文档 | 以 _id 标识；浏览/插入/替换/删除均管理员专属（v1.2 追加） |
| 授权 | 对 db_user 建立或解除库级权限关系 | 权限集合口径归后续设计 |
| 备份导出 | 经 mysqldump 将数据库逻辑导出为 SQL 文件 | 执行一律参数化命令（R-08） |
| 备份导入 | 以 SQL 备份文件向实例/数据库恢复数据 | 数据变更操作 |
| 状态概览 | MySQL version/variables 摘要或 Redis info 摘要 | 只读观测，口径归后续设计 |
| 慢日志 | Redis slowlog 慢命令记录 | 只读查看 |
| key 只读浏览 | 浏览 Redis key 清单与 TTL | MVP 严格只读，不做数据编辑 |
| MongoDB 状态概览 | serverStatus 实况关键状态摘要 | 只读观测，白名单口径 D3 定（v1.1 追加） |
| MongoDB 库清单 | 实例内数据库清单（名称/大小/集合数） | v1.1 只读投影 → v1.2 可管理清单（浏览集合入口+删除库，ADR-031 修订 D-18）；隐式建库语义经显式建集合达成，无独立建库动作 |
| MongoDB 用户与角色治理 | db.createUser/dropUser + 三档库级角色授予回收 | mongo_role：read/readWrite/dbAdmin（v1.1 追加） |
