## 第一部分：文档概述

### 1.1 背景与目标

网站管理（site-mgmt）是斗拱面板的核心卖点模块（idea.md §4.1 M4，里程碑 M3，材料明示工作量最大）：以「接管存量环境」为差异化主线（idea.md §3）——扫描存量 nginx 配置解析为结构化站点对象，面板内可视化与源码双模式编辑后经固定安全流程写回（R-06 快照备份 → 修改 → `nginx -t` 校验 → 失败自动回滚；R-07 未识别指令以 Raw 节点原文本写回；R-16 编辑写回不得影响其余站点），并提供新建站点三模板（静态 / PHP-FPM / 反向代理）、SSL 证书全生命周期治理（ACME HTTP-01/TLS-ALPN 申请、部署、自动续期、存量识别导入；证书状态机经 A2 澄清拍板为 ADR-024）、站点级启停/日志尾部/重载等运维能力。nginxx 配置解析器为 ADR-010 确认的自研核心资产，round-trip 样本集 ≥ 20 为验收硬项（idea.md §6 M3）。业务输入来源：idea.md §4.1 M4 + §3/§5.4（round-trip/安全写入）+ knowledge/business-concepts（site/certificate 对象、R-06/R-07/R-15/R-16、A2）、D0 需求澄清报告（d0-clarification-site-mgmt.md，2026-11-12）及其沉淀的 ADR-024。

本业务架构设计目标：

1. 以 L1-L4 层级刻画网站管理「存量接管 → 站点建设 → 配置治理 → 运行运维 → 证书治理」的业务全生命周期；
2. 将已拍板的业务规则（R-06 安全写入四步、R-07 Raw 保留写回、R-15 存量自动发现、R-16 站点隔离写回、ADR-024 证书状态机）落到确定的业务活动节点上；
3. 落定 D0 遗留的待细化事项（多配置目录写回落点、PHP-FPM pool 对接、日志路径发现、证书存储布局）为可追溯的业务口径（⚠️A13~A16）；
4. 为应用架构（AA）与功能清单（FL）提供唯一业务依据。

> ⚠️假设（本设计新增，承接 D0「待 D1 细化」清单与站点对象语义推导，如裁剪需同步三文档）：
>
> - ⚠️A13 多配置目录归并口径：conf.d 与 sites-enabled 等多配置目录并存时，以「站点 → 来源文件」映射消重，编辑写回原文件（D0 建议口径采纳）；
> - ⚠️A14 PHP-FPM pool 对接口径：新建 PHP-FPM 站点时发现本机已有 pool 并列出供选择，FastCGI 参数模板内置（D0 建议口径采纳）；
> - ⚠️A15 日志路径发现口径：解析 server 块 access_log / error_log 指令获取日志路径，无该指令时回退 nginx 默认路径（D0 建议口径采纳）；
> - ⚠️A16 证书托管口径：ACME 签发证书由面板统一托管并在站点配置中引用，续期成功后原路径替换；存量导入证书保留源站原路径引用不迁移；具体存储路径常量归 D2/D3（D0「D1 定」事项，本架构定业务口径）；
> - ⚠️A17 源码编辑对象口径：Monaco 源码编辑对象限定为站点配置文件（server 块来源文件），不提供全局主配置（nginx.conf 等）编辑入口（D0 未显式列出全局主配置编辑，沿「站点对象」语义推导；如需开放需同步三文档）。
> - ⚠️A18 站点列表聚合口径（v1.1 增量）：同一来源文件内 server_name 归一后相同的多个 server 块（典型：同域名 80 明文与 443 SSL 分块）在站点列表聚合为一个站点条目呈现，监听列合并显示全部监听声明；跨文件同签名重复定义仍走重复定义呈现（⚠️A13）不聚合；聚合仅影响列表呈现模型，写回寻址与编辑对象仍为 server 块粒度（D0 增量澄清拍板，2026-11-16）。
> - ⚠️A19 ACME 文件验证落点口径（v1.1 增量）：HTTP-01 挑战对齐宝塔「文件验证」称谓与语义——验证文件自动放置优先级：①复用站点已有 acme-challenge location 的 root；②站点存在根目录时直接写 {root}/.well-known/acme-challenge/（零 nginx 改写）；③经 WritePipeline 临时注入 location（面板 webroot）→ 签发后撤除恢复；全程自动无需手动放置文件（D0 增量澄清拍板，2026-11-16；DNS-01 与手动文件验证维持 OUT）。
> - ⚠️A20 DNS-01 凭证与适配口径（v1.2 增量，Gate 1 改判拍板 2026-11-16）：DNS-01 经 DNS 服务商 API 自动化（面板存储 API 凭证，自动 TXT 添加/验证/清理，支持泛域名与自动续期）；服务商初始清单=Cloudflare+阿里云 DNS+腾讯云 DNSPod（lego 官方内置 provider，适配器注册表可扩展）；凭据 AES-256-GCM 密文存储+独立密钥文件（沿 database-mgmt CredentialVault 先例）、明文永不回显、审计 detail 脱敏；手动 TXT 验证 OUT（每次续期需人工介入，与自动续期承诺互斥）。

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

网站管理遵循「接得住存量 → 建得了新站 → 改得动配置（安全写回）→ 看得见运行 → 保得住证书」的业务主线，按站点生命周期与接管卖点划分五个业务阶段：

- **存量接管阶段**：扫描 nginx 惯例配置目录，词法解析为指令树，提取 server 块为结构化站点对象并登记来源文件映射——是本模块「接管而非重装」卖点的业务起点（R-15）；
- **站点建设阶段**：以三模板（静态 / PHP-FPM 对接已有 pool / 反向代理）创建新站点，产物进入站点集合参与后续治理；
- **站点配置治理阶段**：对站点对象做查看与双模式编辑（结构化可视化编辑 + Monaco 源码编辑），全部写回经安全写入治理（备份 → 校验 → 失败回滚 → 其余站点零影响），未识别指令 Raw 原文保留（R-06/R-07/R-16）；
- **站点运行运维阶段**：站点级启停（enabled ⇄ disabled，经安全写入流程生效）、访问/错误日志尾部查看、nginx 重载；
- **证书治理阶段**：证书全生命周期——ACME 申请（HTTP-01（文件验证）/TLS-ALPN/DNS-01〔v1.2，DNS API 自动化〕）、DNS 凭证管理、部署到站点、自动续期与失败重试、存量证书识别导入与清单查看、证书删除（ADR-024 状态机贯穿）。

五阶段为主线依赖关系：存量接管与站点建设产出站点对象 → 配置治理消费并安全变更站点对象 → 运行运维使变更生效并保障可观测 → 证书治理为站点 TLS 保障供给，贯穿站点生命周期。

### 2.1 存量接管阶段

**业务说明**：本模块核心卖点的业务起点（R-15 存量自动发现）。面板扫描 nginx 惯例配置目录（conf.d / vhost.d / sites-enabled 等），词法解析为指令树后提取 server 块为结构化站点对象，已有环境无需重装即被纳入管理。本阶段为系统自动发现机制，无用户注册/登记动作，发现结果直接呈现在站点集合中。

##### 2.1.1 nginx 配置存量导入

**业务说明**：将存量 nginx 配置文件转化为面板站点对象的全自动管线。所属 L2：存量接管阶段。管线各环节为系统机制型业务活动，导入结果经站点集合呈现给用户；round-trip 保真（解析→生成→再解析语义等价）是本管线与下游写回能力的共同业务前提（R-07/R-16）。

###### 2.1.1.1 配置目录扫描发现

**业务说明**：扫描 nginx 惯例配置目录（conf.d / vhost.d / sites-enabled 等）发现全部配置文件与其中包含的 server 块，形成待解析清单。所属 L3：nginx 配置存量导入。

###### 2.1.1.2 指令树解析

**业务说明**：对发现的配置文件做词法扫描（处理引号、变量、注释、正则 location 等复杂语法）并构建通用指令树，解析不了的指令/块保留为 Raw 节点携带原文本，保证不破坏现有配置（R-07 的解析侧业务前提）。所属 L3：nginx 配置存量导入。

###### 2.1.1.3 server 块站点提取

**业务说明**：从指令树提取 server 块为结构化站点对象：域名（server_name）、监听端口（listen）、根目录（root）、证书引用（ssl_cert）、location 列表、反代上游（proxy_pass）、enabled 状态等；一个 server 块对应一个站点对象。所属 L3：nginx 配置存量导入。

###### 2.1.1.4 写回落点登记

**业务说明**：为每个导入站点登记「站点 → 来源文件」映射，多配置目录并存时（conf.d 与 sites-enabled 同时启用等场景）按映射消重，编辑写回落到原文件（⚠️A13，D0 待细化事项落定）。该映射是下游全部写回动作的落点依据。所属 L3：nginx 配置存量导入。

### 2.2 站点建设阶段

**业务说明**：在存量接管之外提供新站点创建能力，三模板覆盖个人自托管主流场景：纯静态站点、对接已有 PHP-FPM 的动态站点、反向代理站点。新建产物为面板生成的站点对象与配置文件，纳入统一的配置治理与运行运维主线。

##### 2.2.1 新建站点

**业务说明**：按模板创建新站点的业务能力。所属 L2：站点建设阶段。三模板产出的配置写入同样经安全写入治理（备份 → 校验 → 回滚），与存量站点共用同一治理主线。

###### 2.2.1.1 静态站点创建

**业务说明**：以静态站点模板创建站点：指定域名与监听端口、根目录，生成静态站点 server 块配置。所属 L3：新建站点。

###### 2.2.1.2 PHP-FPM 站点创建

**业务说明**：以 PHP-FPM 模板创建动态站点：发现本机已有 php-fpm pool 并列出供选择对接（不新装 PHP，接管已有环境），FastCGI 转发参数模板内置（⚠️A14，D0 待细化事项落定），生成含 PHP 处理 location 的 server 块配置。所属 L3：新建站点。

###### 2.2.1.3 反向代理站点创建

**业务说明**：以反向代理模板创建站点：指定域名、监听端口与上游地址，生成反代 server 块配置（上游地址、Host 头、WebSocket 透传开关按模板默认值生成，后续可在站点信息管理中调整）。所属 L3：新建站点。

### 2.3 站点配置治理阶段

**业务说明**：站点对象的全量查看与安全变更能力，是本模块「改得动且改不坏」的核心价值承载：结构化可视化编辑与 Monaco 源码编辑双模式覆盖不同熟练度的操作者；全部写回统一经安全写入治理（R-06 四步 + R-16 隔离保证），未识别指令 Raw 原文保留写回（R-07），保证存量配置不被破坏。

##### 2.3.1 站点信息管理

**业务说明**：站点集合的观测与结构化编辑能力：列表（域名、监听端口、根目录、证书状态、反代上游、enabled 状态）、详情（location 列表、Raw 块、来源文件）、基本信息编辑与反向代理参数管理。所属 L2：站点配置治理阶段。

###### 2.3.1.1 站点列表查看

**业务说明**：以列表呈现全部站点对象：域名、监听端口、根目录、证书状态、反代上游、enabled 状态；同一来源文件内同域名多 server 块（如 80 与 443 分块）聚合为一个站点条目、监听列合并显示（⚠️A18，v1.1 增量）；是全部站点操作的入口与操作前状态依据。所属 L3：站点信息管理。

###### 2.3.1.2 站点详情查看

**业务说明**：查看单个站点的结构化详情：location 列表、证书引用、Raw 块（未识别指令原文）、来源文件路径；详情是可视化编辑与源码编辑的入口。所属 L3：站点信息管理。

###### 2.3.1.3 站点基本信息编辑

**业务说明**：结构化编辑站点基本字段：域名（server_name）、监听端口（listen）、根目录（root）、enabled 状态等；编辑保存后经安全写入治理写回来源文件。所属 L3：站点信息管理。

###### 2.3.1.4 反向代理参数管理

**业务说明**：管理反代站点的代理参数：上游地址、Host 头、WebSocket 透传开关；编辑保存后经安全写入治理写回（idea.md §6 M3 验收主场景：修改某站点反代地址并保存，`nginx -t` 通过且站点生效、其余站点无变化）。所属 L3：站点信息管理。

###### 2.3.1.5 Raw 未识别指令保留写回

**业务说明**：写回时对解析不了的指令/块以 Raw 节点按原文本输出（R-07），保证站点对象之外的原配置内容零丢失；该保全语义是「接管不破坏」承诺的业务底线，由全部编辑类写回动作共同遵守。所属 L3：站点信息管理。

##### 2.3.2 配置源码编辑

**业务说明**：面向高阶操作者的源码级编辑能力：以 Monaco 编辑器直接编辑站点配置文件原文，保存前自动执行 `nginx -t` 校验（idea.md §4.1 M4）。编辑对象限定为站点配置文件（⚠️A17）。所属 L2：站点配置治理阶段。

###### 2.3.2.1 Monaco 源码编辑与保存校验

**业务说明**：打开站点配置文件原文进行源码级编辑（语法高亮），保存时自动执行 `nginx -t` 校验，校验不通过则拒绝写入并呈现错误（校验与回滚细节由安全写入治理承载）；源码与结构化视图对同一来源文件保持一致。所属 L3：配置源码编辑。

##### 2.3.3 安全写入治理

**业务说明**：全部配置写入动作的固定安全流程（R-06）：写前快照备份 → 修改 → `nginx -t` 校验 → 失败自动恢复备份并报错 diff；同时保证站点隔离写回（R-16：编辑写回不得影响其余站点，byte-level 或语义级无变化）。本阶段是配置治理与运行操作共用的安全底线机制。所属 L2：站点配置治理阶段。

###### 2.3.3.1 写前快照备份

**业务说明**：任何配置写入前，将目标配置文件快照备份到 conf.backup/时间戳/ 目录，为失败回滚提供恢复点。所属 L3：安全写入治理。

###### 2.3.3.2 写入校验与失败自动回滚

**业务说明**：写入后执行 `nginx -t` 配置校验：校验通过才使变更进入生效通道；校验失败自动恢复写前备份并向操作者报错 diff（失败位置与差异），做到「改不坏」——失败的修改不会留在配置中（R-06）。所属 L3：安全写入治理。

###### 2.3.3.3 站点隔离写回

**业务说明**：写回仅作用于目标站点的来源文件（落点由写回落点登记提供，⚠️A13），保证其余站点配置 byte-level 或语义级无变化（R-16）；该隔离语义与 round-trip 样本集 ≥ 20 的验收硬项共同构成「接管不破坏」的验收底线（idea.md §6 M3）。所属 L3：安全写入治理。

### 2.4 站点运行运维阶段

**业务说明**：站点生命周期内的运行侧治理：站点级启停（enabled ⇄ disabled 状态流转，kb 拍板；开关经安全写入流程修改配置后 reload 生效）、访问/错误日志尾部查看（排障入口）、nginx 重载（配置变更的用户主动生效动作）。

##### 2.4.1 站点运行操作

**业务说明**：站点运行维度的管控与观测能力。所属 L2：站点运行运维阶段。启停改变站点 enabled 状态但保留其配置与证书引用（停用≠删除）。

###### 2.4.1.1 站点启停

**业务说明**：通过 enabled 开关在启用 ⇄ 停用间切换站点：开关动作经安全写入流程修改来源文件（启停配置段），校验通过后 reload 生效（kb 状态机：站点 enabled ⇄ disabled，走 R-06 流程 → nginx reload）。所属 L3：站点运行操作。

###### 2.4.1.2 访问与错误日志尾部查看

**业务说明**：查看站点访问日志与错误日志的尾部内容（排障入口）：日志路径经解析 server 块 access_log / error_log 指令获得，无该指令时回退 nginx 默认路径（⚠️A15，D0 待细化事项落定）。所属 L3：站点运行操作。

###### 2.4.1.3 nginx 重载

**业务说明**：用户主动触发的 nginx reload 动作：使已写入的配置变更生效（平滑重载不断连接）；与安全写入流程中的生效环节共用同一 reload 通道。所属 L3：站点运行操作。

### 2.5 证书治理阶段

**业务说明**：站点 TLS 保障的全生命周期：ACME 申请（HTTP-01（文件验证）/ TLS-ALPN / DNS-01（v1.2 增量，DNS API 自动化）三种挑战方式）+ DNS 凭证管理（v1.2）、面板托管与部署引用、自动续期与失败重试、手动更新（v1.1 增量：立即续期/imported 文件替换）（ADR-024 证书状态机：pending → valid → expiring_soon（到期前 30 天）→ expired / renew_failed，重试成功回 valid）、存量证书识别导入与清单查看、证书删除。零遥测边界下的例外说明：ACME 申请是面板唯一的外部网络请求（idea.md §3，R-09 除外条款）。

##### 2.5.1 证书签发与部署

**业务说明**：为站点获取并启用 TLS 证书：两种 ACME 挑战方式申请、签发后由面板托管并部署到站点配置引用（⚠️A16）。所属 L2：证书治理阶段。

###### 2.5.1.1 ACME 证书申请 HTTP-01（文件验证）

**业务说明**：以 HTTP-01 挑战向 ACME 服务（Let's Encrypt 等）申请站点域名证书，面板界面称「文件验证（HTTP-01）」：验证文件由面板自动放置（优先网站根目录，其次既有挑战 location 复用，最后临时注入并撤除，⚠️A19，v1.1 增量），需域名可经 80 端口 HTTP 访问完成挑战验证，全程自动无需手动放置；申请发出后证书进入 pending 态，签发成功转 valid（ADR-024 状态机）。所属 L3：证书签发与部署。

###### 2.5.1.2 ACME 证书申请 TLS-ALPN

**业务说明**：以 TLS-ALPN 挑战申请证书：无需 80 端口 HTTP 通路，经 443 端口 TLS 握手内挑战完成验证，适用于仅 HTTPS 暴露的站点；状态流转同 HTTP-01（ADR-024 状态机）。所属 L3：证书签发与部署。

###### 2.5.1.4 ACME 证书申请 DNS-01（DNS API 自动化，v1.2 增量）

**业务说明**：以 DNS-01 挑战申请证书（含泛域名）：面板经用户配置的 DNS 服务商 API 凭证**自动添加/验证/清理 TXT 记录**（⚠️A20），全程无人工介入——适用 80/443 均不可达面板服务器的场景与泛域名证书；支持自动续期（续期复用签发时凭证，凭证缺失如实失败）；挑战方式标记 acme_challenge=dns_01；凭证经 DNS 凭证管理（2.5.1.5）维护。所属 L3：证书签发与部署。

###### 2.5.1.5 DNS 凭证管理（v1.2 增量）

**业务说明**：维护 DNS 服务商 API 凭证（Cloudflare/阿里云 DNS/腾讯云 DNSPod，⚠️A20）：新建（凭据材料服务端校验、AES 密文存储永不回显——沿 database-mgmt 凭据先例）、删除（有 dns_01 证书引用时警示不硬阻断、删除后引用证书自动续期将失败如实呈现）；凭证操作 admin 专属+审计留痕（R-03，detail 脱敏）。所属 L3：证书签发与部署。

###### 2.5.1.3 证书部署

**业务说明**：将面板托管的有效证书部署到目标站点：修改站点配置的证书引用（经安全写入流程写回并 reload 生效）；部署建立「证书 ⇄ 站点」引用关系，为后续续期替换与删除约束提供依据。所属 L3：证书签发与部署。

##### 2.5.2 证书续期治理

**业务说明**：证书有效期治理：到期前 30 天证书转 expiring_soon 并触发自动续期调度（ADR-024），续期成功回 valid 并替换托管证书、重新部署；失败转 renew_failed 并支持手动重试，保证站点 TLS 不因证书过期中断。所属 L2：证书治理阶段。

###### 2.5.2.1 自动续期调度

**业务说明**：后台自动续期任务：对 expiring_soon 状态证书自动发起续期（复用原申请的挑战方式），成功后替换托管证书内容（原路径替换，⚠️A16）、重新部署引用并回 valid；续期为系统机制型业务活动，无用户入口。所属 L3：证书续期治理。

###### 2.5.2.2 续期失败处理与手动重试

**业务说明**：续期失败转 renew_failed 并向操作者呈现失败原因（排障），支持手动重试：重试成功回 valid，证书到期仍未成功则转 expired（ADR-024 状态机）。所属 L3：证书续期治理。

###### 2.5.2.3 证书手动更新

**业务说明**：不等待自动续期调度的手动更新入口（v1.1 增量，D0 增量澄清拍板）：acme 来源证书（valid/expiring_soon/expired/renew_failed 非在途态）由操作者主动发起立即续期重签（复用原挑战方式进入同一续期通道）；imported 来源证书提供新证书文件替换通道（粘贴新证书与私钥，备份后原子写回源站原路径，引用站点 ssl_cert 引用值不变、无需重新部署）；更新结果与失败原因如实呈现。所属 L3：证书续期治理。

##### 2.5.3 证书纳管与清理

**业务说明**：存量证书的接管与证书集合的终局治理：扫描导入时从站点配置 ssl_cert 引用自动识别已有证书纳入管理（来源 imported），证书清单提供域名、签发者、有效期、来源、状态的全集观测，证书删除提供生命周期终局出口。所属 L2：证书治理阶段。

###### 2.5.3.1 存量证书识别导入

**业务说明**：存量导入管线自动识别站点配置中的 ssl_cert 证书引用，将已有证书纳入面板管理（来源标记 imported，保留源站原路径引用不迁移，⚠️A16），与 ACME 签发证书（来源 acme）在同一证书清单中统一呈现；系统机制型业务活动，随站点导入自动发生（R-15 同哲学）。所属 L3：证书纳管与清理。

###### 2.5.3.2 证书清单查看

**业务说明**：查看全部纳管证书：域名列表、签发者（issuer）、有效期、来源（acme/imported）、当前状态（ADR-024 状态机）；是证书排障（含 renew_failed）与站点证书状态列的数据源。所属 L3：证书纳管与清理。

###### 2.5.3.3 证书删除

**业务说明**：删除面板托管的证书及其续期任务：仍有站点引用时提示先解除部署引用（解释性决策：防误删致站点 TLS 失效）；存量导入证书的删除仅解除面板管理关系，不删除源站原证书文件（存量证书文件归站点原配置所有）。所属 L3：证书纳管与清理。
