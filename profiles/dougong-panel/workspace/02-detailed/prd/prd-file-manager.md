## 第一部分：业务目标（G1）

为登录运维者提供所在服务器 **受管根范围内文件的直接浏览与操作能力**：服务器上的文件本就在那里，面板不导入、不镜像、不重建，直接对真实文件系统提供浏览（列表/图标）、上传下载、在线编辑、整理、权限属主修改与压缩解压——这是「接管存量环境」哲学在文件维度的落点（D0 §2 模块定位）。安全是本域的第一约束：所有路径类操作经「EvalSymlinks 解析真实路径 → 白名单前缀校验」两步强制前置（R-04，files 适配器/安全路径层），路径逃逸测试为里程碑 M2 验收硬项（D0 §2）；删除不直接销毁而是入站回收站（R-17，ADR-021 拍板），使删除可逆、销毁终局可追溯。轻量承诺在本域的落法：**文件台账零持久化**——file_entry 为文件系统实时投影、元数据不落库（kb 拍板），唯一持久化对象是回收站条目 trash_entry（落 SQLite，ADR-021 新增对象）。服务对象：单机自托管的管理员（admin）与只读用户（readonly）——admin 执行全部变更与数据取出，readonly 同等查看目录内容、导航与回收站列表（ADR-018：禁变更、禁上传下载）。

本域是「可信」支柱（idea.md §1 目标 3）在文件操作上的承载者：每一笔变更（含下载这一数据取出）都可追溯到操作者、时间、对象与结果（R-03）。

## 第三部分：角色定义（G3）

| 角色 | 英文 | 职责与权限 | 获得方式 |
|------|------|-----------|---------|
| 管理员 | admin | 查看能力全集（目录浏览/导航/回收站列表/白名单配置查看）+ 全部变更类操作（上传/编辑/整理/权限属主/压缩解压/还原/清空/白名单配置修改）+ 数据取出（下载） | account-auth 初始化/用户管理创建 |
| 只读用户 | readonly | 同等查看目录内容、导航与回收站列表（ADR-018「全可看」）；上传/下载/编辑/整理/权限属主/压缩解压/还原/清空/配置修改全部无入口（界面不提供）+ 越界请求被全局边界管控拒绝（account-auth S-03-02） | 管理员创建并指派 |

访客（未认证操作者）不涉及：本模块全部功能位于登录会话之后（R-02），无访客触达点（与 monitoring/service-mgmt 同口径）。角色差异边界：全部写类操作与下载为 admin 专属（ADR-018 禁变更禁上传下载）；查看类动作不写审计（R-03 语义为「变更」留痕）；下载虽为读类动作但按数据取出口径记审计（解释性决策，沿 account-auth「审计导出记审计」同口径，D1 FL 附录B 落定）。

## 第四部分：功能需求明细

> 与 AA（application-arch-file-manager.md）19 个功能子模块一一对应，覆盖 FL（function-list-file-manager.md）admin 19 个菜单行（readonly 3 个只读行同 FR 的只读视角）；变更类 FR 全部记审计，查看类与机制型 FR 审计为「—」。所有携带路径的 FR（FR-03~19）均隐含 FR-01 强制前置校验，各 FR 表内不再重复。

### 4.1 安全路径管控（S-19）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | 路径白名单校验（S-19-01，机制型） | 对每个携带路径的请求执行两步校验：① EvalSymlinks 解析请求路径为真实物理路径（消除 `../` 相对路径与符号链接间接指向）；② 真实路径须落在受管根前缀内且未命中排除目录清单。任一步不通过即拒绝本次操作并向操作者明确提示越界原因；不虚构部分结果、不降级放行。防三类逃逸：`../` 相对路径、符号链接外指、解压条目越界（zip slip，见 FR-15）。路径逃逸测试为里程碑验收硬项（D0 §2） | —（前置机制；拒绝不记审计，R-03 语义为变更留痕） |
| FR-02 | 受管根与排除目录配置（S-19-02） | 查看与修改白名单业务边界：受管根默认 `/`（整机受管），可配置为其他目录；排除目录清单默认建议 `/proc`、`/sys`、`/dev`（伪文件系统），可增删；修改后对后续文件操作即予生效（进程内生效机制 D3 定，待对齐-1）；⚠️A12（D1：R-04「可配置排除」语义的必要落点，D0 IN 未显式列出） | 记审计（R-03） |

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-16 | 回收站入站登记（C-06-01，机制型） | 删除入站（FR-11）的回收站接收：回收站为**受管根下单一目录** `.dougong-trash/`，每个被删条目在 trash 内以唯一标识子目录存放（标识含时间与随机成分，避免重名覆盖）；同时写 trash_entry 元数据记录（原路径、删除时间、操作者、类型、大小、trash 内标识）落 SQLite（ADR-021）；**跨设备降级**：条目与回收站不在同一文件系统时 rename 失败（EXDEV），降级为「复制入站 + 原条目删除」，降级事实记审计（D1 BA 2.3.1.1 落定）；入站来源路径经 FR-01 校验 | 降级事实记审计；常规入站随 FR-11 的删除审计覆盖 |

## 第六部分：状态流转（T2）

本域有 **1 个持久化状态机**（trash_entry，kb 拍板）；file_entry 无面板侧状态机（实时投影）。

**回收站条目状态机**（trash_entry_status）：

| 当前状态 | 目标状态 | 触发 | 备注 |
|---------|---------|------|------|
| 在站（in_trash） | 已还原（restored） | 面板还原操作（FR-18）成功 | 条目移回原路径；记录保留供追溯；从回收站列表消失 |
| 在站（in_trash） | 已清空（purged） | 面板清空操作（FR-19） | 条目内容删除；**记录物理删除**（purged 为终态语义值，落库行随即消失，销毁事实由审计留痕） |

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| file_entry「状态」 | 文件系统条目无面板侧状态机：存在性与属性（大小/权限/属主/修改时间）事实源在文件系统，面板仅投影；属性变化是投影刷新而非状态流转 | 无状态机（投影语义，FR-03） |
| 上传同名冲突中的「覆盖」 | 覆盖是操作者对冲突的显式决策（替换目标文件），不是状态流转——被覆盖文件无状态机、旧内容直接被 rename 替换（R-05 原子性） | 决策语义，非状态机 |
| 分块上传任务「进行中/完成/失败」 | 一次性执行过程状态，任务结束即消亡、不持久化、断点续传二期（OUT-4） | 过程数据（P7），非领域状态机 |
| 跨设备降级「copy+delete」（FR-16） | 入站登记的实现路径切换（rename 失败 → 复制+删除），非状态变化；降级事实记审计 | 实现语义，非状态机 |
| 隐藏条目显示/不显示 | 浏览呈现口径固定为全量呈现（D1 解释性决策），无开关无状态 | 呈现语义，非状态机 |
| 回收站条目「被外部改动」（trash 目录被 shell 手工清空） | 面板外干预：列表读取时按 trash 实况与 trash_entry 记录对账（孤儿记录=trash 内容已不在 → 列表剔除并标注），见 N2 | 一致性对账语义，非状态机 |

无审批类状态流转（T3 N/A 的依据）：本域操作为管理员即时执行，无提交/授权环节；唯一授权边界=角色判定（ADR-018），属访问控制非审批流。

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：受管根默认 `/`（整机量级文件数，目录内条目单目录数十至数千条量级）；回收站在站条目为低频删除积累、量级小；零文件台账（唯一持久化=trash_entry）。未锁定项（工程化缺口，不虚构，移交 D3/D4）：分块大小阈值与并发分块数（待对齐-3）；在线编辑大小上限与二进制检测方式（待对齐-4）；目录浏览分页/全量、排序与刷新机制（待对齐-7）；回收站列表排序口径（待对齐-6）；上传冲突决策接口形态（待对齐-2）；权限递归修改口径（待对齐-5）；白名单配置存储载体与生效机制（待对齐-1）。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| 路径越界（`../` 逃逸 / 符号链接外指 / 解压条目越界） | FR-01 两步校验拒绝，明确提示越界原因，不降级放行；拒绝不记审计（第五部分口径）；逃逸测试为 M2 验收硬项 |
| 解压遇越界条目（zip slip） | 逐条目校验，任一条目越界则整体失败回滚，不部分解压（FR-15）——半解压状态不可接受 |
| 删除跨设备（EXDEV） | 入站登记降级 copy+delete，降级事实记审计（FR-16）；降级失败（复制中途中断）则整次删除失败、原条目保持不动，如实报错 |
| 还原目标路径被占用 | 提示显式选择覆盖或放弃，不自动改名（FR-18/D1 落定）；覆盖失败（目标为只读等）如实报错且条目保持「在站」 |
| 上传落盘失败（磁盘满/权限不足） | 临时文件写入失败即整文件失败，不留半写文件（R-05 临时文件清理）；如实呈现失败原因 |
| 上传/移动/解压同名冲突 | 显式决策覆盖或跳过/放弃（D1 解释性决策），不静默覆盖 |
| 编辑打开二进制/超大文件 | 拒绝并提示改用下载后本地处理（FR-08）；二进制检测与上限数值 D3 定（待对齐-4） |
| 分块上传中途失败/中断 | 校验失败的分块拒绝；任务中断即整任务作废重传（断点续传二期 OUT-4）；临时分块数据按任务作废清理 |
| 在线编辑保存失败（磁盘满/文件被外部改动） | 全量覆盖写失败即报错，编辑内容保留在编辑器（前端态）待重试；不做合并/冲突自动解决（无版本历史 OUT-2） |
| trash 目录被面板外改动（shell 手工删除/清空 `.dougong-trash/`） | 面板外干预属预期风险边界：列表读取按 trash 实况与记录对账，孤儿记录剔除并标注；不做自动重建（面板不接管面板外删除语义，第五部分口径） |
| 操作对象在请求间隙被外部删除/改动 | 文件系统原子操作语义天然报错（ENOENT 等），如实呈现；不虚构成功 |
| 白名单配置修改为排除当前浏览目录 | 生效后该目录操作被拒绝并提示越界原因（配置即予生效，FR-02）；不阻止修改本身（admin 明知配置） |
| 操作在途重复提交 | 前端在途禁用（D4 呈现）+ 服务端路径级操作语义（rename 原子性）双保险；重复删除第二请求报 ENOENT 如实反馈 |
| readonly 越界发起任何变更/下载 | 全局边界管控拒绝并提示边界原因（account-auth S-03-02，ADR-018）；界面本就无入口 |
| 路径/名称/分块参数非法 | 服务端校验拒绝（R-14）：路径形态、名称合法性（无分隔符/保留名）、分块序号与总大小一致性 |
| 空目录浏览 / 无在站条目 | 返回空列表，非错误 |

**N3 业务规则细节**：见第五部分规则汇总全集；补充幂等语义——删除入站对已不存在的路径报错如实（不做静默成功）；rename 原子性保证覆盖类操作（上传覆盖/移动覆盖/还原覆盖）的目标替换无中间态；清空为幂等终局（重复清空=0 条目成功）。

**N4 历史需求**：面板侧无文件操作历史台账（零文件台账推导）；操作追溯由 account-auth 审计日志查询覆盖（audit_action=change + 下载的数据取出记录，对象=路径）；回收站已还原记录保留供追溯（FR-18）；文件属性变迁历史不在范围（文件系统无此语义，如需属备份/审计二期范畴）。
