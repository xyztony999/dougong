## 第一部分：业务目标（G1）

为登录运维者提供所在服务器 **存量 ufw / firewalld 后端的识别与端口规则治理能力**：防火墙后端本就装在机器上，面板不安装、不切换、不替换——进入防火墙业务时自动探测（ufw 优先 → firewalld，R-15 识别既有后端），两者均无时以引导提示呈现；识别后提供端口级规则的查看、添加、删除（命令一律参数数组，R-08；操作即时生效并记审计 R-03），以及系统监听端口与规则投影的开放状态对照（无放行规则的对外监听端口为风险敞口提示对象）——这是「接管存量环境」核心卖点（idea.md D5/§3）在主机网络入口侧的承载，M5 验收硬项为「ufw 与 firewalld 环境各自通过规则增删测试」（idea.md §6 M5）。本模块误操作风险为全面板最高——一次错误删除可将面板自身的访问入口一并封锁（失联风险），**面板端口保护为设计硬项**（M7 明示项，D0 定性）：直接命中面板端口的删放行/加阻断动作必须警示并二次确认（判定基准为面板基座监听配置）。轻量承诺在本域的落法：**零规则台账**——firewall_rule 为后端实况投影、不落库（kb 拍板口径，本 PRD D2 沿用，与 site 零站点台账/database-mgmt 零库用户台账同哲学），面板外经服务器本地增删的规则如实反映。服务对象：单机自托管的管理员（admin）与只读用户（readonly）——admin 执行全部规则增删，readonly 查看规则列表与端口对照（ADR-018「全可看」）。

本域的安全约束递次为：面板端口保护（防自锁，第一约束）、R-08 命令参数数组纪律（防注入，第二约束）、R-03 全变更审计（第三约束）。

| 角色 | 英文 | 职责与权限 | 获得方式 |

访客（未认证操作者）不涉及：本模块全部功能位于登录会话之后（R-02），无访客触达点（与 monitoring/service-mgmt/file-manager/site-mgmt/database-mgmt/terminal 同口径）。角色差异边界：全部写类操作为 admin 专属；查看类动作不写审计（R-03 语义为「变更」留痕）；规则增删动作写审计（规则四要素入审计载荷，无敏感值脱敏面——规则参数本身即业务内容）。

## 第四部分：功能需求明细

> 与 AA（application-arch-firewall.md）7 个功能子模块一一对应，覆盖 FL（function-list-firewall.md）admin 5 个菜单行（readonly 3 个只读行同 FR 的只读视角）；变更类 FR（FR-05/FR-06）记审计，查看类与机制型 FR 审计为「—」或随宿主动作覆盖。所有产生后端变更的 FR 均以 firewallx 适配器经识别出的唯一后端通道执行、命令一律参数数组（R-08，各 FR 表内不重复）；全部以识别出可用后端为前提（无后端时整体降级为 FR-02 引导，见第八部分）。

### 4.1 防火墙后端识别（S-42）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | 双后端自动识别（S-42-01，机制型） | 自动探测既有防火墙后端：优先级 ufw → firewalld（R-15 识别既有后端、不引入新防火墙）；探测维度=后端存在且可用，探测为只读行为（不改变后端任何状态）；识别结论=唯一后端类型（firewall_backend：ufw/firewalld/none）+ 后端运行状态（如 ufw 启用/未启用、firewalld 运行态——呈现字段集 D3 定，待对齐-1）；后续全部规则业务经该唯一后端通道执行；探测触发时机（进入防火墙页/手动刷新组合）D3 定（待对齐-1）；识别结论呈现于规则视图页头（宿主呈现，机制型覆盖见 FL 附录A） | —（机制；结论随页头呈现） |
| FR-02 | 无后端引导提示（S-42-02） | ufw 与 firewalld 均未检测到（firewall_backend=none）时防火墙业务以引导提示页呈现：说明未检测到受支持后端、指引安装其一后再使用；**不提供代为安装入口**（MVP）；规则相关功能整体不可用，**不得将「无后端」呈现为「无规则」空列表**（语义区分：无后端≠无规则，空列表会误导管理员放松警惕——D1 FL 附录B 解释性决策）；两角色同视角（readonly 亦只见提示，无可操作内容）；检测频率口径（每次进入均探测 vs 会话内缓存）D3 定（待对齐-9） | —（查看类降级视图） |

### 4.2 端口规则观测（S-43）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-03 | 端口规则列表查看（S-43-01） | 只读呈现当前后端全部端口级规则投影：端口/端口段、协议（firewall_rule_protocol：tcp/udp）、方向（固定入站，MVP 单值维度）、来源限制（任意来源或 CIDR 网段）、动作（firewall_rule_action）、后端原始语义标识（用于与后端自身工具输出互认，呈现口径 D3 定待对齐-2）；规则为后端实况投影不落库（零规则台账，第六部分辨析）——面板外经服务器本地增删的规则如实反映；页头呈现识别出的后端类型与运行状态（FR-01 宿主呈现）；对**直接命中面板端口的规则作出标注**（判定基准与口径同 FR-07，panel-core 监听配置实况读取）；两角色同等可用（ADR-018）；管理员可从列表发起添加（FR-05）与逐条删除（FR-06），readonly 无操作入口；列表筛选/排序口径 D3 定（待对齐-5） | —（查看类） |
| FR-04 | 监听端口对照查看（S-43-02） | 读取系统当前监听端口清单（监听地址、端口、监听进程），与端口规则投影逐项对照，呈现每个监听端口的开放状态（listen_port_state：allowed_by_rule 已被规则放行 / no_allow_rule 无放行规则）；**对外监听且无放行规则的端口为风险敞口重点提示对象**；对照仅针对入站方向（出站 OUT-3）；监听端口取数为系统网络栈只读读取、单一只读通道（与系统监控采集统一取数来源，D1 口径-3——具体库选型归后端工程，避免双通道口径漂移）；localhost-only 监听端口的呈现口径（是否单列「仅本机」维度）D3 定（待对齐-3）；两角色同等可用（ADR-018） | —（查看类） |

### 4.3 端口规则治理（S-44）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-05 | 端口规则添加（S-44-01） | 录入端口/端口段、协议（tcp/udp）、来源限制（任意来源或 CIDR 网段）、动作后提交，经当前后端命令通道即时生效；**动作支持面随后端能力**（D1 口径-2）：ufw 全动作 allow/deny/reject/limit（deny 丢弃无回应、reject 明确拒绝、limit 限速放行防暴破），firewalld MVP 仅 allow（deny/reject/limit 依赖富规则，OUT-1）——添加入口按当前后端如实呈现可用动作集；**firewalld 下按永久 + 运行态双写**（写入永久配置并即时生效运行态，保证重启有效，D1 口径-1；双写实现口径与 runtime 应用失败处置 D3 定，待对齐-8）；在面板端口上添加 deny/reject 阻断规则时触发面板端口保护（FR-07）；端口/端口段/CIDR 服务端校验（R-14，校验规则集 D3 定待对齐-4）；admin 专属（ADR-018） | 记审计（R-03） |
| FR-06 | 端口规则删除（S-44-02） | 对指定规则（按后端规则标识寻址）执行删除：交互确认后经当前后端命令通道即时生效；firewalld 下同样永久 + 运行态双写删除（D1 口径-1）；删除面板端口放行规则时触发面板端口保护（FR-07）；规则不存在时如实报错（面板外已删——实况投影的自然结果，不静默成功）；admin 专属（ADR-018） | 记审计（R-03） |
| FR-07 | 面板端口规则保护（S-44-03，机制型） | 对**直接命中面板自身端口**的高危规则治理动作执行「识别 → 警示 → 二次确认」保护（M7 明示项，D0 定为设计硬项）：触发面=删除面板端口的放行规则（D0 明示）+ 在面板端口上添加 deny/reject 阻断规则（D1 口径-4：二者同为「面板失联」风险场景，保护语义一致）；警示语义明示「此操作可能导致面板失去访问」，二次确认后方可执行；**保护为警示与确认语义，不阻止操作本身**（最终执行权在管理员，救援通道为服务器本地/SSH 操作）；判定基准=面板基座监听配置（监听端口与协议，panel-core panel_config 实况读取，读取通道 D3 定待对齐-6）；判定口径=规则对象**直接命中**面板端口（端口/端口段直接覆盖面板端口），不做跨规则重叠语义推导（宽端口段删除影响推导二期，OUT-7）；警示文案与确认交互 D4 定；随 FR-05/FR-06 触发，无独立用户入口（机制型覆盖见 FL 附录A） | 随宿主动作（FR-05/FR-06 审计载荷含保护触发事实，口径 D3 定） |

## 第六部分：状态流转（T2）

本域 **无业务状态机**：D0 拍板「规则有无即状态」，kb 状态机表无 firewall_rule 条目；规则增删为后端实况 CRUD、无审批链、不产生业务编号。

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| 后端识别结论（ufw/firewalld/none） | 每次探测整值刷新的判定值（firewall_backend 枚举），无流转触发与状态机语义 | 判定值属性，非状态机 |
| 后端运行状态（ufw 启用/未启用、firewalld 运行态） | 后端自身实况属性的只读透传（面板不提供启停开关，OUT-5） | 透传属性，非状态机 |
| 规则存在/不存在 | 规则=后端侧记录的存在与删除（事实源在后端），无状态字段流转 | 记录存在语义，非状态机 |
| 监听端口开放状态（allowed_by_rule/no_allow_rule） | 规则投影与监听实况的读取时对照派生值，随任一侧实况变化整值刷新 | 派生属性（listen_port_state），非状态机 |
| 添加/删除在途、firewalld 双写在途 | 一次性动作执行过程，终态反馈即消亡（与 service-mgmt 操作任务同构） | 过程数据（P7），非状态机 |
| 无后端引导提示呈现 | 识别结论为 none 时的降级视图，非实体状态 | 视图降级语义，非状态机 |
| 面板端口标注 | 规则与面板监听配置的命中关系派生标记（直接命中口径） | 派生标记，非状态机 |

无审批类状态流转（T3 N/A 的依据）：本域操作为管理员即时执行，无提交/授权环节；「面板端口保护」的二次确认为**交互层危险操作防护**（M7 明示项），属操作前置警示语义、非他人授权的审批流——与「确认」概念对齐（d2 分册 2.5：操作人自己确认事实，不需要申请模型）。

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：量级——规则数十~百条、监听端口数十~百条（单机量级，全量呈现无需分页，分页口径 D3 复核）；零持久化（零规则台账，无 DDL 无数据侧设计）；M5 验收硬项（ufw 与 firewalld 环境各自通过规则增删测试）。未锁定项（工程化缺口，不虚构，移交 D3/D4）：探测时机与运行状态字段集（待对齐-1）；规则稳定标识与列表口径（待对齐-2/-5）；对照呈现口径（待对齐-3）；校验规则集（待对齐-4）；监听配置读取通道（待对齐-6）；等价规则语义（待对齐-7）；双写实现（待对齐-8）；检测频率（待对齐-9）。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| 无后端（ufw/firewalld 均未检测到） | 整体降级为引导提示页（FR-02），规则功能不可用，不呈现「无规则」空列表、不报错 |
| 后端存在但运行态异常（如 firewalld 服务停止、ufw 未启用） | 如实呈现后端运行状态（FR-01 结论）；规则读写按后端实际执行结果如实反馈（后端启停归 service-mgmt/系统侧，本域不操作） |
| 规则添加失败（后端拒绝/权限不足/后端内部错误） | 失败原因如实反馈（R-08 通道 stderr 透传口径 D3 定），不虚构成功；无持久化故无回滚语义（后端原子性由后端自身保证） |
| firewalld 永久写入成功但运行态应用失败（双写两步非原子） | 如实报错并明示当前生效层（permanent 已写入、runtime 未生效）；处置口径（自动重载重试 vs 提示手动刷新）D3 定（待对齐-8）；不回滚永久配置（写入是用户意图，重启后仍将生效） |
| 删除时规则已不存在（面板外已删） | 如实报错（不静默成功，与幂等删除语义区分）；刷新列表后消失 |
| ufw 重复添加等价规则 | 后端语义如实反馈（合并/并列/报错按 ufw 自身行为，D3 定待对齐-7）；服务端校验前置（R-14） |
| 面板端口自锁风险操作（删放行/加阻断） | 面板端口保护警示 + 二次确认（FR-07）；确认后执行（执行权在管理员）；救援通道=服务器本地/SSH（提示文案明示，D4 定） |
| 面板外经服务器本地增删规则 | 实况是唯一事实源：规则列表如实反映（零规则台账推导）；以列表刷新对齐 |
| 监听端口部分读取失败 | 失败条目/字段置空并标注原因，不虚构默认值（与 monitoring system_info 同口径）；规则侧不受影响 |
| 空规则清单（后端可用且无规则） | 返回空列表 + 引导添加（区别于无后端降级），非错误 |
| readonly 越界发起规则添加/删除 | 全局边界管控拒绝并提示边界原因（account-auth S-03-02，ADR-018）；界面本就无入口 |
| 规则参数非法（端口越界 1-65535/端口段倒置/CIDR 格式错误/动作不在当前后端支持面） | 服务端校验拒绝（R-14），不进入后端执行；动作面按当前后端约束（firewalld 提交 deny 类直接拒绝） |
| 审计写入失败（规则已生效） | 规则生效事实如实反馈；审计失败告警不静默（同事务口径经 account-auth OHS，异常处置沿其契约） |

**N3 业务规则细节**：见第五部分规则汇总全集；补充幂等语义——规则添加非幂等（等价规则重复提交按后端语义反馈，待对齐-7）；删除非幂等（不存在报错，不静默成功）；规则清单读取无副作用（纯投影）；面板端口保护确认非幂等语义（每次涉险操作独立触发，不记忆确认）。

**N4 历史需求**：面板侧无规则变更历史台账（零规则台账推导——事实源在后端，后端自身无历史语义，不虚构历史）；操作追溯由 account-auth 审计日志查询覆盖（audit_action=change，对象=防火墙规则，变更内容=规则四要素与动作）；无独立规则历史表需求。
