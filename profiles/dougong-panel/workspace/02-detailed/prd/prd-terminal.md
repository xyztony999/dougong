## 第一部分：业务目标（G1）

为管理员提供**浏览器内的服务器 shell 交互能力**（浏览器 xterm.js ↔ WebSocket ↔ 服务端 PTY，idea.md §4.1 M6）：不装 SSH 客户端即可完成日常运维操作，全屏程序（vim/top）正常渲染（里程碑 M5 验收硬项）。Web 终端是全面板**安全暴露面最大的能力**——它把 shell（默认面板运行用户，通常 root）直接交给浏览器，因此本域设计以「复用既有安全基座 + 严格限流」为中心：鉴权逐字复用面板会话与角色判定（R-18，仅 admin 可用，ADR-018 禁 readonly），连接超时与并发按 ADR-023 标准档执行（每用户并发 5 / 空闲 30 分钟断开 / 单连接硬上限 8 小时），面板会话失效联动断开全部终端（R-18 反向联动，M5 验收硬项）。轻量承诺在终端上的落法：**会话零持久化**——terminal_session 全程内存态、断开即释放（D0 拍板），无会话台账、无写放大。服务对象：单机自托管的管理员（admin）——本模块为 admin 专属，readonly 无任何功能。

本域是「可信」支柱（idea.md §1 目标 3）在最高权限入口上的承载者：会话建立/断开作为安全事件留痕（D1 解释性决策，经 account-auth 审计契约），每条 root shell 的开合均可追溯。

## 第三部分：角色定义（G3）

| 角色 | 英文 | 职责与权限 | 获得方式 |
|------|------|-----------|---------|
| 管理员 | admin | Web 终端唯一使用者：新建会话（默认身份/指定系统用户）、双向交互、主动断开；会话受并发 5/空闲 30min/硬上限 8h 限流约束 | account-auth 初始化/用户管理创建 |
| 只读用户 | readonly | **本模块无任何功能**（ADR-018「禁 Web 终端」整体拒绝）：界面不提供终端入口，越界发起的连接握手在鉴权与角色判定处被拒绝并明确提示边界原因 | 管理员创建并指派 |

访客（未认证操作者）不涉及：终端握手复用面板会话鉴权（R-18/R-02），无面板会话的连接在握手处即被拒绝，无访客触达点。本模块是全项目唯一 readonly 完全无功能的模块（比 ADR-018「禁上传下载」更彻底的整域禁用）；「指定系统用户」不构成第三角色——它是 admin 建立会话时的身份参数，不是面板登录身份（运行身份 ≠ 操作者身份，见第六部分辨析）。

## 第四部分：功能需求明细

> 与 AA（application-arch-terminal.md）11 个功能子模块一一对应；交互类 FR（FR-03~FR-06、FR-10）中会话的建立与断开作为安全事件写审计（D1 解释性决策，经 account-auth 审计契约 OHS）；机制类 FR 自身为「—」（事件随宿主动作记）。

### 4.1 终端接入控制（S-38）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | WS 握手鉴权与角色判定（S-38-01，机制型） | 终端连接握手时复用面板会话鉴权与角色判定（R-18，鉴权载体同 R-02 同源 Cookie 会话）：无有效面板会话→拒绝握手；角色为 readonly→拒绝并明确提示边界原因（ADR-018）；鉴权通过后进入身份确定与并发判定（FR-03/04 + FR-02） | 会话建立事件随本流程落点（见 FR-03/04） |
| FR-02 | 并发准入控制（S-38-02，机制型） | 同一操作者同时存续终端连接数上限 5（ADR-023）：建立新连接时判定，达上限→拒绝并提示先关闭既有会话；配额以「操作者+存续会话集合」计数，断开清理（FR-11）完成时释放；服务端判定不信任前端（R-14） | —（拒绝不记审计，见 N4 口径） |

### 4.2 运行身份选择（S-39）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-03 | 默认身份接入（S-39-01） | 不指定身份时以面板运行用户（通常 root）身份建立终端会话（R-18 默认语义）；身份随会话建立一次确定、会话期间不变更（D1 落定）；PTY 启动经参数数组（R-08 纪律，禁 shell 拼接） | 会话建立记安全事件审计（操作者、运行身份、来源） |
| FR-04 | 指定系统用户接入（S-39-02) | 从系统用户清单（system_user）选择一个**具备登录 shell** 的用户（nologin/false 等非交互 shell 用户不进入清单，D1 落定）；以面板运行用户权限代为启动所选用户的登录 shell（su 语义），**不做密码代输**（D0 建议落定）；清单取数通道 D3 定（待对齐-2）；并发约束与默认身份一致（FR-02） | 会话建立记安全事件审计（含指定身份标识） |

### 4.4 会话生命周期管控（C-11）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-07 | 空闲超时断开（C-11-01，机制型） | 会话连续 30 分钟无操作者输入即自动断开（ADR-023）；判定口径从严：以「无输入」为准，服务端持续输出（如 tail -f）不重置计时（D0 建议落定，FL 附录B 登记）；触发后经统一断开清理（FR-11）执行 | 断开事件随 FR-11 记（原因=idle_timeout） |
| FR-08 | 连接硬上限断开（C-11-02，机制型） | 单个终端连接自建立起最长 8 小时，到时强制断开（ADR-023），与是否活跃无关；需继续使用须重新建立会话（重走 FR-01~04 准入）；触发后经统一断开清理执行 | 断开事件随 FR-11 记（原因=hard_limit） |
| FR-09 | 面板会话失效联动断开（C-11-03，机制型） | 面板登录会话过期/登出/被强制下线时，联动断开该操作者的**全部**终端连接（R-18 反向联动，M5 验收硬项「面板会话过期后终端连接断开」）；触发源为 account-auth 会话失效事件 | 断开事件随 FR-11 记（原因=panel_session_invalid） |

### 4.5 会话断开与资源释放（S-41）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-10 | 用户主动断开（S-41-01） | 操作者关闭终端标签页或会话：立即断开连接，服务器侧 shell 进程随之终止；与全部被动断开路径统一收敛到 FR-11 清理 | 断开事件随 FR-11 记（原因=self_close） |

## 第六部分：状态流转（T2）

本域有单对象状态机（kb 状态机表无本模块行，D0 §5 已确认流转）：**terminal_session：活跃 → 断开**，断开为终态且**对象随之销毁**（内存态不落库，断开即无痕）。

| 当前状态 | 目标状态 | 触发 | 断开原因（terminal_end_reason） | 备注 |
|---------|---------|------|-------------------------------|------|
| 活跃 | 断开（销毁） | 用户主动断开（FR-10） | self_close | 关闭标签页/会话 |
| 活跃 | 断开（销毁） | 空闲 30 分钟无输入（FR-07） | idle_timeout | 输出不重置计时（从严口径） |
| 活跃 | 断开（销毁） | 单连接满 8 小时（FR-08） | hard_limit | 与活跃无关 |
| 活跃 | 断开（销毁） | 面板会话失效联动（FR-09） | panel_session_invalid | 过期/登出/强制下线，全量联动 |
| 活跃 | 断开（销毁） | 网络异常中断（浏览器崩溃/断网） | network_error | 服务侧检测断连后走统一清理 |

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| 「断开」是否存在持久 closed 态 | 断开即销毁（零持久化），closed 无观察窗口；断开事实经断开通知（前端提示）+ 审计事件（account-auth 落库）留痕 | 终态=销毁；与 account-auth session_status{expired,revoked} 落库语义的关键差异 |
| 会话存续集合的增减（建立/断开） | 并发配额的计数语义（FR-02），非单对象状态流转 | 计数语义，非状态机 |
| 并发上限拒绝 | 新连接未建立即被拒（无对象产生），不构成状态流转 | 准入拒绝，非状态机 |
| 「重连」 | 每次重连=新建会话对象（重走 FR-01~04 准入），非原对象状态回退 | 无重连态，对象不可复活 |
| 指定系统用户切换 | 身份随会话建立一次确定（D1 落定），会话期内无「切换身份」动作；换身份=新建会话 | 身份为建立时参数，非运行中状态 |
| 面板会话失效 | 触发源在 account-auth 域（外部事件），本域为联动执行方 | 跨域事件触发，非本域自发流转 |

无审批类状态流转（T3 N/A 的依据）：会话建立与断开均为即时执行，无提交/授权环节；唯一授权边界=角色判定（ADR-018），属访问控制非审批流。

## 第七部分：查询与导出需求（T4/T5）

**查询（T4）**：本模块无台账型列表查询（无会话清单页面，OUT-5）；查询形态仅一类：

| 查询形态 | 筛选维度 | 说明 |
|---------|---------|------|
| 系统用户候选清单查询 | 无筛选（全量候选）；具备登录 shell 的过滤在服务端完成 | 新建终端会话（指定身份）的下拉候选（FR-04）；实况读取不缓存口径 D3 定（待对齐-2）；readonly 不可见（本模块整体禁用） |

**导出（T5）**：无导出需求——零持久化（内存态会话）无可导出集合；本模块不提供任何导出能力。

**被引用关系（T1a）**：

| 被引用能力 | 消费方 | 方式 |
|-----------|--------|------|
| —（无） | — | 本模块为终端消费终模块：不向其他业务模块输出契约（AA 附录B；docker-mgmt 二期「容器内终端」为预期消费方向，不预先建模） |

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：并发上限=每用户 5（ADR-023）；空闲 30 分钟 / 硬上限 8 小时（ADR-023）；零持久化（D0 拍板，无表无 DDL）；单机单操作者量级（自托管场景，全局并发=用户数×5 的量级上限）。未锁定项（工程化缺口，不虚构，D3 补齐）：WS 消息协议形态（待对齐-1）；断连检测粒度与孤儿进程回收时限（待对齐-3）；输出背压（全屏程序高速输出时的缓冲上限）（待对齐-4）。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| 握手无有效面板会话 | 拒绝连接并引导登录（R-18/R-02）；不产生会话对象 |
| readonly 发起终端连接 | 握手角色判定拒绝并明确提示边界原因（ADR-018）；不产生会话对象 |
| 并发达上限（5）发起新连接 | 服务端拒绝并提示先关闭既有会话（ADR-023）；不记审计（第五部分口径） |
| 指定的系统用户不存在 / 无登录 shell | 服务端校验拒绝（R-14）；清单本身已滤（FR-04），直发请求为兜底防线 |
| PTY 进程创建失败（系统资源不足等） | 建立失败如实报错，不产生会话对象、不占用并发配额（配额与对象同生共死） |
| 面板会话中途失效（过期/登出/强制下线） | 联动断开该操作者全部终端连接（FR-09，M5 验收硬项），前端提示会话已失效 |
| 网络异常中断（浏览器崩溃/断网） | 服务侧检测断连后走统一清理（FR-11），回收进程、释放配额；检测粒度与时限 D3 定（待对齐-3） |
| 空闲/硬上限触发时进程不退出（僵死） | 清理流程强制回收 shell 进程（进程组语义），回收失败记审计失败结果（R-03 记「结果」精神） |
| 全屏程序高速输出（如 cat 大文件） | 输出通道缓冲与背压口径 D3 定（待对齐-4）；不因输出洪峰重置空闲计时（口径从严） |
| 断开后重连 | 每次均为新会话（重走准入），无断点续接（无会话录制回放，OUT-2 推论） |
| 审计通道不可用时的会话建立 | 失败从严：会话建立事件写入失败则拒绝建立会话（root shell 暴露面不容无痕，与凭据「只进不出」同从严精神；口径 D3 复核，待对齐-6） |

**N3 业务规则细节**：见第五部分规则汇总全集；三重准入顺序（鉴权→并发→身份）；空闲从严口径；身份一次确定不可变更。

**N4 历史需求**：本模块零持久化 → 面板侧无会话历史台账；会话开合追溯由 account-auth 审计日志查询覆盖（audit_action=security，对象=终端会话/运行身份）；终端 I/O 内容不留痕（无录制回放，OUT-2——内容级留痕既违反零持久化也构成敏感信息风险，明示不做）。
