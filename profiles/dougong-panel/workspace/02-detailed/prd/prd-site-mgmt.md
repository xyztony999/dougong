## 第一部分：业务目标（G1）

为登录运维者提供所在服务器 **存量 nginx 站点的接管与持续治理能力**：服务器上的 nginx 配置本就在那里，面板不重装、不重建、不另起一套运行时——扫描惯例配置目录解析为结构化站点对象（R-15），面板内可视化与源码双模式编辑后经固定安全流程写回原文件（R-06 备份→修改→`nginx -t`→失败自动回滚；R-07 未识别指令以 Raw 节点原文本写回；R-16 其余站点 byte-level 或语义级零影响），并提供三模板新建、站点启停/日志/重载与证书全生命周期治理（ACME HTTP-01/TLS-ALPN 申请、部署、自动续期、存量识别导入，ADR-024 状态机）——这是「接管存量环境」核心卖点（idea.md D5/§3「存量接管（核心壁垒）」）的直接承载，nginxx round-trip 解析器为自研核心资产（ADR-010），round-trip 样本集 ≥ 20 为验收硬项（idea.md §6 M3）。轻量承诺在本域的落法：**站点台账零持久化**——site 为配置文件实时投影、不落库（本 PRD D2 判定，沿 file-manager「不导入不镜像」同哲学），唯一持久化对象是 certificate（落 SQLite：ACME 续期无法从配置文件推导，必须由面板自持续期任务状态）。服务对象：单机自托管的管理员（admin）与只读用户（readonly）——admin 执行全部建站/编辑/启停/证书操作，readonly 查看站点列表/详情、证书状态与访问/错误日志尾部（D0 口径 + ADR-018）。

本域是「可信」支柱（idea.md §1 目标 3）在网站维度的承载者：每一笔配置与证书变更都可追溯到操作者、时间、对象与结果（R-03），且「改不坏」有机制承诺（R-06 四步 + R-16 隔离）——存量服务器最怕的就是面板把现有站点改挂。

## 第三部分：角色定义（G3）

| 角色 | 英文 | 职责与权限 | 获得方式 |
|------|------|-----------|---------|
| 管理员 | admin | 查看能力全集（站点列表/详情/证书清单/日志尾部）+ 全部变更类操作（双模式编辑/三模板建站/启停/重载/证书申请部署删除/续期重试） | account-auth 初始化/用户管理创建 |
| 只读用户 | readonly | 同等查看站点列表/详情、证书清单、访问与错误日志尾部（D0 口径 + ADR-018「全可看」）；建站/编辑/启停/重载/证书操作全部无入口（界面不提供）+ 越界请求被全局边界管控拒绝（account-auth S-03-02） | 管理员创建并指派 |

访客（未认证操作者）不涉及：本模块全部功能位于登录会话之后（R-02），无访客触达点（与 monitoring/service-mgmt/file-manager 同口径）。角色差异边界：全部写类操作（含经安全写入的一切配置/证书文件变更）为 admin 专属；查看类动作不写审计（R-03 语义为「变更」留痕）；自动续期为后台机制，结果记审计。

### 4.1 安全写入治理（S-30）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | 写前快照备份（S-30-01，机制型） | 任何配置写入动作（编辑保存/源码保存/新建/启停/证书部署）执行前，将目标配置文件完整快照备份到 conf.backup/时间戳/ 目录：快照为该文件写入前的原样副本，是失败回滚的唯一恢复点；备份失败则本次写入整体不执行（不进入修改步骤）；快照保留策略（磁盘占用治理）D3 定（待对齐-10） | —（机制；写入本身由宿主 FR 记审计） |
| FR-02 | 写入校验与失败自动回滚（S-30-02，机制型） | 写入后执行 `nginx -t` 配置校验：**通过才进入生效通道**（reload，FR-19）；失败自动恢复 FR-01 写前备份（配置回到写入前原样）并向操作者报错 diff（失败位置与差异），失败的修改不留在配置中（R-06「改不坏」）；`nginx -t` 通过但 reload 失败的处置语义 D3 定（待对齐-8：reload 失败时配置已落盘，回滚 or 保留+报错需显式口径） | —（机制；写入结果由宿主 FR 记审计） |
| FR-03 | 站点隔离写回（S-30-03，机制型） | 写回仅作用于目标站点的来源文件（落点由 FR-07 映射提供），**保证其余站点配置 byte-level 或语义级无变化**（R-16）；与 round-trip 样本集 ≥ 20（解析→生成→再解析语义等价）共同构成「接管不破坏」验收底线（idea.md §6 M3：改某站点反代地址保存 → `nginx -t` 通过且站点生效、其余站点无变化；构造失败修改 → 自动回滚成功） | —（机制） |

### 4.2 nginx 配置存量导入（S-26）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-04 | 配置目录扫描发现（S-26-01，机制型） | 扫描 nginx 惯例配置目录（conf.d / vhost.d / sites-enabled 等）发现全部配置文件与 server 块，形成待解析清单；扫描触发时机与频率（启动全量/操作时按需/文件监听）D3 定（待对齐-2）；nginx 未检出时模块呈空态引导而非报错（本域推导：R-15 发现哲学，无 nginx 即无可接管对象） | —（查看类机制） |
| FR-05 | 指令树解析（S-26-02，机制型） | 对发现的配置文件做词法扫描（处理引号、变量、注释、正则 location 等复杂语法）构建通用指令树；解析不了的指令/块保留为 **Raw 节点携带原文本**（R-07 解析侧前提）；解析器为 nginxx 自研核心资产（ADR-010），round-trip 保真（解析→生成→再解析语义等价）以样本集 ≥ 20 验收 | —（查看类机制） |
| FR-06 | server 块站点提取（S-26-03，机制型） | 从指令树提取 server 块为结构化站点对象：域名（server_name）、监听端口（listen）、根目录（root）、证书引用（ssl_cert）、location 列表、反代上游（proxy_pass）、enabled 状态等；一个 server 块对应一个站点对象；提取结果即站点列表数据源（零站点台账，第六部分辨析） | —（查看类机制） |
| FR-07 | 写回落点登记（S-26-04，机制型） | 为每个导入站点登记「站点 → 来源文件」映射；多配置目录并存时（conf.d 与 sites-enabled 同时启用等场景）按映射消重——一个站点只登记一个写回落点（原文件）；编辑写回落到原文件（⚠️A13，D0 待细化落定）；同域名 server 块在多处重复定义的呈现与提示口径 D3/D4 定（待对齐-2 附带） | —（机制） |

|------|------|-------------|------|
| FR-17 | 站点启停（C-07-01） | 通过 enabled 开关切换站点启用 ⇄ 停用（kb 状态机）：开关动作经安全写入流程（FR-01~03）修改来源文件启停配置段，校验通过后经 FR-19 reload 生效；**停用≠删除**——保留配置与证书引用（OUT-6：站点删除不在 MVP）；启停结果反映到列表 enabled 列 | 记审计（R-03） |
| FR-18 | 访问与错误日志尾部查看（C-07-02） | 查看站点访问日志与错误日志尾部：日志类型 site_log_type（access/error）；日志路径经解析 server 块 access_log/error_log 指令获得，无该指令时回退 nginx 默认路径（⚠️A15，D0 待细化落定）；读取规格（行数/字节上限、轮转文件处理）D3 定（待对齐-7）；两角色同等可用（D0 口径：readonly 查看日志尾部） | —（查看类） |
| FR-19 | nginx 重载（C-07-03） | 用户主动触发的 nginx 平滑 reload：使已通过校验写入的配置生效（不断连接）；与 FR-02 的生效环节共用同一 reload 通道；重载成功/失败原因如实反馈（不虚构成功）；reload 失败处置待对齐-8 | 记审计（R-03） |

### 4.7 证书签发与部署（C-08）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-20 | ACME 证书申请 HTTP-01（C-08-01） | 以 HTTP-01 挑战为站点域名向 ACME CA（Let's Encrypt 等）申请证书：需域名可经 80 端口 HTTP 访问完成挑战验证；发出后证书入 pending，签发成功转 valid、失败转 renew_failed 并呈现失败原因（ADR-024 状态机）；挑战方式标记 acme_challenge=http_01；**ACME 是面板唯一的外部网络请求**（R-09 除外条款，经 ACL 集成，见第九部分）；CA 账户密钥存储与 CA 环境（生产/staging）选择 D3 定（待对齐-4） | 记审计（R-03） |
| FR-21 | ACME 证书申请 TLS-ALPN（C-08-02） | 以 TLS-ALPN 挑战申请证书：经 443 端口 TLS 握手内完成挑战验证，适用于仅 HTTPS 暴露的站点；状态流转同 FR-20；挑战方式标记 acme_challenge=tls_alpn；DNS-01 不做（OUT-2） | 记审计（R-03） |
| FR-22 | 证书部署（C-08-03） | 将面板托管的有效证书部署到目标站点：修改站点配置的证书引用（ssl_cert 指向面板托管路径，⚠️A16），经安全写入流程（FR-01~03）写回并 reload 生效；建立「证书 ⇄ 站点」引用关系——为续期替换（FR-23）与删除约束（FR-27）提供依据；证书存储路径常量 D3 定（⚠️A16 建议值 /etc/dougong/certs/） | 记审计（R-03） |

### 4.8 证书续期治理（C-09）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-23 | 自动续期调度（C-09-01，机制型） | 后台自动续期任务（子流程，I/O 契约见 domain-model.md 第四部分）：证书到期前 30 天转 expiring_soon（ADR-024）触发续期——按原挑战方式（acme_challenge）发起，成功后**替换托管证书文件内容（原路径替换，⚠️A16）→ 重新部署引用站点 → 状态回 valid**；失败转 renew_failed + 失败原因；到期仍未成功转 expired；同域名重复申请防重策略 D3 定（待对齐-5） | 续期结果记审计（R-03） |
| FR-24 | 续期失败处理与手动重试（C-09-02） | renew_failed 排障与恢复：呈现失败原因（挑战不通/CA 拒绝/速率限制等）；支持手动重试（进入 FR-23 同一调度通道）：成功回 valid 并替换重部署，到期仍未成功转 expired（ADR-024）；保证站点 TLS 不因续期失败静默中断 | 记审计（R-03） |

### 4.9 证书纳管与清理（C-10）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-25 | 存量证书识别导入（C-10-01，机制型） | 存量导入管线自动识别站点配置 ssl_cert 证书引用，将已有证书纳入面板管理：来源标记 cert_source=imported，**保留源站原路径引用不迁移**（⚠️A16）；与 ACME 签发证书（cert_source=acme）在同一证书清单统一呈现；随站点导入自动发生（R-15 同哲学），无独立入口；imported 证书元数据（有效期等）的刷新机制 D3 定（待对齐-3） | —（机制；纳管结果经清单呈现） |
| FR-26 | 证书清单查看（C-10-02） | 查看全部纳管证书：域名列表、签发者（issuer）、有效期、来源（acme/imported）、当前状态（ADR-024 状态机）；为证书排障（renew_failed 定位）与站点列表证书状态列（FR-08）的数据源；来源/状态筛选与排序口径 D3 定（待对齐-3）；两角色同等可用（ADR-018） | —（查看类） |
| FR-27 | 证书删除（C-10-03） | 删除面板托管证书及其续期任务：仍有站点引用时**提示先解除部署引用**（解释性决策：防误删致站点 TLS 失效；解除交互与自动化程度 D3/D4 定，待对齐-9）；imported 来源证书的删除仅解除面板管理关系，**不删除源站原证书文件**（⚠️A16：存量证书文件归站点原配置所有） | 记审计（R-03） |

## 第六部分：状态流转（T2）

本域有 **2 个状态机**：certificate 六状态机（持久化，ADR-024 拍板）与 site enabled ⇄ disabled（配置侧状态投影，kb 拍板）。

**证书状态机**（cert_status，ADR-024）：

| 当前状态 | 目标状态 | 触发 | 备注 |
|---------|---------|------|------|
| pending | valid | ACME 签发成功（FR-20/21） | 可部署（FR-22） |
| pending | renew_failed | ACME 申请失败（挑战不通/CA 拒绝） | 呈现失败原因，可手动重试 |
| valid | expiring_soon | 到期前 30 天（自动，ADR-024 阈值固定） | 触发自动续期调度（FR-23） |
| expiring_soon | valid | 自动续期成功（FR-23） | 替换托管文件（原路径）→ 重新部署引用站点 |
| expiring_soon | renew_failed | 自动续期失败（FR-23） | 呈现失败原因，可手动重试（FR-24） |
| expiring_soon | expired | 到期仍未续期成功 | 终态：站点 TLS 失效风险，需重新申请 |
| renew_failed | valid | 手动重试成功（FR-24） | 替换重部署同自动续期 |
| renew_failed | expired | 到期仍未成功 | 终态，同上 |

imported 来源证书以 valid 态入册（FR-25），无续期通道，沿 valid → expiring_soon → expired 自然流转。

**站点启停状态机**（site_enabled，kb 拍板；配置侧状态投影）：

| 当前状态 | 目标状态 | 触发 | 备注 |
|---------|---------|------|------|
| enabled | disabled | 面板停用操作（FR-17）经安全写入 + reload | 停用保留配置与证书引用（停用≠删除） |
| disabled | enabled | 面板启用操作（FR-17）同上 | 同上 |

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| 「6 状态机」计数 vs 枚举命名 5 状态 | ADR-024 文本称「6 状态」，其枚举命名与 kb 状态机表均为 5 个命名状态（pending/valid/expiring_soon/expired/renew_failed）；本 PRD 按枚举命名与上表流转执行，「第 6 状态」语义待 ADR-024 侧澄清——如为申请中（processing）等中间态需修订 ADR-024 并同步三文档+枚举池 | 口径差异已登记（D1 AA 附录B / 本 PRD 第九部分），不阻塞建模 |
| site_type（static/php_fpm/reverse_proxy） | 创建时的模板来源标记，创建后不随生命周期流转（无状态迁移语义） | 来源标记，非状态机 |
| cert_source（acme/imported） | 证书的获取来源维度，一经确定不变（不随状态流转） | 来源维度，非状态机 |
| 站点启停在途（点击后未 reload 完成） | 一次性动作执行过程，终态反馈即消亡（与 service-mgmt 操作任务同构） | 过程数据（P7），非状态机 |
| 安全写入四步（备份→修改→校验→回滚） | 同步机制链路，各步无独立持久化生命周期状态（与 file-manager 回收站入站登记同口径） | 机制链路，非子流程非状态机 |
| Raw 块「保留/丢失」 | Raw 内容保全为序列化保证（R-07），无状态语义 | 机制承诺，非状态机 |
| 证书部署关系（证书⇄站点） | 引用关系随部署/解除建立与撤销，非独立状态机；引用清单为关系数据 | 关联语义，非状态机 |
|续期任务执行态（排队/执行中） | 子流程单次执行的过程状态，执行完即消亡、结果写回 certificate 与审计（与分块上传任务状态同口径） | 过程数据（P7） |

无审批类状态流转（T3 N/A 的依据）：本域操作为管理员即时执行，无提交/授权环节；证书申请的 pending 是外部 CA 的异步签发过程（非审批）；唯一授权边界=角色判定（ADR-018），属访问控制非审批流。

## 第七部分：查询与导出需求（T4/T5）

**查询（T4）**：本域查询形态为四类：

| 查询形态 | 筛选/排序维度 | 说明 |
|---------|-------------|------|
| 站点列表查询 | enabled 筛选 + 排序口径 D3 定（待对齐-2） | 扫描投影全量站点（单机站点数十量级）；证书状态列为同域 certificate 数据只读消费；两角色同等 |
| 站点详情单点定位 | 站点标识（来源文件内 server 块定位，稳定键形态待对齐-1） | 编辑/启停/日志/部署的寻址前置读取 |
| 证书清单查询 | 来源（acme/imported）与状态（cert_status）筛选 + 排序口径 D3 定（待对齐-3） | certificate 持久化清单；renew_failed 排障入口；两角色同等 |
| 站点日志尾部查询 | 站点标识 + 日志类型（site_log_type：access/error）+ 读取规格参数（行数/字节上限，待对齐-7） | 尾部读取非全文检索；两角色同等 |

**被引用关系（T1a）**：

| 被引用能力 | 消费方 | 方式 |
|-----------|--------|------|
| —（现阶段无） | — | 本模块现阶段不向其他业务模块输出契约；cron-backup（备份源=站点目录，kb backup_job）等后续模块如引用站点对象/根目录，另行在对应模块 D2 定义（预期消费方向，本 PRD 不预先建模） |
| 消费方视角 | account-auth | 本模块消费其审计写入（R-03）、会话鉴权与只读边界（R-02/ADR-018）契约，见第九部分跨域集成 |
| 消费方视角 | 外部 ACME CA（Let's Encrypt 等） | 本模块经 ACL（lego 封装）发起证书申请/续期（R-09 唯一外呼例外），见第九部分 |

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：round-trip 样本集 ≥ 20 个真实复杂配置（含 if/try_files/正则 location/变量/map）全部通过为验收硬项；单机存量站点数十量级、配置文件单文件 KB 级；证书清单量级小（低频签发积累）；零站点台账（唯一持久化=certificate）。未锁定项（工程化缺口，不虚构，移交 D3/D4）：站点稳定标识键形态（待对齐-1）；扫描触发时机与列表刷新机制（待对齐-2）；certificate 表结构与 imported 元数据刷新（待对齐-3）；ACME 账户密钥存储与 CA 环境（待对齐-4）；同域名重复申请防重（待对齐-5）；源码编辑冲突保护（待对齐-6）；日志尾部读取规格（待对齐-7）；reload 失败处置（待对齐-8）；证书删除解除引用交互（待对齐-9）；conf.backup 快照保留策略（待对齐-10）。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| 编辑保存后 `nginx -t` 失败 | FR-02 自动恢复写前备份（配置回到原样）+ 报错 diff；失败修改不留在配置中（R-06）；M3 验收显式覆盖（构造失败修改 → 回滚成功） |
| `nginx -t` 通过但 reload 失败 | 处置语义 D3 定（待对齐-8：配置已落盘，回滚 or 保留+报错）；失败原因如实呈现，不虚构成功 |
| 面板外修改配置（shell/file-manager 通道/外部工具） | 配置文件是唯一事实源：扫描感知后列表自动反映（待对齐-2 刷新机制）；编辑基线过期的冲突保护待对齐-6；file-manager 通用编辑通道与 R-06 的协同不在本模块范围（D1 AA 附录B 已声明，如需约束在对应模块或 Gate 处置） |
| conf.d 与 sites-enabled 同域名 server 块重复定义 | 按 FR-07 映射消重登记写回落点；重复定义的呈现与提示口径 D3/D4 定（待对齐-2 附带）；不静默丢弃（接管不破坏） |
| ACME 挑战失败（80/443 不通、域名未解析、防火墙拦截） | 证书转 renew_failed（pending 阶段）并呈现失败原因（FR-20/21）；不虚构签发结果 |
| ACME CA 速率限制/服务不可用 | 失败原因如实呈现；手动重试由操作者决策（FR-24）；自动续期失败转 renew_failed 不无限重试（重试节奏 D3 定，随待对齐-4/5 一并） |
| 续期成功但重部署失败 | 托管文件已替换、状态回 valid，部署失败原因如实呈现并支持重试部署（部署为幂等动作）；不回滚续期本身 |
| 证书文件被外部替换/删除（面板外干预） | imported 证书以源站文件实况为准（元数据刷新机制待对齐-3）；acme 托管证书文件属面板所有，外部删除在续期/部署时暴露并如实报错 |
| 删除仍被站点引用的证书 | 提示先解除部署引用（FR-27/待对齐-9）；不静默删除 |
| PHP-FPM pool 不存在或未检出 | FR-15 如实提示无可用 pool（不虚构候选，不引导安装 PHP——OUT-7） |
| nginx 未安装/未检出 | 模块空态引导（FR-04 本域推导）：提示无可接管 nginx，不报错不虚构列表 |
| 写回目标来源文件被外部删除 | 写入失败如实报错（文件不存在），不自动重建文件（接管不重建）；扫描刷新后站点从列表消失 |
| 域名/端口/上游地址非法 | 服务端校验拒绝（R-14）：域名形态、端口范围、上游 URL 形态、编辑内容完整性 |
| readonly 越界发起任何变更 | 全局边界管控拒绝并提示边界原因（account-auth S-03-02，ADR-018）；界面本就无入口 |
| 重复点击启停/重载 | 前端在途禁用（D4 呈现）+ 服务端动作语义幂等（重复启用=幂等生效，重复 reload 幂等）；不产生中间态残留（R-06 每次写入独立备份链） |
| 空站点列表 / 空证书清单 | 返回空列表 + 引导（建站/申请证书），非错误 |

**N3 业务规则细节**：见第五部分规则汇总全集；补充幂等语义——启停为幂等开关（重复执行终态一致）；reload 幂等（重复重载无副作用）；续期重试幂等（ADR-024 重试语义，成功即 valid）；证书部署幂等（重复部署同一证书引用不变）；删除入站对已不存在的证书报错如实（不做静默成功）。

**N4 历史需求**：面板侧无配置变更历史台账（零站点台账推导）；操作追溯由 account-auth 审计日志查询覆盖（audit_action=change，对象=站点/证书）；**conf.backup/时间戳/ 快照目录即配置变更的原样历史载体**（保留策略待对齐-10）；证书续期历史由审计留痕（成功/失败各记一条），不做独立续期历史表。
