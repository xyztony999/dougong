## 第一部分：业务目标（G1）

为登录运维者提供所在服务器 **已有 Docker daemon 的接管式容器治理能力**：连接本机既有 daemon（`/var/run/docker.sock`，官方 Go SDK），已有容器、镜像、卷、网络与 Compose 项目自动纳入管理——**接管而非重装**（R-12/R-15），未安装 Docker 时以安装引导页呈现而非报错（§6 容器管理验收硬项：「已运行多个容器与 Compose 项目的服务器上安装面板 → 全部自动识别（无需手动登记）→ 启停/重启/日志查看/镜像拉取删除全部可用；未安装 Docker 的机器展示安装引导而非报错」）。这是「接管存量环境」核心卖点（idea.md D5/§3）在容器侧的承载，并与 1Panel 应用商店路线明确切割——**只管理已有环境，不做应用商店/一键部署**（R-12，idea.md §8：与 DPanel 同哲学、补齐宿主机建站能力后卖点合一）。Compose 治理经容器 label 自动识别项目并以 `docker compose` CLI 参数数组方式操作（R-13/ADR-013，经 label 定位工作目录与配置文件）。轻量承诺在本域的落法：**零容器/镜像/卷/网络/Compose 台账**——五类对象均为 daemon 实况投影、不落库（kb 拍板口径，本 PRD D2 沿用，与 site 零站点台账/database-mgmt 零库用户台账/firewall 零规则台账同哲学），面板外经 docker CLI 的变更如实反映。服务对象：单机自托管的管理员（admin）与只读用户（readonly）——admin 执行全部生命周期操作与资源治理，readonly 查看全部清单与日志（ADR-018「全可看」，日志属查看类）。

本域的安全约束递次为：接管不破坏（R-12 只接管不重装、删除约束以 daemon 拒绝为最终权威、MVP 无强制删除，第一约束）、R-08 命令参数数组纪律（Compose CLI 调用防注入，第二约束）、R-03 全变更审计（第三约束）。

| 角色 | 英文 | 职责与权限 | 获得方式 |

访客（未认证操作者）不涉及：本模块全部功能位于登录会话之后（R-02），无访客触达点（与 monitoring/service-mgmt/site-mgmt/database-mgmt/terminal/firewall 同口径）。角色差异边界：全部写类操作为 admin 专属；查看类动作不写审计（R-03 语义为「变更」留痕）；全部变更动作写审计（对象四要素入审计载荷，无凭据类敏感值——对象参数即业务内容）。

### 4.1 Docker daemon 接管（S-45）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | daemon 探测与连接（S-45-01，机制型） | 自动探测本机 Docker daemon（`/var/run/docker.sock`）并建立连接、判定可用性：探测结论=接管判定值（docker_daemon_state：available/unavailable）+ daemon 版本（伴随信息，识别能力代际用、不参与业务判定）；探测为只读行为，进入容器业务时被动自动执行，无需用户发起；本域全部读取与操作经该唯一通道（远程 daemon 接入 OUT-6，本机 sock 唯一）；探测实现口径（sock 存在性 vs ping）与探测时机（进入页/手动刷新组合）D3 定（待对齐-8）；接管结论呈现于容器视图页头（宿主呈现，机制型覆盖见 FL 附录A） | —（机制；结论随页头呈现） |
| FR-02 | 未装 Docker 安装引导（S-45-02） | 接管判定为 unavailable 时容器业务以安装引导页呈现：说明本机未检测到可用的 Docker daemon、指引安装 Docker 后再使用（含官方安装途径说明，**不提供代为安装入口**，OUT-9）；容器业务整体不可用，**不得将「未安装」呈现为「无容器」空列表**（语义区分：未装≠无容器，空列表会误导操作者误判环境状态——与防火墙「无后端≠无规则」同判，D1 FL 附录C 解释）；两角色同视角（readonly 亦只见提示，无可操作内容）；检测频率口径（每次进入均探测 vs 会话内缓存）D3 定（待对齐-8） | —（查看类降级视图） |

### 4.3 容器生命周期管理（C-12）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-06 | 容器启停与重启（C-12-01） | 对指定容器执行启动（start，仅 stopped 态开放）、停止（stop，running/paused 态开放——对 paused 等效先恢复后停止，daemon 语义保证）、重启（restart，running/paused 态开放——stopped 容器经「启动」达成，restart 入口不对其开放）；**入口按动作矩阵随当前态开放/禁用并提示原因**（BA 附录B.2 唯一口径）；动作与当前态不匹配时服务端校验拒绝并明确报错、不盲目下发（R-14，报错口径 D3 定待对齐-3）；操作即时生效、无草稿/审批环节，结果经列表刷新确认；admin 专属（ADR-018） | 记审计（R-03） |
| FR-07 | 容器暂停与恢复（C-12-02） | 对指定容器执行暂停（pause，仅 running 态开放——进程冻结、容器与资源保留）与恢复（unpause，仅 paused 态开放）；为 ADR-025 拍板动作集组成部分（排障冻结现场场景，区别于多数面板只做启停）；矩阵约束与服务端校验同 FR-06；admin 专属 | 记审计（R-03） |
| FR-08 | 容器删除（C-12-03） | 对指定容器执行删除：**交互确认后执行**（确认文案含容器名与镜像信息）；**删除入口仅对 stopped 态开放**，running/paused/过渡态禁用并提示先停止（**MVP 无强制删除语义**，D1 口径-4——防误删运行中服务，与 R-12「接管而非破坏」一致）；删除解除该容器对镜像/卷/网络的引用（FR-11/13/15 可达性前提之一，引用存在性以 daemon 拒绝为最终权威判定）；容器不存在时如实报错（面板外已删，不静默成功）；admin 专属 | 记审计（R-03） |

## 第六部分：状态流转（T2）

本域 **无面板自持业务状态机**：容器状态机（kb 状态机表容器行、ADR-025）为 **daemon 实况的面板动作映射**——状态事实源在 daemon 侧，面板零持久化不持有状态字段，状态读取为实况投影、动作下发为状态迁移请求；映射矩阵（BA 附录B）即状态相关接口的设计依据。

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| 容器核心三态（running/stopped/paused） | daemon 实况按映射矩阵归并的呈现值（container_status 枚举），面板不持有、随读取整值刷新 | 映射值属性，非面板自持状态机 |
| 过渡态（restarting/removing） | daemon 瞬时 API 态的原始值透传，操作入口禁用，操作完成/失败后自然回落三态 | 透传属性，非状态机 |
| created/exited/dead → stopped 归并 | 三类 daemon 终/初态在面板动作语义上等价（同一动作可用面），按矩阵归并呈现 | 映射归并口径（D1 口径-1），非状态流转 |
| 动作 × 状态可用性矩阵 | 动作入口随当前映射态约束（入口开放/禁用 + 服务端校验拒绝），为派生的可用性语义 | 可用性矩阵，非状态机 |
| 镜像/卷/网络/Compose 项目存在/不存在 | 对象=daemon 侧记录的存在与删除，无状态字段流转（与 firewall「规则有无即状态」同判） | 记录存在语义，非状态机 |
| Compose 项目运行态（容器组汇总呈现） | 项目无自有状态字段，运行态=其容器清单实况的读取时汇总派生值 | 派生属性，非状态机 |
| Compose 定位失败（工作目录/配置文件缺失） | 识别时判定结论（操作可用性依据），整值刷新，无流转触发 | 判定态，非状态机 |
| daemon 接管结论（available/unavailable） | 每次探测整值刷新的判定值（docker_daemon_state 枚举） | 判定值属性，非状态机（与 firewall_backend/instance_conn_state 同构） |
| 启停/拉取/up-down 在途 | 一次性动作执行过程，终态反馈即消亡（与 service-mgmt 操作任务/firewall 双写在途同构） | 过程数据（P7），非状态机 |
| 未装引导呈现 | 接管结论为 unavailable 时的降级视图 | 视图降级语义，非状态机 |

无审批类状态流转（T3 N/A 的依据）：本域操作为管理员即时执行，无提交/授权环节；删除的交互确认为**交互层危险操作防护**（卷删除的数据销毁确认尤其如此），属操作前置警示语义、非他人授权的审批流——与「确认」概念对齐（d2 分册 2.5：操作人自己确认事实，不需要申请模型）。

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：量级——容器/镜像/卷/网络各数十~百条、Compose 项目个位~十位（单机量级）；日志尾部默认 500 行；零持久化（零台账，无 DDL 无数据侧设计）；§6 容器管理验收硬项（多容器与 Compose 项目服务器上自动识别 + 启停/重启/日志/镜像拉取删除可用 + 未装展示引导；idea.md §6 该验收章节标 M6、对应 §4.1 模块 M9，编号差异沿材料）。未锁定项（工程化缺口，不虚构，移交 D3/D4）：清单字段集与筛选分页（待对齐-1）；日志接口形态（待对齐-2）；动作-状态校验报错口径（待对齐-3）；拉取进度反馈（待对齐-4）；Compose CLI 组装与定位失败错误码（待对齐-5）；资源快照统计口径（待对齐-6）；daemon 拒绝原因映射（待对齐-7）；探测实现与时机（待对齐-8）。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| daemon 不可用（未装/sock 不可达/daemon 停止） | 整体降级为安装引导页（FR-02），容器业务不可用，不呈现「无容器」空列表、不报错（接管结论区分未装与运行中不可达的呈现口径 D3 随待对齐-8 定） |
| 操作时容器已被面板外删除（清单与实况漂移） | 如实报错（不静默成功）；刷新列表后消失（实况是唯一事实源） |
| 动作与当前状态不匹配（如对 running 容器发起 start） | 服务端校验拒绝并明确报错（R-14，报错口径待对齐-3），不盲目下发 daemon；入口本就按矩阵禁用（防直调） |
| 容器处于过渡态（restarting/removing）时操作 | 操作入口禁用；直调被服务端校验拒绝；操作完成/失败后回落三态 |
| 删除被引用镜像 / 被挂载卷 / 被接入网络 | daemon 拒绝并如实呈现拒绝原因（不前置推导、不强制绕过，D1 口径-4；原因映射待对齐-7） |
| 删除预定义网络（bridge/host/none 等） | daemon 拒绝，如实呈现拒绝语义（不提供绕过） |
| Compose 定位失败（工作目录已移除/配置文件缺失） | up/down/restart/logs 项目级操作不可用并提示缺失原因（呈现 label 记录路径）；项目内容器经 FR-06~08 逐个操作兜底（D1 口径-2） |
| Compose 操作期间 daemon 异常/CLI 失败 | CLI 执行结果与 stderr 如实反馈（不虚构成功）；无持久化故无回滚语义（daemon/Compose 原子性由其自身保证） |
| 日志跟踪期间容器被删除或停止 | 日志流终止并如实提示原因（不静默断流） |
| 镜像拉取失败（tag 不存在/网络不通/仓库限流） | 失败原因如实反馈（daemon 错误透传口径待对齐-4）；不产生清单残留（拉取完成才进入清单） |
| 空清单（daemon 可用且无容器/镜像/卷/网络/项目） | 返回空列表（区别于未装降级），非错误 |
| readonly 越界发起任何变更操作 | 全局边界管控拒绝并提示边界原因（account-auth S-03-02，ADR-018）；界面本就无入口 |
| 镜像名称:tag 等参数非法 | 服务端校验拒绝（R-14），不进入 daemon 执行 |
| 审计写入失败（操作已生效） | 操作生效事实如实反馈；审计失败告警不静默（同事务口径经 account-auth OHS，异常处置沿其契约） |

**N3 业务规则细节**：见第五部分规则汇总全集；补充幂等语义——生命周期动作非幂等（动作与当前态不匹配即拒绝，不静默成功）；删除类非幂等（对象不存在报错，不静默成功）；拉取幂等（同 tag 重复拉取按 daemon 层叠/覆盖语义如实反馈）；全部读取无副作用（纯投影）；确认交互不记忆（每次删除/涉险操作独立确认）。

**N4 历史需求**：面板侧无对象变更历史台账（零台账推导——事实源在 daemon，daemon 自身无面板语义的历史，不虚构）；操作追溯由 account-auth 审计日志查询覆盖（audit_action=change，对象=容器/镜像/卷/网络/Compose 项目，变更内容=对象标识与动作）；日志历史留存不做（OUT-10，daemon 实况流）；无独立历史表需求。
