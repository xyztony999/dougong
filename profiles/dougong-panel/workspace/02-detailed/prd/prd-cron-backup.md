## 第一部分：业务目标（G1）

为登录运维者提供所在服务器 **既有 cron 定时任务的接管治理** 与 **站点目录 + 数据库的定时备份能力**：计划任务线接管 root crontab（系统已有任务自动纳入、如实投影，R-15「接管不要求重装」精神在本域的落法），提供任务增删改、表达式校验与执行预览、执行日志尾部、面板代执行的手动触发；备份线提供 backup_job 定义（源=站点目录〔联动站点清单〕+ 数据库〔联动实例/库清单、复用 database-mgmt 已存凭据〕、目标=本地目录/rsync 远程、保留份数、调度）、面板内置调度器定时执行与立即执行、backup_run 执行记录（running → success / failure，ADR-016）、产物下载与按保留份数轮转清理（R-11）——备份产物手动下载恢复（自动还原 MVP 不做）。轻量承诺与接管哲学在本域的落法：**cron_job 零任务台账**（crontab 文件是唯一事实源，面板侧备注与来源标注以 crontab 注释行承载，面板外编辑如实反映——D2 判定，与 site 零站点台账/firewall 零规则台账同哲学）+ **备份调度与系统 cron 解耦**（面板内置调度器不写 crontab，D1 落定口径，避免双写一致性）。服务对象：单机自托管的管理员（admin，全部变更与触发、产物下载）与只读用户（readonly，任务/历史/日志查看，ADR-018）。

本域安全约束递次为：R-08 命令参数数组纪律（防注入，第一约束——含手动触发「请求仅携带任务标识、命令取自 crontab 原文」的边界口径，见 FR-06）、R-03 全变更与手动触发审计（第二约束）、凭据不落本域（数据库备份取数经 database-mgmt 契约用其已存凭据，凭据值不进入本域——第三约束，沿 ⚠️A18 同精神）。

## 第三部分：角色定义（G3）

| 角色 | 英文 | 职责与权限 | 获得方式 |
|------|------|-----------|---------|
| 管理员 | admin | 查看能力全集（任务列表/执行日志/备份任务/历史/详情）+ 全部变更与触发动作（计划任务增删改/手动触发、备份任务增删改/立即执行）+ 产物下载 | account-auth 初始化/用户管理创建 |
| 只读用户 | readonly | 同等查看计划任务列表（含系统预置位视角）与执行日志、备份任务清单、备份历史与执行详情（ADR-018「全可看」）；全部变更/触发/下载无界面入口 + 越界请求被全局边界管控拒绝并提示原因（account-auth S-03-02） | 管理员创建并指派 |

访客（未认证操作者）不涉及：本模块全部功能位于登录会话之后（R-02），无访客触达点（与 monitoring/service-mgmt/file-manager/site-mgmt/database-mgmt/firewall/docker-mgmt 同口径）。角色差异边界：全部写类与触发类操作为 admin 专属；查看类动作不写审计（R-03 语义为「变更与手动触发」留痕）；产物下载对 readonly 不开放（ADR-018 禁上传下载，下载属数据取出，与 file-manager 下载/审计导出同判——D1 FL 附录B 解释性决策）。

### 4.1 计划任务管理（S-51）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | 计划任务列表查看（S-51-01） | 只读呈现 root crontab 全部任务：cron 表达式、命令、面板侧备注、来源标注（cron_source：panel 面板创建 / existing 系统既有——以面板标记注释存在与否判定，承载口径见第六部分辨析）；同屏只读展示系统预置位清单（`/etc/cron.d/` 与 `/etc/cron.hourly\|daily\|weekly\|monthly`，呈现粒度 D3 定待对齐-2）；面板外变更（手工编辑 crontab）如实呈现（实况投影，零任务台账）；两角色同等可用（ADR-018）；管理员可从列表发起创建/编辑（FR-02）、删除（FR-03）、手动触发（FR-06），readonly 无操作入口；列表排序口径 D3 定（待对齐-1） | —（查看类） |
| FR-02 | 计划任务创建与编辑（S-51-02） | 在 root crontab 新建任务或编辑既有任务：录入表达式与命令（及备注），提交前经表达式校验（FR-04 内嵌）；面板创建/编辑写回时自动附加/维护面板标记注释行（来源标注与备注的注释行承载，D2 判定，语法 D3 定待对齐-1）；编辑系统既有任务保留其来源语义（标记缺失即 existing）；服务端校验表达式合法性与命令非空（R-14）；admin 专属（ADR-018） | 记审计（R-03） |
| FR-03 | 计划任务删除（S-51-03） | 对面板管理的任务执行删除：交互确认后从 root crontab 移除（含其面板标记注释行）；系统预置位任务不提供删除入口；任务不存在时如实报错（面板外已删，不静默成功）；admin 专属 | 记审计（R-03） |
| FR-04 | cron 表达式校验与执行预览（S-51-04，机制型） | 对输入表达式做合法性解析（五段式 cron 语法，支持的标准宏如今写法范围 D3 定待对齐-3），并预览未来若干次执行时间（预览次数档位 D3/D4 定）；无副作用纯计算（响应即消亡）；内嵌于创建/编辑表单（FR-02 前置），无独立菜单（机制型覆盖见 FL 附录A） | —（纯计算） |
| FR-05 | 计划任务执行日志查看（S-51-05） | 只读查看系统 cron 执行日志的尾部片段（任务触发记录），用于定位任务是否按期执行；日志来源按发行版适配（journalctl -u cron / /var/log/cron，技术实现归适配器）；尾部行数档位与刷新口径 D3 定（待对齐-4）；两角色同等可用（查看类，ADR-018） | —（查看类） |
| FR-06 | 计划任务手动触发（S-51-06） | 对面板管理的任务由面板代为立即执行一次（不等下一个调度点）：**请求仅携带任务标识，命令文本取自 crontab 记录原文、按 shell 语义代执行**（cron 任务的执行语义本身即 shell；R-08 禁的是「拼接用户输入构造命令」，此处命令为存量配置原文且不经请求参数拼接——不破纪律，命令文本不接受请求传入）；以面板运行用户（任务属主）身份执行，受超时控制约束（时长 D3 定待对齐-5）；超时按失败终态反馈（原因=timeout），不扩状态枚举；执行结果与输出呈现给操作者（输出不持久化，响应即消亡）；系统预置位任务不提供手动触发；admin 专属 | 记审计（R-03，含执行结果；输出摘要入审计载荷的口径 D3 定） |

### 4.2 备份任务管理（S-52）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-07 | 备份任务列表查看（S-52-01） | 只读呈现全部备份任务：名称、备份源构成（站点目录项/数据库项）、目标类型（backup_target_type）与目标、保留份数、调度表达式、最近一次执行结论（自 backup_run 按 job 归组取最新回显，running 呈现进行中）；任务清单为立即执行（FR-11）、历史查看（FR-12）、编辑删除（FR-09）的宿主入口；两角色同等可用（ADR-018）；admin 可从清单发起变更与立即执行，readonly 无入口 | —（查看类） |
| FR-08 | 备份任务创建（S-52-02） | 定义备份任务四要素：①源清单——站点目录项（联动 site-mgmt 站点清单选取，保存为目录路径值快照）与数据库项（联动 database-mgmt 实例/库清单选取，保存为 db_instance 引用 + 库名），可多选组合（backup_source_type：site_dir/database）；②目标——本地目录路径或 rsync 远程地址（backup_target_type：local/rsync）；③保留份数（正整数，上限档位 D3 定）；④调度——cron 表达式（复用 FR-04 校验与预览，D2 口径-2）；名称唯一性校验（R-14，冲突语义 D3 定）；服务端校验目标地址/路径合法性；admin 专属 | 记审计（R-03） |
| FR-09 | 备份任务编辑与删除（S-52-03） | 编辑：整体替换任务定义（源清单/目标/保留份数/调度，值对象替换语义）；变更后下一个调度周期按新定义执行。删除：交互确认后删除任务定义，**不连带清理既有产物与历史记录**（backup_run 为独立执行事实，留存至按保留份数自身轮转——ADR-016 独立实体的自然推论，D1 FL 附录B）；admin 专属 | 记审计（R-03） |

### 4.3 备份执行与历史管理（C-13）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-10 | 备份定时调度执行（C-13-01，机制型） | 面板内置调度器随面板进程运行（独立于系统 cron、不写 crontab，D1 落定口径），按各任务调度表达式自动触发备份执行：创建 backup_run（触发方式 backup_trigger=cron、状态 running），执行备份源打包（站点目录 tar 归档、数据库 mysqldump 导出——命令一律参数数组 R-08、数据库取数经 database-mgmt 已存凭据建连），产物写入目标（本地目录/rsync 远程经 backupx 适配器），终态回写（success 含产物路径与大小 / failure 含失败原因）；**面板重启期间错过的调度点不补跑**（跳过，与系统 cron 语义一致，D2 口径-3）；**同任务执行互斥**：已有 running 时该任务的调度触发跳过该周期（D2 口径-4）；机制型无用户入口（覆盖见 FL 附录A） | —（机制；调度产生的 run 记录即事实留痕） |
| FR-11 | 备份立即执行（C-13-02） | 管理员对指定任务立即发起一次备份：创建 backup_run（触发方式=manual），执行链路与终态回写同 FR-10；**同任务已有 running 执行时拒绝**并提示进行中（D2 口径-4 执行互斥的手动侧）；admin 专属（ADR-018） | 记审计（R-03，手动触发类） |
| FR-12 | 备份历史列表查看（C-13-03） | 按 job 归组（或全任务）分页检索 backup_run：任务、触发方式（backup_trigger）、状态（backup_run_status）、开始时间、耗时、产物大小；running 记录呈现进行中；筛选维度（任务/状态/触发方式/时间范围）与分页参数 D3 定（待对齐-8）；两角色同等可用（ADR-018）；轮转清理后超出保留份数的记录自动移出列表（FR-15） | —（查看类） |
| FR-13 | 备份执行详情查看（C-13-04） | 查看单条 run 完整信息：状态与起止时间、耗时（派生）、触发方式、备份源明细、产物路径与大小、失败原因（failure 时）；两角色同等可用 | —（查看类） |
| FR-14 | 备份产物下载（C-13-05） | 对指定 success 记录的备份产物从目标位置（本地目录 / rsync 远程）取回并经面板下载留存，供面板外恢复使用（自动还原 OUT-1）；仅 success 状态可下载（running/failure 无产物）；产物被面板外删除时下载如实报错（run 记录为历史事实不回改）；admin 专属（ADR-018 禁上传下载） | —（下载为数据取出，审计口径对齐 file-manager 下载先例：记审计，载荷 D3 定） |
| FR-15 | 备份保留轮转清理（C-13-06，机制型） | 备份执行成功后按任务保留份数自动轮转（R-11）：按结束时间排序保留最近 N 条 success 记录（N=任务保留份数），更早 success 记录连同其产物一并删除，早于最旧保留记录的 failure 记录一并清理（D2 口径-5 轮转口径）；**记录与产物同删**（一致性边界，见 domain-model 判定）；清理结果反映于备份历史；机制型随成功执行触发（执行时机与部分失败处置 D3 定待对齐-7），无用户入口 | —（机制；删除事实的审计口径 D3 定待对齐-7） |

## 第五部分：业务规则汇总

| 编号 | 规则 | 来源 |
|------|------|------|
| R-15（精神） | 接管存量：root crontab 既有任务自动纳入管理、如实投影、不重装不替换；备份源联动既有站点与数据库清单 | idea.md §3/§4.1 M8 / D1 BA 1.1 |

## 第六部分：状态流转（T2）

本域唯一业务状态机：**backup_run（backup_run_status）**——`running → success / failure`（ADR-016 拍板；触发=cron 定时调度〔FR-10〕或 manual 立即执行〔FR-11〕，终态在执行完成/失败/超时时回写；终态不可逆，重新执行=产生新 run；记录按保留份数轮转清理 R-11）。

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| backup_job 任务定义 | 无状态字段流转——定义静态（源/目标/保留份数/调度），「最近执行结论」为 backup_run 的回显非任务状态；无启停开关（OUT-5，删除即停） | 配置单据，非状态机 |
| cron_job 存在/不存在 | 任务=crontab 侧记录的存在与删除（事实源在 crontab），无状态字段流转 | 记录存在语义，非状态机 |
| 来源标注（panel/existing） | 标记注释存在与否的判定值，随注释行实况整值刷新（面板外删注释→existing） | 判定值属性（cron_source），非状态机 |
| 表达式校验预览 | 无副作用纯计算，响应即消亡 | 过程数据（P7），非状态机 |
| 定时调度触发/轮转清理 | 后台机制链路（触发器/治理环节），无独立生命周期状态 | 机制链路，非状态机 |
| 手动触发/立即执行在途 | 一次性执行过程（有终态回写），其状态载体就是 backup_run 自身（running 为其过程态） | 聚合内过程态，非独立状态机 |
| 执行互斥判定 | 「同任务存在 running」的查询条件（D2 口径-4），派生自 run 集合 | 查询派生值，非状态机 |

无审批类状态流转（T3 N/A 依据）：本域操作为管理员即时执行，无提交/授权环节；删除确认、执行互斥拒绝均为交互层/并发防护语义，非他人授权审批流。

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：量级——计划任务数十~百条、备份任务个位数~十余、backup_run 总量=Σ各任务保留份数（数十~数百条，轮转治理下有界）、备份产物单份 MB~GB 级（目标磁盘/远端容量由用户自理，空间不足执行失败如实记录）；持久化=backup_job/backup_run 两表（D0 拍板，DDL 归 D3）；cron 侧零持久化（零任务台账）。未锁定项（工程化缺口，不虚构，移交 D3/D4）：见待对齐-1~-9。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| cron 表达式非法 | 服务端校验拒绝（R-14/FR-04），不进入写回；预览区明示解析错误位置 |
| 编辑/删除时任务已不存在（面板外已改） | 如实报错不静默成功（实况投影自然结果）；刷新列表对齐 |
| 面板标记注释被面板外编辑丢失 | 来源标注按 existing 呈现（如实投影，零台账推导）；任务本身仍可管理（读写以 crontab 行为准） |
| 手动触发超时 | 按失败终态反馈（原因=timeout），终止执行；不扩状态枚举（D2 落定） |
| 手动触发命令执行失败 | 退出码/stderr 如实反馈（R-08 通道透传口径 D3 定），不虚构成功 |
| 同任务已有 running 执行时再次触发 | 手动→拒绝并提示进行中；调度→跳过该周期（D2 口径-4） |
| 备份源站点目录已不存在（站点已删/目录移动） | 执行失败如实记录（失败原因=源不可达）；任务定义不自动变更（值快照语义） |
| 备份数据库实例不可达/已移除纳管 | 执行失败如实记录（凭据建连失败/引用悬空）；不级联删任务（第七部分） |
| 目标空间不足 / rsync 远程不可达 | 执行失败如实记录（失败原因含传输/写入错误摘要）；重试语义=再次手动/等待下周期（无自动重试，MVP） |
| 产物被面板外删除后下载 | 下载如实报错；run 记录为历史事实不回改（FR-14） |
| 轮转清理部分失败（产物已删记录未删或反之） | 如实进入下次轮转再治理；失败处置与告警口径 D3 定（待对齐-7）；不阻塞新的备份执行 |
| 审计写入失败（变更/触发已生效） | 生效事实如实反馈；审计失败告警不静默（同事务口径经 account-auth OHS） |
| readonly 越界发起变更/触发/下载 | 全局边界管控拒绝并提示边界原因（account-auth S-03-02）；界面本就无入口 |
| 面板重启错过调度点 | 跳过不补跑（D2 口径-3）；重启后按表达式对齐下一周期 |

**N3 业务规则细节**：见第五部分规则汇总全集（17 条）；幂等语义补充——计划任务创建非幂等（标记注释追加语义 D3 定）、删除非幂等（不存在报错）、手动触发/立即执行非幂等（每次产生新执行事实、受执行互斥约束）、表达式校验无副作用、轮转清理幂等（重复执行收敛到同一保留水位）。

**N4 历史需求**：backup_run 即执行历史（只追加+轮转清理，R-11）；操作追溯由 account-auth 审计覆盖（audit_action=change，对象=计划任务/备份任务，含触发类动作）；cron 侧无变更历史台账（零任务台账推导，事实源在 crontab，不虚构历史）；面板标记注释的变更随任务写回审计覆盖。

## 附录：PRD 完备性检查报告

**功能类型**：业务流程 + 台账混合型——backup_run 有状态机业务流程（running→success/failure）；计划任务/备份任务为台账与配置单据管理（无审批、无集合导出）；rsync 远程目标为外部传输通道（用户主动，ACL）。

### 第一层：通用必检项 G1-G5
