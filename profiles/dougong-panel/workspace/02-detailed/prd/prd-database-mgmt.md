## 第一部分：业务目标（G1）

为登录运维者提供所在服务器 **存量 MySQL/MariaDB 与 Redis 实例的接管与治理能力**：实例本就装在机器上，面板不重装、不重建——自动探测本机 socket 常见路径与 localhost 默认端口（3306/6379）发现存量实例（R-15 发现即接管，⚠️A19 不做全网段扫描），管理员配置连接凭据验证连通后纳入管理，随后提供 MySQL/MariaDB 侧库与用户的建删、库级授权、root 密码修改、状态概览/进程列表观测、mysqldump 备份导出与导入（R-08 参数数组纪律），以及 Redis 侧 info 状态/慢日志观测、密码设置与 key 只读浏览（MVP 严格只读）——这是「接管存量环境」核心卖点（idea.md D5/§3）在数据库维度的直接承载，M4 验收硬项为「发现存量 MySQL 实例 → 建库/建用户/授权/改密码/备份导出再导入成功；Redis 状态与慢日志展示正确；所有操作可审计」（idea.md §6 M4）。轻量承诺在本域的落法：**库与用户台账零持久化**——database/db_user 为实例内实况实时投影、不落库（本 PRD D2 判定，沿 site「零站点台账」/file-manager「不导入不镜像」同哲学），唯一持久化对象是 db_instance 与 redis_instance 实例档案（落 SQLite：**凭据密文无法从实例实况推导，必须由面板自持**，⚠️A18 密文存储、明文仅内存态建连、任何接口不回显）。服务对象：单机自托管的管理员（admin）与只读用户（readonly）——admin 执行全部纳管/治理/备份操作与 key 浏览，readonly 查看实例清单、库/用户列表、状态概览/进程列表与慢日志（D0 口径 + ADR-018）。

本域的安全敏感度为全面板最高之一：实例凭据是面板持有的最高价值秘密（数据库 root 凭据），凭据只进不出（不回显、审计脱敏、密文落库）是贯穿全部功能的第一约束；mysqldump/mysql 命令一律参数数组执行（R-08）是第二约束；全部变更留痕审计（R-03，M4 验收「所有操作可审计」）是第三约束。

**v1.2 增量目标（2026-11-18 用户实机反馈轮，D0 Q1~Q6）**：①治理深度下探——MySQL/MariaDB 由库级下探至表级（表清单/结构/分页数据浏览/单列主键行写/删表，F3），MongoDB 推翻 D-18 只读口径（ADR-031）扩展至库/集合/文档治理（删库/建集合/删集合/文档 CRUD，F4）；②纳管呈现去歧义——探测登记改 TCP 优先、socket 兜底（Q1 二次拍板，清单天然一行 TCP，rescan 保守清理无凭据冗余 socket 行），连接状态/凭据 Tag 语义 tooltip+图例（F2）；③多级页面返回导航——顶栏面包屑（F5，消费 panel-core S-09-01）；④角色口径细化（Q6）：元数据（表清单/结构/集合清单/库清单）两角色全可看，数据内容（行/文档/key 值）与全部写操作 admin 专属（沿 redis key 先例），readonly 数据区负空间。零台账哲学不变：表/行/集合/文档均为实例内实况投影不落库，唯一持久化对象仍为实例档案（含凭据密文）。

## 第三部分：角色定义（G3）

| 角色 | 英文 | 职责与权限 | 获得方式 |
|------|------|-----------|---------|
| 管理员 | admin | 查看能力全集（实例清单/库列表/用户列表/状态概览/进程列表/慢日志）+ 全部变更与数据动作（凭据配置/移除纳管/建删库/建删用户/授权/root 密码/备份导出导入/Redis 密码）+ key 只读浏览 | account-auth 初始化/用户管理创建 |
| 只读用户 | readonly | 同等查看纳管实例清单、数据库列表、数据库用户列表、MySQL 状态概览/进程列表、Redis info 状态/慢日志（D0 口径 + ADR-018「全可看」；进程列表与用户列表为 D1 解释性决策开放——与慢日志同敏感级、凭据不回显）；凭据配置、一切治理变更、备份导出导入、key 浏览全部无入口（界面不提供）+ 越界请求被全局边界管控拒绝（account-auth S-03-02） | 管理员创建并指派 |

访客（未认证操作者）不涉及：本模块全部功能位于登录会话之后（R-02），无访客触达点（与 monitoring/service-mgmt/file-manager/site-mgmt 同口径）。角色差异边界：全部写类操作与数据取出动作（备份导出/key 浏览）为 admin 专属；查看类动作不写审计（R-03 语义为「变更」留痕）；凭据配置与改密动作写审计但凭据值脱敏。

**v1.2 角色口径细化（拍板 Q6，沿 redis key 先例）**：元数据（表清单/表结构/集合清单/库清单）两角色全可看；数据内容（MySQL 行数据/Mongo 文档/Redis key 值）admin 专属——readonly 进入浏览页可见元数据，数据区呈现「数据内容仅管理员可见」负空间（不取数据内容）；全部写操作（删表/行写/Mongo 删库/建删集合/文档 CRUD）admin+CSRF，readonly 操作列整列不渲染。admin 职责扩展至表级治理与集合文档治理全部动作；readonly 查看面扩展至表清单/表结构/集合清单（元数据），数据内容浏览负空间。

### 4.1 实例发现与纳管（S-31）

| 编号 | 需求 | 主流程与规则 | 审计 |
|------|------|-------------|------|
| FR-01 | 存量实例探测（S-31-01，机制型） | 自动探测本机 MySQL/MariaDB、Redis 与 MongoDB 实例：默认探测范围=localhost:3306/6379/27017 TCP 端口 + socket 常见路径（/tmp/mysql.sock、/var/run/mysqld/、/tmp/mongodb-27017.sock 等），不做全网段扫描（⚠️A19）；发现新实例即登记进纳管清单（R-15 发现即接管，不要求重装）；同时得出连接状态（instance_conn_state：reachable/unreachable——**探测态**，由 socket/端口存活探测得出，非流转状态机）；**v1.2 登记策略（rule_changed，拍板 Q1 二次拍板取代展示层归并）：TCP 优先、socket 兜底——两阶段探测：先探本机 TCP 目标记录各引擎本机 TCP 可达性，再探 socket 目标；该引擎本机 TCP 可达时 socket 即使可达也不登记为独立实例（视为同一服务的冗余通道），仅该引擎无任何本机 TCP 可达时 socket 兜底登记（覆盖 skip-networking）；identity_key 语义不变（引擎\|连接方式\|地址），仅注册策略变；rescan 保守清理：同引擎本机 TCP 现已可达时，仅解除「未配置凭据（credentialsSet=false）」的冗余 socket 行纳管（审计同事务 R-03，动作码 instance_removed 或新码 instance_merged D3 定），「已配置凭据」的 socket 行保留并在清单标注（避免凭据丢失），引导改配 TCP 行后手动移除，不做凭据自动迁移**；探测触发时机（模块加载/进入实例页/手动重扫组合）与默认路径端口全集 D3 定（待对齐-6）；无任何引擎检出时模块呈空态引导而非报错（本域推导：R-15 发现哲学） | —（机制；新实例纳管登记随清单呈现；v1.2 rescan 冗余清理记审计） |
| FR-02 | 实例凭据配置与连接验证（S-31-02） | 为已发现实例配置/更新连接方式（db_conn_mode：socket/tcp）与访问凭据：**保存即尝试验证连通，验证通过配置才生效**——验证失败如实反馈失败原因（凭据错误/网络不通/socket 消失），本次配置不落库、不覆盖既有有效凭据（本域推导：防止存入坏凭据致实例失管）；凭据密文落库（⚠️A18）、明文仅内存态建连使用、任何接口不回显；本子模块同时是 FR-12（root 密码修改）/FR-19（Redis 密码设置）成功后同步面板侧凭据密文的存储通道；服务端校验（R-14） | 记审计（凭据值脱敏，R-03） |
| FR-03 | 纳管实例清单查看（S-31-03） | 多引擎统一实例清单：引擎类别（db_engine：mysql/mariadb/redis/mongodb）、标识（host:port，socket 接入以 socket 路径参与标识；多实例同机按标识消重，D1 设计口径）、连接方式、版本、连接状态（探测态）、凭据配置状态（未配置凭据的实例呈现待配置提示——仅探测到不可治理）；管理员可触发重新探测刷新清单（v1.2 rescan 统计可含归并清理数，接口 DTO 零变更）；版本字段在连接建立后实况获取更新（探测初期可空，如实呈现不虚构）；清单筛选/排序口径 D3 定（待对齐-6）；两角色同等可用（ADR-018）；**v1.2 呈现语义见 FR-39（TCP 优先呈现+状态 tooltip/图例+冗余 socket 行标注）** | —（查看类） |
| FR-04 | 实例移除纳管（S-31-04） | 解除实例的面板纳管关系（⚠️A20）：仅删除面板侧实例档案与已存凭据密文，**不卸载实例、不停止实例进程、不删除任何数据**（与 R-15「接管不重装」语义对偶）；移除后实例可经重新探测再次纳管；移除动作需交互层二次确认（确认文案明示「不删除数据」） | 记审计（R-03） |

## 第六部分：状态流转（T2）

本域 **无业务状态机**：D0 拍板「实例连接状态 reachable/unreachable 为探测得出的状态值、非流转语义」，kb 状态机表无本模块对象；database/db_user 为无状态实况对象；纳管关系的建立/解除为记录的存在与删除，非实体状态字段流转。

**辨析表**（易混淆项逐项澄清，防伪状态机）：

| 易混淆项 | 辨析 | 结论 |
|---------|------|------|
| 实例连接状态（reachable/unreachable） | socket/端口存活探测得出的状态值，随每次探测整值刷新，无流转触发与状态机语义（D0 拍板） | 探测态属性（instance_conn_state），非状态机 |
| 纳管/未纳管/已移除 | 纳管关系=实例档案记录的存在与否：纳管=记录创建、移除=记录删除（含凭据密文），无状态字段流转 | 记录存在语义，非状态机 |
| 凭据已配置/未配置 | 实例档案的派生属性（凭据密文存在与否），驱动「待配置」呈现提示 | 派生属性，非状态机 |
| 连接验证在途/导出在途/导入在途 | 一次性动作执行过程，终态反馈即消亡（与 service-mgmt 操作任务/续期单次执行同构） | 过程数据（P7），非状态机 |
| key TTL | 剩余存活时间的倒计时属性，引擎侧管理，面板只读呈现 | 属性值，非状态机 |
| 授权关系（用户⇄库） | 引用关系随授权/回收建立与撤销，非独立状态机；授权概况为关系数据投影 | 关联语义，非状态机 |
| 字符集/引擎类别/连接方式 | 库与实例的来源/配置维度，一经确定不流转（db_engine 为档案标记） | 分类维度，非状态机 |
| 表/行/集合/文档（v1.2） | 实例内实况对象，随引擎侧增删改进出投影，无面板侧状态字段流转（与 database/db_user 同构） | 无状态实况对象，非状态机 |
| 单列主键行写资格（v1.2） | 表结构的派生属性（键信息判定单列主键有无），驱动行写入口可用/禁用提示 | 派生属性，非状态机 |
| 行编辑/文档编辑在途、JSON 校验态（v1.2） | 一次性动作执行过程与前端校验态，终态反馈即消亡 | 过程数据（P7/P3），非状态机 |
| 冗余 socket 行标注（v1.2） | rescan 派生的呈现标注（同引擎 TCP 可达+已配凭据），随探测整值刷新 | 派生呈现属性，非状态机 |

无审批类状态流转（T3 N/A 的依据）：本域操作为管理员即时执行，无提交/授权环节；唯一授权边界=角色判定（ADR-018），属访问控制非审批流。

## 第八部分：非功能性要求与异常场景

**N1 非功能性（已锁定项）**：量级——单机实例个位~十位、库/用户数十量级、慢日志数百条、key 万级（游标分页承载）；v1.2 补充：表数十~数百量级（全量投影）、行数据/文档经分页承载（默认 20 上限 100，大表不一次性全量拉取）、集合数十量级；唯一持久化=实例档案（含凭据密文）——表/行/集合/文档零台账不落库（v1.2 维持零台账哲学）；M4 验收硬项（发现→建库/建用户/授权/改密码/备份导出再导入成功 + Redis 状态慢日志正确 + 全操作可审计）。未锁定项（工程化缺口，不虚构，移交 D3/D4）：实例表 DDL 与密钥方案（待对齐-1）；投影读取口径（待对齐-2）；授权粒度（待对齐-3）；概览条目（待对齐-4）；备份产物落位与导入来源（待对齐-5）；探测时机与路径全集（待对齐-6）；浏览/读取规格（待对齐-7）；命令模板（待对齐-8）；字符集候选来源（待对齐-10）。

**N2 异常场景**：

| 场景 | 处理 |
|------|------|
| 实例不可达（实例停止/socket 消失/端口关闭） | 探测得出 unreachable 如实呈现；治理操作建连失败如实报错并提示检查实例状态（启停归 service-mgmt，本模块不操作进程）；不虚构状态数据 |
| 凭据验证失败（密码错/账号无权限） | FR-02 如实反馈失败原因，本次配置不生效（不落库不覆盖既有有效凭据） |
| root 密码修改成功但面板密文同步失败 | 两步非原子：引擎侧已改密、面板侧密文未更新 → 纳管暂时失联；如实报错并提示以新密码经 FR-02 重新配置凭据恢复（FR-12）；不回滚引擎侧密码（改密是用户意图） |
| Redis 密码设置后旧连接失效（requirepass 生效） | 同步面板凭据密文后以新凭据重连验证；同步失败恢复路径同上（FR-19） |
| 同名库/同名同 host 用户已存在 | 引擎报错如实呈现（不静默覆盖）；服务端校验前置（R-14） |
| 删除不存在的库/用户 | 如实报错（不静默成功，与幂等删除语义区分） |
| mysqldump 失败（磁盘满/权限/锁等待） | 失败原因如实反馈，失败产物清理（不留半截文件误导留存）；不虚构成功 |
| 导入非合法 SQL/导入中途失败 | 如实报错；**不自动回滚**（SQL 重放语义，部分导入为既成事实）——导入前二次确认明示非幂等（FR-16）；恢复手段=修正后重新导入或以备份为准 |
| 面板外经 mysql client/redis-cli 建库建用户改密 | 实况是唯一事实源：库/用户清单实时反映（零台账推导）；面板外改密致面板凭据失效时实例呈现凭据错误，经 FR-02 重新配置恢复 |
| 大库 key 浏览 | SCAN 游标分页承载（待对齐-7），不一次性全量拉取 |
| 无任何引擎检出（未装 MySQL/Redis） | 模块空态引导（FR-01 本域推导）：提示无可接管实例，不报错不虚构清单 |
| 实例被卸载（socket/端口消失且持续 unreachable） | 清单持续呈现 unreachable（不自动移除档案——移除是管理员的显式动作 ⚠️A20）；探测刷新不误删已纳管档案 |
| readonly 越界发起任何变更/导出/key 浏览 | 全局边界管控拒绝并提示边界原因（account-auth S-03-02，ADR-018）；界面本就无入口 |
| 凭据/密码参数非法（空密码超限/非法字符） | 服务端校验拒绝（R-14），不进入引擎执行 |
| 空实例清单/空库清单/空用户清单/空慢日志 | 返回空列表 + 引导（配置凭据/建库/建用户），非错误 |
| 表/集合不存在（浏览/删除/行写定位失败）（v1.2） | 如实报错（不静默成功）；错误码 DBM 族新增编号 D3 定稿（待对齐-11） |
| 无单列主键表发起行写（v1.2） | 入口禁用并如实提示原因（FR-27/28）；越界请求服务端拒绝（R-14，不进入引擎执行） |
| 行写主键旧值已失效（并发修改/面板外删除）（v1.2） | WHERE 主键=旧值匹配 0 行时如实反馈「行已不存在或已被修改」（不静默成功；乐观并发口径 D3 定，待对齐-11） |
| Mongo 文档 JSON 非法（v1.2） | 前端拦截提示（FR-35/36）；服务端亦校验拒绝（R-14）；错误码 D3 定稿 |
| 文档 _id 不存在/已删除（v1.2） | ReplaceOne/DeleteOne 匹配 0 时如实报错（不静默成功） |
| 同名集合已存在（v1.2） | 引擎报错如实呈现（不静默覆盖）；服务端校验前置（R-14） |

| 空表清单/空集合清单/空表数据/空集合文档（v1.2） | 返回空列表 + 引导（建表归后续/新建集合/插入文档），非错误 |

**N3 业务规则细节**：见第五部分规则汇总全集；补充幂等语义——库/用户创建非幂等（已存在报错）；删除非幂等（不存在报错，不静默成功）；凭据配置可重入（重复配置验证通过即覆盖生效）；导出重试安全（重新导出覆盖/新产物，待对齐-5 定覆盖口径）；导入**非幂等**（SQL 重放，二次确认前置，FR-16）；授权/回收幂等（重复授权/回收无授权结果一致）。v1.2 补充：表/集合删除与 Mongo 删库非幂等（不存在报错）；集合创建非幂等（同名报错）；行编辑/行删除按主键旧值定位（匹配 0 行如实反馈，不静默）；文档插入 _id 冲突报错、文档编辑/删除按 _id 定位（不存在报错）；rescan 冗余清理幂等（已清理的行不再存在，重扫无副作用）。

**N4 历史需求**：面板侧无库/用户/授权变更历史台账（零台账推导）；操作追溯由 account-auth 审计日志查询覆盖（audit_action=change，对象=实例/库/用户/备份动作）；实例档案自身即为纳管历史载体（创建/凭据更新/移除均留审计）；备份导出产物（SQL 文件）本身即数据快照历史（留存策略归操作者/产物落位待对齐-5），不做独立备份历史表（定时备份执行记录 backup_run 归 cron-backup 模块）。v1.2 补充：表/行/集合/文档变更同样零历史台账，操作追溯经审计覆盖——新增动作码（table_dropped/row_updated/row_deleted/mongo_database_dropped/mongo_collection_created/mongo_collection_dropped/mongo_document_inserted/mongo_document_updated/mongo_document_deleted 及 rescan 冗余清理 instance_removed 或 instance_merged，命名 D3 定稿）；审计 detail 脱敏沿 R-03（行数据/文档内容不入审计明文，仅对象定位与动作结果）。
